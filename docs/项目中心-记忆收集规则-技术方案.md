# 「项目中心-记忆」增加「设定收集记忆规则」输入框 - 技术方案

> 创建日期：2026-08-28
> 更新日期：2026-08-28

## 1. 背景与目标

「项目中心 → 项目详情 → 知识记忆 → 记忆」段目前只有两项设置：

1. **自动从会话收集记忆**（启停开关）
2. **记忆保留策略**（保留天数 + 永久保留 + 过期策略）

本次需求：增加一个 **「设定收集记忆规则」输入框**，让用户可以自定义 AI 从会话中收集记忆时遵循的规则（例如"只收集与代码规范、架构决策相关的要点，忽略闲聊与临时调试内容"），从而控制自动收集的记忆的质量与方向。

## 2. 交互设计

遵循现有 Settings 极简风格与「点击行展开行内编辑区」的统一编辑范式（与「记忆保留策略」行一致）：

### 2.1 设置区新增一行（位于「自动从会话收集记忆」与「记忆保留策略」之间）

```
┌──────────────────────────────────────────────────┐
│ 自动从会话收集记忆                        (●─) 开 │
│     会话结束后自动提炼要点写入记忆                  │
├──────────────────────────────────────────────────┤
│ 收集记忆规则                                ⌃     │  ← 新增行
│     只收集代码规范与架构决策相关要点……（规则摘要，  │
│     单行省略；未设定时显示「未设定，将自动提炼      │
│     通用要点」）                                  │
├──────────────────────────────────────────────────┤
│ 记忆保留策略                                ⌃     │
│     保留 90 天 · 过期自动归档                      │
└──────────────────────────────────────────────────┘
```

- **行结构**：左侧 = 「收集记忆规则」（主文案 13.5px）+ 当前规则摘要（次级 12px 灰，单行省略；为空时显示「未设定，将自动提炼通用要点」）；右侧 = 展开箭头（⌃，展开时旋转 180°）。
- **位置**：紧跟「自动从会话收集记忆」开关行之后——规则是"收集什么"的约束，逻辑上从属于自动收集，放在开关下方最自然。

### 2.2 点击行展开行内编辑区（输入框）

```
│ 收集记忆规则                                ⌄     │
│   ┌────────────────────────────────────────┐   │
│   │ （多行文本域 textarea，高约 72px，        │   │
│   │   预填当前规则，占位提示：                │   │
│   │   如 只收集代码规范、架构决策相关的要点，  │   │
│   │   忽略闲聊与临时调试内容）                │   │
│   └────────────────────────────────────────┘   │
│                              [取消] [保存]       │
```

- **输入框**：多行文本域（`textarea`），复用 `.field-input` 的细边框风格（`1px solid var(--border)`、圆角 8px、13px 字号），高度约 72px（3 行），内边距 8px 10px，可内部滚动；
- **操作**：底部右对齐「取消」文字按钮 + 「保存」黑底按钮（与保留策略编辑区一致）；
- **保存**：写回本地 state（Mock 不持久化），行次级文案联动刷新为规则摘要（单行省略）；
- **取消**：丢弃修改，收起编辑区；
- **空值允许**：规则不是必填项，清空保存 = 恢复「未设定」状态（保存按钮不禁用）；
- **与自动收集开关联动**：自动收集关闭时，规则行整体禁用灰显（次级文案变灰、行不可点击、title 提示「自动收集已关闭」）——规则只对自动收集生效，关闭时设定无意义。

### 2.3 与现有范式的差异说明

- 不用弹窗（FormModal）：弹窗规范仅用于「新增类」操作（新建/导入/添加），本需求是**编辑一项设置**，与「记忆保留策略」同类，采用行内展开编辑区；
- 不用单行 input：规则是自然语言描述，通常较长，用 textarea 更合适。

## 3. 数据模型改动（`src/data/projects.ts`）

```ts
export interface MemorySettings {
  autoCollect: boolean
  /** 收集记忆规则：用户自定义的自然语言规则，空 = 未设定（自动提炼通用要点） */
  collectRules: string          // ← 新增字段
  retentionDays: number
  permanent: boolean
  expirePolicy: '自动归档' | '自动删除' | '仅提醒'
}
```

Mock 数据补充（3 个项目）：

| 项目 | collectRules 默认值 |
|---|---|
| loomweb | `只收集代码规范、架构决策与组件拆分相关的要点，忽略闲聊与临时调试内容。` |
| yigou-app | `重点收集支付、账号安全相关的处理经验，涉及第三方 SDK 的坑需完整记录。` |
| data-pipeline | `收集数据口径与调度配置的变更记录，忽略一次性脚本调试内容。` |

## 4. 组件改动（`KnowledgePanel.tsx` / `KnowledgePanel.css`）

### 4.1 `MemorySegment` 组件

- 新增 state：`editingRules: boolean`、`rulesDraft: string`；
- 新增 handler：
  - `handleSaveRules()`：`onUpdateKnowledge({ ...knowledge, memorySettings: { ...memorySettings, collectRules: rulesDraft.trim() } })`，保存后收起；
- 渲染：在开关行与策略行之间插入「收集记忆规则」行（`Row` + `expandable`），结构对齐「记忆保留策略」行：
  - 次级文案：`memorySettings.collectRules || '未设定，将自动提炼通用要点'`；
  - 自动收集关闭时：行加 `disabled` 态（不可点击）；
  - 展开区：`textarea.rules-textarea` + 「取消 / 保存」操作栏。

### 4.2 样式（`KnowledgePanel.css` 追加）

```css
/* 收集规则文本域 */
.rules-textarea {
  width: 100%;
  min-height: 72px;
  resize: vertical;
  /* 复用 .field-input 的边框/圆角/字号体系，覆盖高度与内边距 */
}

/* 自动收集关闭时规则行禁用态 */
.memory-rules-row.disabled { cursor: default; }
.memory-rules-row.disabled .settings-row-title,
.memory-rules-row.disabled .settings-row-sub { color: #c2c2c6; }
```

## 5. 不改动的部分

- 「团队知识库」段、记忆条目列表、保留策略行、手动添加/清理过期等交互均不变；
- `FormModal`、`Toggle`、`SettingsRow` 等通用组件不改动；
- 其余面板（规范/成员/ADE/自动化）不涉及。

## 6. 实施步骤

1. `src/data/projects.ts`：`MemorySettings` 增加 `collectRules` 字段 + 3 个项目 Mock 数据补充；
2. `KnowledgePanel.tsx`：`MemorySegment` 增加规则行（展示 + 行内展开编辑 + 保存/取消 + 禁用态联动）；
3. `KnowledgePanel.css`：追加 `.rules-textarea` 与禁用态样式；
4. `npm run build` 验证构建通过；
5. 浏览器自检：规则摘要展示、展开编辑、保存联动、清空恢复「未设定」、关闭自动收集后规则行禁用；
6. 提交 git commit。

## 7. 验收标准

1. 「记忆」段设置区出现「收集记忆规则」行，位于自动收集开关行下方，次级文案展示规则摘要（单行省略）或「未设定，将自动提炼通用要点」；
2. 点击行展开编辑区：textarea 预填当前规则，可修改后「保存」（次级文案联动刷新）或「取消」（丢弃修改）；
3. 清空内容保存后恢复「未设定」状态，保存按钮不禁用（空值合法）；
4. 关闭「自动从会话收集记忆」后，规则行灰显不可点击（title 提示「自动收集已关闭」），重新开启后恢复可用；
5. 三个项目各自展示对应 Mock 规则文案；
6. 视觉与现有 Settings 极简风格一致（细边框、圆角、字号体系），构建通过，代码提交 commit。

## 8. 风险与说明

- 纯 Mock：规则仅存本地 state，刷新即还原，不对接真实后端；
- 规则长度不限（前端不做截断校验），摘要展示时单行省略；
- 不做规则模板/预设选项（保持极简，后续可按需扩展）。
