# 「详情页会话布局（左会话区 + 右可关闭横向 tab）」技术方案

> 创建日期：2026-10-15
> 更新日期：2026-10-15

## 0. 确认记录（鹿鹿子大王）

- **设计稿 v2 已确认**：`docs/项目中心-详情页会话布局-设计图-v2.html`（v1 保留存档）；
- 三点要求：
  1. 左栏多个会话**不做横向 tab**，改为 🕘 icon 打开**历史会话抽屉**；
  2. 右侧顶部 tab **可 × 关闭**，末尾 **＋ icon** 重新打开（最后一个 tab 不可关闭）；
  3. **项目成员移出右侧 tab**，改为左栏 👥 icon 打开**成员抽屉**（沿用 MembersPanel 逻辑）。

## 1. 背景与目标

### 1.1 现状问题

| # | 问题 | 现状表现 |
|---|---|---|
| 1 | **详情页无会话入口** | 自动化任务的会话藏在 RunModal 弹窗里，「跳转到会话」只能新开外部 URL，站内没有常驻会话视图 |
| 2 | **竖向导航占空间** | `ProjectDetail` 左侧 180px 竖向 10 项导航 + 右侧内容面板，纵向利用率低，横向空间被固定占用 |
| 3 | **成员信息层级错位** | 成员是项目协作的基础信息，却和配置类 tab（规范/代码/审查）平级放在右侧导航里 |

### 1.2 改造目标

1. 详情页主体改为**左右两大栏**：
   - **左栏 = 会话区**（约 34%，`min-width 360px`）：当前会话行（名称 + 运行状态）+ 🕘 历史会话 icon（带未读角标）+ 👥 成员 icon，主体为消息流 + 插话输入框；
   - **右栏 = 项目配置区**：原竖向导航全部变为**顶部横向下划线式 tab**，可 × 关闭 / ＋ 重开；
2. 会话消息流**复用 RunModal 的消息语言**（ADE 左头像灰气泡 / 人右绿气泡 / 系统居中 / Gate 橙色左边条 / 阶段结果蓝色左边条），跑自动化任务时**实时联动**（引擎驱动，消息、Gate 批准/拒绝、插话均生效）；
3. 成员管理（添加/行内编辑/移除）整体迁入左栏抽屉，逻辑不变。

## 3. 数据模型变更（`src/data/projects.ts`）

### 3.1 新增 `ProjectSession`（会话条目）

```ts
/** 项目会话（左栏会话区条目） */
export interface ProjectSession {
  id: string
  /** 会话名（如「周报生成 · 汇总统计」） */
  name: string
  /** 来源：auto = 自动化任务（关联 jobId）；manual = 手动发起 */
  source: 'auto' | 'manual'
  /** auto 时关联的任务 id（消息实时取 job.currentRun，引擎联动） */
  jobId?: string
  /** 来源副文案（如「自动化任务 · 今日 08:00 触发」/「手动会话 · 与 wang、luyu」） */
  originText: string
  /** 手动会话的消息（auto 会话不存这里，实时取 run） */
  messages: RunMessage[]
  /** 未读数（进入会话时清零） */
  unread: number
  /** 排序权重（数字大在前；运行中 > 等待 > 已结束） */
  order: number
}
```

### 3.2 `Project` 增加字段

```ts
export interface Project {
  // ...其余不变
  /** 项目会话列表（左栏历史会话抽屉数据源） */
  sessions: ProjectSession[]
}
```

`createEmptyProject()` 补 `sessions: []`。

### 4.2 `ChatMessage.tsx`（消息渲染共享化）

从 `RunModal.tsx` 抽出 `MessageItem`，改名导出 `ChatMessage`：

```tsx
interface ChatMessageProps {
  message: RunMessage
  prevMessage?: RunMessage
  /** 关联任务（Gate actions/form 需要；手动会话传 null → 不渲染按钮/表单） */
  job: AutoJob | null
  /** 当前是否等待处理（控制 actions/form 可用） */
  waiting: boolean
  onApprove?: (jobId: string) => void
  onReject?: (jobId: string) => void
  onSubmit?: (jobId: string, values: Record<string, string>) => void
}
```

- 原 `job.currentRun?.status === '等待确认' || '等待输入'` 的内部判断改为 `waiting` prop（调用方决定）；
- 样式整体从 `RunModal.css` 的 `.run-msg-*` 段迁移到 `ChatMessage.css`，**类名保持不变**（`RunModal.css` 里删除重复定义，两个消费方共用一份）。

### 4.3 `ChatPane.tsx`（左栏会话区）

```
┌ chat-head ─────────────────────────────┐
│ ‹ 返回  📁loomweb  [进行中]  编辑        │   ← 原 detail-header 浓缩
│ 简介 · 创建于 … · 周期 … (单行省略)      │   ← 原 detail-desc
├ session-bar ───────────────────────────┤
│ 💬 周报生成 · 汇总统计          🕘②  👥  │   ← 当前会话行 + 两个 icon
│ 自动化任务 · ● 运行中 3/5 · 今日 08:00   │
├ chat-stream（消息流，复用 ChatMessage） ┤
├ chat-input ────────────────────────────┤
│ [S] 插话：向正在执行的 ADE 发送指令… [➤] │
└─────────────────────────────────────────┘
```

Props 与行为：

```tsx
interface ChatPaneProps {
  project: Project
  engine: AutomationEngine
  onUpdateProject: (id: string, updater: (p: Project) => Project) => void
  onBack: () => void
  onOpenEdit: () => void          // 编辑项目弹窗（留在 ProjectDetail）
  /** 通知跳转定位：切到目标会话 */
  focusJobId?: string | null
}
```

- **当前会话**：`activeSessionId` state（默认 order 最大的会话；`focusJobId` 到达时切到对应 `jobId` 的会话并清未读）；
- **auto 会话消息**：`job.currentRun ?? job.history[0]` 的 `messages` → 引擎推进时自动更新；`waiting = job.currentRun` 为等待态；
- **手动会话**：`session.messages` 静态渲染，`job = null`；
- **插话输入框**：auto 且活动运行 → `engine.sendMessage(project.id, jobId, text)`（复用引擎 1.5s 回应）；手动会话 → 本地 append 一条「人」消息 + 一条 ADE 假回应（`onUpdateProject` 更新 session.messages）；
- **发送身份**：输入框左侧常驻 `CURRENT_USER` 头像（同 RunModal）；
- **消息流吸底**：沿用 RunModal 的 `stickBottom` ref + `useEffect` 滚动逻辑；
- **两个 icon**：
  - 🕘 历史会话：`unread > 0` 显示角标（= 未读总数），点击开 `HistoryDrawer`；
  - 👥 成员：点击开 `MembersDrawer`；
  - 两抽屉**互斥**（`drawer: 'history' | 'members' | null` state，同一时刻只开一个）；
- **编辑项目弹窗**：`onOpenEdit` 触发 ProjectDetail 既有 FormModal（不迁移）。

### 4.4 `HistoryDrawer.tsx`（历史会话抽屉）

- 覆盖式（`position: absolute` 于 chat-pane 内，宽 272px + 遮罩 + 右投影），**不挤压布局**；
- 头部：`历史会话` + `N 个会话` + ×；
- 条目：会话名 + 状态徽标（auto → run 状态映射 RunModal 的 `runTone`；manual → `已结束`）+ 未读小徽标 + `originText` 副文案；当前会话高亮底色；
- 点击条目：`setActiveSessionId` + 清未读 + 关抽屉；
- 底部：`＋ 新对话`（新建手动会话：id/order 生成、空消息、切为当前会话，输入框即刻可插话）+ 提示文案；
- props：`sessions / activeSessionId / onSelect / onClose / onNewSession`。

### 4.5 `MembersDrawer.tsx`（成员抽屉）

- 同款覆盖式抽屉；头部：`项目成员` + `N 人 · M ADE` + `＋ 添加` + ×；
- 条目：30px 头像（`MEMBER_COLORS[member.name]` 底色 + initial）+ 姓名（`member.name === CURRENT_USER.name` 带「我」徽标）+ `role · permission` 副文案 + 在线点 + `lastActive`；
- **行内编辑 / 添加弹窗 / 移除**：整体迁移 `MembersPanel` 的 state 与 handlers（`adding/editId/form`），样式复用 `MembersPanel.css` 的 `inline-edit`（行内编辑在 272px 抽屉里纵向堆叠排列，fields 换 flex-direction: column）；
- MembersPanel.tsx / .css **删除**（右栏不再渲染）；编辑入口从「点行展开」改为行右侧「编辑」文字按钮 + 展开区。

### 4.6 `ClosableTabs.tsx`（右侧可关闭横向 tab）

```tsx
interface ClosableTabsProps {
  items: TabItem[]                 // 9 项（原 NAV_ITEMS 去 members）
  openKeys: NavKey[]               // 打开中的 tab（顺序渲染）
  activeKey: NavKey
  closedKeys: NavKey[]             // 已关闭（+ 菜单数据源）
  onSelect: (key: NavKey) => void
  onClose: (key: NavKey) => void   // 仅剩 1 个时禁用（× 隐藏）
  onReopen: (key: NavKey) => void
}
```

- tab 条：图标 + label +（automation 项带待处理红计数）+ `×`（淡色，hover 加深；`openKeys.length === 1` 时全部隐藏 ×）；
- 末尾 `＋`：点击弹下拉「已关闭的 tab」（icon + 名称 + 「已关闭」hint；空时显示「暂无已关闭的 tab」），点条目 `onReopen`；
- 溢出横向滚动（`overflow-x: auto`），选中项 `scrollIntoView({ inline: 'nearest' })`；
- 样式：macOS 下划线式（active = 黑字 600 + 2px 底线，`margin-bottom: -1px` 压边框）。

### 4.7 `ProjectDetail.tsx`（骨架改造）

状态机变化：

```tsx
// 删：const [nav, setNav] = useState<NavKey>(...)
// 新：
const [openTabs, setOpenTabs] = useState<NavKey[]>(DEFAULT_OPEN_TABS)   // 初始 9 项全开
const [activeTab, setActiveTab] = useState<NavKey>(initialNav ?? 'specs')
```

- `NAV_ITEMS` 改 9 项（去 `members`）+ 新增 `tabLabel` 元数据给 ClosableTabs；
- **关闭**：`setOpenTabs(open.filter(...))`；若关的是 activeTab → 激活相邻（优先右侧，无则左侧）；closedKeys = 9 项差集；
- **重开**：append 到 openTabs 末尾 + 激活；
- **通知跳转联动**（保持既有行为）：`initialNav` 到达 → 若目标 tab 已关闭先重开再激活（`useEffect` 合并处理）；`focusJobId` 同时传给 AutomationPanel（右栏高亮卡片）与 ChatPane（左栏切会话），`onClearFocus` 一次清两处；
- 头部区域**整体移入 ChatPane**（返回/名称/状态/编辑/简介周期行），`detail-header/detail-desc` 相关 JSX 迁走，编辑弹窗留在 ProjectDetail；
- `renderPanel()`：`case 'members'` 删除；其余面板 JSX 不动。

### 4.8 `RunModal.tsx`（消息渲染收敛）

- `MessageItem` 内部实现删除，改 `import { ChatMessage } from './ChatMessage'`；
- 消息流 map 处传 `waiting = isActiveRun(job.currentRun) && (等待确认|等待输入)`，行为与原先一致（原 `waiting` 内部计算挪到调用方）；
- `.run-msg-*` 样式段移入 `ChatMessage.css` 后，RunModal.css 仅保留弹窗壳/步骤条/输入框样式。

## 5. 交互细节汇总

| 场景 | 行为 |
|---|---|
| 进入详情页 | 左栏默认显示 order 最大会话（运行中优先）；右栏 9 tab 全开、默认激活 specs（或 initialNav） |
| 🕘 icon 角标 | 未读总数（s2=1 + s3=1 → 2）；进入会话清零 |
| 抽屉互斥 | 开历史抽屉时点成员 icon → 历史关闭、成员打开；×/遮罩点击关闭 |
| 关 tab | activeTab 被关 → 激活相邻；仅剩 1 个 tab × 隐藏 |
| ＋ 菜单 | 已关闭 tab 列表；重开 append 末尾并激活；点击外部/Esc 关闭菜单 |
| 通知跳转 | 恢复原链路：进详情 → 重开并激活 automation tab → 左栏切到对应会话 + 右栏高亮待处理卡片 |
| 手动会话插话 | 本地 append 人消息 + 1.5s ADE 假回应（提示文案「空闲会话转为新任务指令」语义的 Mock 简化） |
| 消息流 Gate | 批准/拒绝/提交按钮仅 auto 会话且 waiting 时可用（引擎动作，两栏共享同一 engine 实例，状态同步） |
| tab 红计数 | automation 项显示 pendingCount（`jobs.filter(等待确认|等待输入).length`），沿用现有计算 |

11. `npm run build` 通过。
