# 协作中心 · 代码仓库配置与同步方案

> 日期：2026-10-27
> 状态：设计稿，待评审
> 关联：[协作中心-项目沙箱与工作区方案.md](协作中心-项目沙箱与工作区方案.md)（基础层已实现）

## 1. 背景

沙箱容器、目录、终端已经可用，但 `/workspace/repos` 是空的：当前「代码」tab 里的仓库只是前端 Mock 配置（名称、类型、分支、说明），没有真实 Git 地址、没有凭证、也不落库。

目标是让**用户自己配置仓库**：填写 Git 地址与 Token 后，服务端把代码同步到项目沙箱，agent 与终端才能看到和修改真实代码。

## 2. 范围

**本期做：**

- 仓库配置落库：名称、类型、Git URL、默认分支、可编辑/只读、说明
- Token 配置与安全存储（只回 `hasToken`，不回明文）
- 代码 tab 的新增 / 编辑 / 移除 / 手动同步
- 新增仓库后自动 clone 到项目沙箱 `repos/<name>`
- 已有仓库 fetch / 安全更新；同步状态与错误展示

**本期不做：**

- SSH 密钥、SVN、多仓库凭证共享
- worktree、diff 栏、commit / push / MR
- 会话级代码模式确认（依赖仓库能力，后续再做）
- 只读仓库的写保护（先按配置展示，后续在容器/分支层落实）

## 3. 数据模型

### 3.1 `project_repos`

```sql
CREATE TABLE IF NOT EXISTS project_repos (
  id            TEXT PRIMARY KEY,
  project_id    TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  name          TEXT NOT NULL,
  type          TEXT NOT NULL DEFAULT 'gitlab',   -- gitlab | github
  url           TEXT NOT NULL,
  branch        TEXT NOT NULL DEFAULT 'main',
  mode          TEXT NOT NULL DEFAULT 'editable', -- editable | readonly
  note          TEXT NOT NULL DEFAULT '',
  sync_state    TEXT NOT NULL DEFAULT 'idle',     -- idle | syncing | ready | error
  last_synced_at TEXT,
  sync_error    TEXT,
  created_at    TEXT NOT NULL,
  updated_at    TEXT NOT NULL,
  UNIQUE(project_id, name)
);
CREATE INDEX IF NOT EXISTS project_repos_project ON project_repos(project_id);
```

- 已有 Mock 仓库**不迁移**（没有真实 URL）；代码 tab 从空开始
- `name` 同时作为沙箱目录名：只允许 `[A-Za-z0-9._-]`，项目内唯一
- `type` 首期支持 `gitlab | github`；SVN 在 UI 中暂不提供

### 3.2 Token 存储

Token 不进数据库、不进 API 响应，存 `server/data/secrets.json`：

```json
{
  "repoTokens": {
    "repo_xxx": "<token>"
  }
}
```

- API 只返回 `hasToken: boolean`
- 更新：传 `token` 覆盖；传 `clearToken: true` 删除
- `secrets.json` 已有 0600 权限；新增读写函数复用现有 `readSecrets/writeSecrets`

## 4. API

全部走 `requireProject`（Cookie 鉴权 + 项目成员）；非研发项目返回 409。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/projects/:id/repos` | 仓库列表（含同步状态、`hasToken`，不含 Token） |
| POST | `/api/projects/:id/repos` | 新增；body: `name,type,url,branch,mode,note,token?`；成功后异步触发首次同步 |
| PATCH | `/api/projects/:id/repos/:repoId` | 修改 `branch,mode,note` 与 Token；`name/type/url` 不可改 |
| DELETE | `/api/projects/:id/repos/:repoId` | 移除配置与 Token；按确认删除本地沙箱目录 |
| POST | `/api/projects/:id/repos/:repoId/sync` | 异步同步，返回最新状态 |

校验：

- URL 仅允许 `https://`、`http://`、`file://`；拒绝 URL 中带 username/password（避免凭证泄漏到日志）
- 重名 409；非法 URL 400；分支为空 400
- 同一仓库同一时间只允许一个同步任务（进程内 mutex）

## 5. 同步（Clone / Fetch）

### 5.1 为什么在宿主机同步

当前默认镜像 `ubuntu:latest` 没有 git；容器以非 root 运行，无法 apt 安装。因此首期由**服务端宿主机的 git** 完成 clone/fetch，直接写入沙箱卷：

```
<sandboxRoot>/<projectId>/repos/<repoName>/
```

容器启动后通过 `/workspace/repos/<repoName>` 直接看到代码，不需要容器内 git。后续换成带 git 的镜像时，可把同步移入容器。

### 5.2 凭证注入

不把 Token 拼进 URL（会出现在进程参数和错误日志里），使用 `GIT_ASKPASS`：

```sh
#!/bin/sh
case "$1" in
  *Username*) printf '%s\n' "${ORG_OS_GIT_USERNAME:-oauth2}" ;;
  *) printf '%s\n' "$ORG_OS_GIT_TOKEN" ;;
esac
```

执行环境：

```
GIT_ASKPASS=<DATA_DIR>/git-askpass.sh
ORG_OS_GIT_TOKEN=<token>
ORG_OS_GIT_USERNAME=oauth2 | x-access-token
GIT_TERMINAL_PROMPT=0
```

- GitLab 用 `oauth2` 作为用户名，Token 作为密码
- GitHub 用 `x-access-token` 作为用户名
- 无 Token 的公开仓库也可以同步
- askpass 脚本 0700；Token 只存在于服务端进程环境变量

### 5.3 命令

首次同步：

```bash
git clone <url> <sandbox>/<projectId>/repos/<name>
git -C <dir> checkout <branch>
```

已有仓库：

```bash
git -C <dir> fetch --prune origin
# 工作区干净时：
git -C <dir> checkout -B <branch> origin/<branch>
# 工作区有改动时：只 fetch，不 reset，返回 warning
```

- 每次同步前写 `sync_state = syncing`，结束后写 `ready` / `error` + `last_synced_at`
- 超时 10 分钟；错误信息截断后落库
- 同步不依赖容器运行；容器未启动也可以更新卷里的代码

## 6. 前端（代码 tab）

### 6.1 列表

- 数据改为 `GET /api/projects/:id/repos`，不再使用 `project.repos` Mock
- 行信息：仓库名、Git 地址（主机名）、默认分支、类型、可编辑/只读、Token 状态、同步状态与时间
- 操作：同步、编辑、移除（移除前提示会删除本地沙箱目录）
- 同步状态：`同步中 / 已就绪 / 失败`，失败展示原因

### 6.2 添加弹窗

字段：

| 字段 | 说明 |
|---|---|
| 仓库名 | 必填；仅 `[A-Za-z0-9._-]`，项目内唯一 |
| 类型 | GitLab / GitHub |
| Git 地址 | 必填；https/http/file |
| 默认分支 | 必填，默认 `main` |
| Token | 密码输入；公开仓库可留空；已配置时显示「已配置」 |
| 用途/上下文说明 | 可选 |

- 添加成功后弹窗关闭，行内显示「同步中」，完成后刷新
- 失败时保留配置，可点「同步」重试

### 6.3 编辑

- 可改：分支、可编辑/只读、说明、Token（留空 = 不变，勾选「清除 Token」= 删除）
- 不可改：仓库名、类型、Git 地址（需要变更请移除后重新添加）
- 修改分支后提示「下次同步生效」

### 6.4 非研发项目

不显示「代码」tab；直接调用仓库 API 返回 409。

## 7. 安全

- Token 不回传前端、不写日志；错误信息中脱敏 URL 和 Token
- 拒绝带用户信息的 URL（`https://user:pass@...`）
- 只允许配置 URL，不允许执行任意 git 命令；仓库名做路径安全校验
- 删除仓库时同时删除 Token；本地目录删除需二次确认
- 云端后续：Token 存 KMS/Vault、按用户短期令牌、仓库权限最小化

## 8. 边界与失败处理

| 场景 | 行为 |
|---|---|
| 重复仓库名 | 409，前端提示 |
| 非法 URL | 400 |
| 认证失败 / 仓库不存在 | 同步 `error`，展示 git 错误摘要 |
| 网络超时 | 同步失败，可重试 |
| 工作区有未提交改动 | 只 fetch，不 reset，状态 ready + warning |
| 同步中再次同步 | 返回「同步中」，不重复执行 |
| 配置删除时正在同步 | 等同步结束或标记取消后再删目录 |
| 沙箱目录不存在 | 同步前自动创建 |
| 宿主机没有 git | 同步失败，提示安装 git |
| 非研发项目 / 非成员 | 409 / 403 |
| 只读仓库 | 可同步、可读；写保护后续实现 |

## 9. 验收

1. 代码 tab 添加一个本地测试仓库（`file:///tmp/demo.git`，无 Token）→ 自动 clone，`<sandbox>/<projectId>/repos/demo` 出现文件
2. 打开终端 → `ls /workspace/repos/demo` 能看到代码
3. 修改默认分支并同步 → 切到新分支；本地有改动时不会被 reset
4. Token：配置后 API 只返回 `hasToken: true`；`secrets.json` 可见、API 不可见；清除 Token 后失效
5. 重名 409、非法 URL 400、非成员 403、非研发项目 409
6. 移除仓库：配置与 Token 删除，本地目录按确认删除
7. `tsc -b`、`node --check`、`npm run build` 通过
