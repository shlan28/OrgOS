# 「自动化任务」实时交互升级方案（v2.1 · 任务运行弹窗）

> 创建日期：2026-08-28
> 更新日期：2026-08-28（v2.1：应用户要求，交互输入框收进任务弹窗，不在任务页面内联）
> 前置文档：`项目中心-自动化任务交互改造方案.md`（v1，已实现：运行状态可视化 + 暂停点 Gate + 应用内通知）

## 1. 问题：v1 的交互不是"实时"

v1 已实现的能力与差距：

| 能力 | v1 现状 | 差距 |
|---|---|---|
| 暂停等人确认/输入 | ✅ Gate 卡片（批准/拒绝/表单） | 只在**预设暂停点**发生 |
| 运行状态可视化 | ✅ 步骤时间线 + 日志（展开可见） | **只读**，人插不上话 |
| 运行中的人工介入 | ❌ 只有「取消运行」 | **无法实时沟通** |

结论：v1 是"任务停下来等人"（异步表单），不是"人和运行中的任务实时对话"。AI 队友（ADE）执行任务时，人应该能**随时插话**——补充信息、调整指令、提问——任务也能**实时回应**。

## 2. v2.1 核心设计：任务运行弹窗（RunModal）

**页面只负责"看"：状态、进度、启停；弹窗负责"聊"：消息流 + 输入框。**

- 点击任务行 → 打开该任务的**运行弹窗**（不再行内展开）；
- 弹窗 = 单个任务的完整操作中心：**运行控制台（消息流 + 输入框）⇄ 编辑模式**（表单）；
- 页面任务列表保持极简可扫读，不被长内容撑开。

### 2.2 消息样式（贴合 macOS 消息应用）

| 角色 | 样式 |
|---|---|
| 系统 | 居中灰色小字（运行开始/结束/人工批准等事件） |
| ADE | 左侧浅灰气泡 + 角色标签 |
| 人 | 右侧绿色气泡（沿用 `--accent-green` 系），iMessage 观感 |
| 问题（Gate） | 左侧橙色左边条卡片：⚠ 标题 + 说明 + 内联按钮（确认型）或迷你表单（输入型） |

### 2.3 弹窗两个模式

1. **运行控制台**（默认）：消息流自动滚到底部，新消息到达时若已在底部则跟随滚动；
2. **编辑模式**：头部点「编辑」→ 弹窗体切换为表单（任务名/触发方式/触发参数/「运行中需要人工确认」开关 + 保存/取消/删除任务）；运行中的任务「编辑」禁用（提示"运行中的任务不可修改"）。

## 3. 页面（任务列表）相应简化

```
共 4 个任务 · 4 个启用 · 1 个运行中 · 2 个待人工处理（橙，可点击定位）

⚠ 待人工处理（2）                                    ← 保留置顶分组（快捷处理）

│ 发布准备 · 运行 #r13  [等待输入]   [去填写 →]        ← 输入型：按钮改为打开弹窗（表单收进弹窗）

任务                                        [+ 新建]
│ 每日构建                    [● 运行中] 2/4   (●─) 开 │ ← 行点击 = 打开弹窗
│    定时 · 每天 08:00 · 执行中：单元测试               │
│ MR 静态检查                  [成功]    [运行]  (●─) 开 │
│ 周报生成                    [等待确认]          (●─) 开 │
│ 发布准备                    [等待输入]          (●─) 开 │
```

- **行内不再有展开区/输入框**：点击行 → 弹窗；
- 待处理分组：确认型保留行内快捷 `[拒绝] [批准]`（一键操作，开弹窗反而重）；输入型只留 `[去填写 →]`（打开弹窗定位到问题消息）——**所有输入都发生在弹窗里**；
- 通知下拉「去填写」→ 跳转项目 → 自动化任务 tab → **直接打开该任务的弹窗**（focusJobId 从"展开行"改为"开弹窗"）。

## 4. 消息模型（数据增量）

```ts
/** 运行消息 */
export interface RunMessage {
  id: string
  /** 系统 = 运行开始/结束等事件；ADE = 任务执行方；人 = 用户插话 */
  role: '系统' | 'ADE' | '人'
  text: string
  time: string
  /** 确认型问题消息附带的内联按钮 */
  actions?: { label: string; kind: 'primary' | 'default' }[]
  /** 输入型问题消息附带的迷你表单 */
  form?: { key: string; label: string; placeholder?: string; required?: boolean }[]
}

// JobRun 增量：
export interface JobRun {
  // …v1 字段不变…
  /** 对话式消息流（替代 logs 的展示职责，logs 字段移除） */
  messages: RunMessage[]
}
```

## 5. 交互流程（Mock 演示脚本）

1. **运行推进**：每 3~4 秒流出一条 ADE 消息（步骤开始/完成/输出摘要），弹窗头部进度条与列表行徽标 `2/4` 同步推进；弹窗关闭时推进照常（状态在引擎里，不依赖弹窗开着）；
2. **人插话**：弹窗输入框发消息 → 绿气泡立即上屏 → 约 1.5 秒后 ADE 回应（固定话术：「收到，已记录：{摘要}」/「好的，将在后续步骤中应用」）；
3. **确认型暂停**：needApproval 任务运行到中点 → 流内出现问题消息（⚠ + 说明 + `[拒绝] [批准]`）+ 铃铛通知 + 待处理分组卡片；在**弹窗流内 / 待处理卡片 / 通知下拉**任一处批准 → 三处同步消失，流内出现「人工批准，继续运行」系统消息并继续推进；
4. **输入型暂停**：同上，问题消息带迷你表单（必填校验，空则提交禁用），提交后流内显示「收到人工输入（版本号=v1.4.0…）」并继续；
5. **终态**：成功/失败/已取消/已拒绝 → 系统消息收尾，输入框隐藏；历史运行在弹窗中只读回放消息流（头部可切换"当前/上次运行"？——**简化：只展示最近一次运行**，历史列表本期不做）；
6. **初始场景**（loomweb）：每日构建运行中（流里已有几条消息，打开弹窗即可插话）、周报生成等待确认、发布准备等待输入、MR 静态检查空闲（弹窗内显示上次运行回放 + 「运行」入口）。

## 7. 验收标准（v2.1）

1. 点击任务行打开弹窗：头部任务名/徽标/进度正确，消息流自动滚到底；
2. 运行中任务：弹窗内消息流实时推进（弹窗开着时可见），关闭弹窗不影响推进，重开可见新消息；列表行徽标与进度同步；
3. 弹窗输入框：发消息绿气泡立即上屏，约 1.5 秒后 ADE 回应；终态运行输入框隐藏；
4. 确认型暂停：弹窗流内问题消息带按钮；与待处理卡片、通知三处任一处理即全部同步消失，流内可见「人工批准，继续运行」；
5. 输入型暂停：弹窗流内迷你表单必填校验；页面待处理卡片与通知的「去填写」均打开弹窗并定位到问题消息；
6. 弹窗「编辑」模式：可改任务名/触发方式/参数/确认开关，可删除任务；运行中任务编辑禁用；
7. v1 验收标准（汇总联动/通知角标/取消运行/手动运行/启停约束）不回退；
8. 构建通过，提交 commit。

## 8. 风险与说明

- 纯 Mock：ADE 对插话的回应为固定话术；真实系统接 Agent 会话接口；
- 消息流不持久化，刷新重置；弹窗只展示最近一次运行（含进行中的当前运行），多历史回放本期不做；
- 弹窗内消息自动滚动仅在"已处于底部"时跟随，避免人回看历史时被强行拉底。
