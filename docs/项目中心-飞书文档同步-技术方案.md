## 1. 需求

1. 文档子 tab 的飞书目录树与文档清单从写死 Mock 换成真实飞书数据。
2. 项目可以登记多个同步源，点「立即同步」拉取该源整棵子树的文档清单（标题、类型、层级路径、飞书修改时间、链接）。
3. 同步结果落服务端：换设备、刷新、换人都能看到同一份清单；每源与每篇文档都有同步状态与失败原因。
4. 在「项目知识库」中把文档加入收录时，按类型拉正文 → 转 markdown/纯文本 → 存快照 → 状态置「待索引」。
5. 本轮不做定时同步、不做切分与检索。

## 2. 现状与差距

| 项 | 现状 | 差距 |
|---|---|---|
| 文档子 tab | `DocLibraryView` 用写死的 `FEISHU_TREE` 选择目录，导入直接把数据写进 `project.documents`（浏览器内存 / 本地持久化） | 需要真实浏览飞书树、服务端登记同步源、服务端落文档清单 |
| 项目知识库 | `KbIndexPanel` 读 `project.knowledge.docs` Mock，收录/索引状态机由前端 `setTimeout` 模拟 | 文档来源改为同步结果；收录/移出调接口；状态由后端返回 |
| 后端飞书 | `server/feishu.js` 只有 `tenant_access_token` 与通讯录；`server/index.js` 已有 OAuth 授权与云文档 scope 档位 | 没有云文档读取、没有 user token 刷新、没有同步任务 |
| 调度 | 服务端无任何定时器 | 本轮不做（§11 预留） |
| 版本判定 | Mock 无 | 需要 `revision`（飞书 `modified_time`）与内容 hash 区分「已同步 / 待更新」 |

## 3. 总体设计

两条独立管道，互不阻塞：

```
【A. 元数据同步】用户点「立即同步」
  飞书 API（drive/v1/files、wiki/v2/spaces/.../nodes）
    → 广度优先遍历源子树（分页、限深、限流）
    → upsert feishu_docs：外部 token / 类型 / 标题 / 层级路径 / modified_time
    → 本轮未出现的文档标记 deleted
    → feishu_sync_runs 记录本次统计与失败明细

【B. 正文摄入】用户在知识库中「加入收录」
  读 feishu_docs.external_type
    → 按类型取正文（docx blocks / 旧 doc / sheet values / bitable records / 文件导出任务）
    → 转 markdown / 纯文本
    → feishu_doc_contents 快照（带 revision、hash）
    → kb_state = ready（待索引，等 P3 切分管道消费）
```

**为什么拆开**：全量抓正文成本高（Office 要走导出任务排队、表格要分页、全局有限流），而文档 tab 只需要清单。正文只有被收录进知识库才有下游消费者。

两条管道共用同一份 `feishu_docs`，因此知识库列表不需要另存文档。

## 4. 飞书接口清单

| 用途 | 接口 | 权限 scope | 备注 |
|---|---|---|---|
| 列文件夹内容 | `GET /open-apis/drive/v1/files?folder_token=&page_size=200&page_token=` | `drive:drive:readonly` | 返回 `token / name / type / parent_token / url / modified_time / size` |
| 列 wiki 空间节点 | `GET /open-apis/wiki/v2/spaces/:space_id/nodes?parent_node_token=&page_size=50&page_token=` | `wiki:wiki:readonly` | 递归到根节点 `parent_node_token` 为空 |
| wiki 节点解析 | `GET /open-apis/wiki/v2/spaces/get_node?token=` | `wiki:wiki:readonly` | 拿到 `obj_token` 与 `obj_type`（docx/sheet/bitable/file…） |
| docx 正文 | `GET /open-apis/docx/v1/documents/:document_id/blocks` | `docx:document:readonly` | 取块结构转 markdown（保标题/列表/代码/表格） |
| docx 纯文本兜底 | `GET /open-apis/docx/v1/documents/:document_id/raw_content` | `docx:document:readonly` | 块转换失败时退化 |
| 旧版 doc 正文 | `GET /open-apis/doc/v2/:docToken/raw_content` | `docs:doc:readonly` | 兼容早期文档 |
| 电子表格 | `GET /open-apis/sheets/v3/spreadsheets/:token/sheets/query` + `.../values/:range` | `sheets:spreadsheet:readonly` | 按 sheet 转 markdown 表格，单表超 500 行截断 |
| 多维表格 | `GET /open-apis/bitable/v1/apps/:token/tables` + `.../tables/:table_id/records/search` | `bitable:app:readonly` | 字段名做表头，分页取全量并截断 |
| Office 文件 | `POST /open-apis/drive/v1/export_tasks` → 轮询 `GET .../:ticket` → `GET .../file/:file_token/download` | 导出权限（`drive:export:readonly` 一类，以开放平台为准） | 文件类型 → 导出格式：docx→docx/pdf，xlsx→xlsx，pptx→pdf |
| 限流 | 返回 `code = 99991400` | — | 指数退避（1s/2s/4s，最多 4 次） |

**scope 影响**：个人授权档位 `read` 只含 `docs:doc:readonly / docx:document:readonly / drive:drive:readonly / wiki:wiki:readonly`，缺 `sheets:spreadsheet:readonly`、`bitable:app:readonly` 与导出权限。要满足「全部类型」，需在 [index.js:333](../server/index.js:333) 的 `FEISHU_DOC_SCOPES_READ` 补齐，并在开放平台发布新版本。

## 5. 数据模型

新增 4 张表，均为 `node:sqlite` 可直接建（沿用 `server/db.js` 的 `ensureColumn` 兼容策略，但本次全是新表）。

```sql
-- 同步源：项目下的一个飞书文件夹或 wiki 空间
CREATE TABLE IF NOT EXISTS feishu_doc_sources (
  id             TEXT PRIMARY KEY,
  project_id     TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  kind           TEXT NOT NULL,              -- folder | wiki_space | doc
  token          TEXT NOT NULL,              -- folder_token | space_id | 单篇文档 token
  name           TEXT NOT NULL,
  url            TEXT NOT NULL DEFAULT '',
  auth           TEXT NOT NULL DEFAULT 'tenant', -- tenant | user（实际调用身份）
  doc_type       TEXT NOT NULL DEFAULT '',   -- kind=doc 时的飞书文档类型：docx/sheet/bitable/file
  last_synced_at TEXT,
  last_status    TEXT NOT NULL DEFAULT '',   -- ok | partial | failed
  last_error     TEXT,
  created_by     TEXT NOT NULL DEFAULT '',
  created_at     TEXT NOT NULL,
  updated_at     TEXT NOT NULL,
  UNIQUE(project_id, kind, token)
);

-- 文档清单：同步的产物，知识库收录也挂在这里
CREATE TABLE IF NOT EXISTS feishu_docs (
  id             TEXT PRIMARY KEY,
  project_id     TEXT NOT NULL,
  source_id      TEXT NOT NULL REFERENCES feishu_doc_sources(id) ON DELETE CASCADE,
  external_token TEXT NOT NULL,              -- obj_token / file_token / wiki node token
  external_type  TEXT NOT NULL,              -- docx | doc | sheet | bitable | file | mindnote | slides
  title          TEXT NOT NULL,
  url            TEXT NOT NULL DEFAULT '',
  parent_path    TEXT NOT NULL DEFAULT '',   -- 展示用层级路径：产品研发/移动端
  parent_token   TEXT NOT NULL DEFAULT '',
  modified_at    TEXT,                       -- 飞书侧修改时间
  revision       TEXT NOT NULL DEFAULT '',   -- 版本判定键（见 7.2）
  size_bytes     INTEGER,
  sync_status    TEXT NOT NULL DEFAULT 'synced', -- synced | failed | deleted
  sync_error     TEXT,
  last_synced_at TEXT NOT NULL,
  -- 知识库收录状态（P3 消费前停在 ready）
  kb_state       TEXT NOT NULL DEFAULT 'off',    -- off | fetching | ready | failed
  kb_error       TEXT,
  kb_revision    TEXT,                       -- 已拉正文对应的 revision
  kb_fetched_at  TEXT,
  deleted_at     TEXT,
  UNIQUE(project_id, external_token)
);
CREATE INDEX IF NOT EXISTS feishu_docs_source ON feishu_docs(source_id, parent_path);

-- 正文快照：只保留每个文档的最新一份
CREATE TABLE IF NOT EXISTS feishu_doc_contents (
  doc_id     TEXT PRIMARY KEY REFERENCES feishu_docs(id) ON DELETE CASCADE,
  revision   TEXT NOT NULL,
  format     TEXT NOT NULL DEFAULT 'markdown', -- markdown | text
  content    TEXT NOT NULL,
  char_count INTEGER NOT NULL DEFAULT 0,
  fetched_at TEXT NOT NULL
);

-- 同步运行记录：手动同步是异步的，前端靠它展示进度与结果
CREATE TABLE IF NOT EXISTS feishu_sync_runs (
  id          TEXT PRIMARY KEY,
  project_id  TEXT NOT NULL,
  source_id   TEXT,                          -- 空 = 全项目所有源
  trigger     TEXT NOT NULL DEFAULT 'manual',-- manual（预留 schedule）
  status      TEXT NOT NULL DEFAULT 'running',-- running | ok | partial | failed
  total       INTEGER NOT NULL DEFAULT 0,
  added       INTEGER NOT NULL DEFAULT 0,
  updated     INTEGER NOT NULL DEFAULT 0,
  removed     INTEGER NOT NULL DEFAULT 0,
  failed      INTEGER NOT NULL DEFAULT 0,
  error       TEXT,
  started_at  TEXT NOT NULL,
  finished_at TEXT
);
```

**不建 `doc_chunks`**：切分属于 P3，本方案只保证 `feishu_doc_contents` 里有可切的正文，并把 `feishu_docs.kb_state` 置为 `ready`。

## 6. 接口设计

全部挂在 `/api/projects/:id` 下，复用现有 `requireProject`（所有者/管理员/项目成员才可访问）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/doc-sources` | 同步源列表 + 每源最近一次运行摘要 |
| POST | `/doc-sources` | 新增源 `{kind, token, name, docType?}`，同一个 token 不重复登记 |
| POST | `/doc-sources/batch` | 批量新增 `{items: [...]}`：目录、空间、单篇文档可混选，已存在的按复用返回 |
| DELETE | `/doc-sources/:sourceId` | 移除源：级联删文档与快照 |
| GET | `/feishu/tree?kind=&token=&parent=` | 添加源/浏览用，按层懒加载目录树（只列目录，不拉全树） |
| POST | `/doc-sync` | 启动元数据同步 `{sourceId?}`，返回 `{runId}`（202） |
| GET | `/doc-sync/runs/:runId` | 轮询运行状态：status + 计数 + 当前路径 |
| GET | `/docs?sourceId=&folder=&q=&kb=` | 文档清单与目录树（目录由 `parent_path` 派生） |
| POST | `/docs/:docId/kb` | 加入知识库：触发正文拉取，`kb_state` → `fetching`，返回 202 |
| DELETE | `/docs/:docId/kb` | 移出知识库：删快照，`kb_state` → `off` |
| GET | `/docs/:docId/content` | 读快照正文（未拉取时返回 409） |

并发约束：同一项目同一时刻只允许一个同步 run（进程内 Map 锁），重复提交返回已有 runId。正文拉取按文档加锁，避免重复下载。

## 7. 元数据同步流程

### 7.1 遍历

```
source.kind = folder
  BFS：drive/v1/files(folder_token) → 子项
        type ∈ {folder} 入队（深度 ≤ 8）
        其余记为文档节点
        type = wiki？→ 通过 wiki get_node 解析出 obj_token 与空间节点

source.kind = wiki_space
  BFS：wiki/v2/spaces/:space_id/nodes(parent_node_token)
        每个 node 用 node_token 作为 external_token，
        obj_token 用于后续取正文
```

- 每层分页取全（`page_token`），单源节点上限 5000，超出记 `partial` 并停止深入。
- 请求并发 3，单请求超时 15s，命中限流则退避后重试。

### 7.2 版本判定（revision）

- 文档：`revision = modified_time`（文件再加 `size`）。
- wiki 节点：`revision = max(node.obj_edit_time, node.node_edit_time)`。
- 只有 `revision` 变化才更新行，并清空 `kb_revision`（表示快照已过期，知识库里显示「待更新」）。

### 7.3 增删改

| 情况 | 处理 |
|---|---|
| 新文档 | 插入，`sync_status = synced` |
| `revision` 变化 | 更新标题/路径/时间，`kb_state` 若为 `ready` 则标「待更新」（`kb_revision != revision`） |
| 路径/标题变化 | 更新 `parent_path` / `title` / `parent_token`，不重建 |
| 本轮未出现 | `deleted_at` + `sync_status = deleted`，`kb_state = off`，删快照 |
| 单节点失败 | 记 `sync_error`，不影响整批；源级结果置 `partial` |

### 7.4 运行记录

每次同步写一条 `feishu_sync_runs`，结束时汇总 `added/updated/removed/failed`。前端每 1s 轮询 `/doc-sync/runs/:runId`，完成后自动刷新 `/docs`。

## 8. 正文摄入流程（加入知识库）

### 8.1 类型 → 转换

| external_type | 取正文 | 产出 |
|---|---|---|
| `docx` | `docx/v1/documents/:id/blocks` | blocks → markdown（heading / text / bullet / ordered / code / quote / todo / divider / table / image 占位） |
| `doc` | `doc/v2/:token/raw_content` | 纯文本 → markdown 段落 |
| `sheet` | sheets 元信息 + values | 每个 sheet 一张 markdown 表，sheet 名作二级标题 |
| `bitable` | tables + records | 每张表一张 markdown 表，字段名作表头 |
| `file` | export_tasks 创建 → 轮询 → 下载 | docx/xlsx → 文本；pptx/pdf → 抽取文本层（本期仅纯文本，不做版面还原） |
| 其他（mindnote/slides…） | 不支持 | `kb_state = failed`，`kb_error = '该类型暂不支持收录'` |

### 8.2 限制

- 单文档正文上限 2 MB / 5000 块，超出截断并在 `kb_error` 写「内容过长，已截断」。
- 导出任务轮询上限 60s，超时报失败并允许重试。
- 幂等：`kb_revision === revision` 且已有快照 → 直接返回，不重复拉取。

### 8.3 状态机

```
off ──收录──> fetching ──成功──> ready（待索引）
                 └────失败──> failed ──重试──> fetching
ready ──飞书 revision 变化──> ready（标「待更新」，kb_revision ≠ revision）
ready ──移出──> off（删快照）
```

`ready` 之后不自动推进，等 P3 切分/嵌入管道消费并把状态改成 `indexed` 或 `failed`。

## 9. 鉴权与 token

1. **身份选择**：源记录 `auth`。目录源默认 `tenant`（需把文件夹共享给应用，或文件夹由应用创建）；wiki 空间若应用未加入空间，回退为当前登录用户的 `user_access_token` 并在源行标「个人身份」。两者都不可用时报可操作错误。
2. **tenant token**：内存缓存到过期前 5 分钟，失效时透明重取。
3. **user token**：目前只存了 token 本身，需补 `expires_at` 与 `refresh_token` 刷新（`POST /open-apis/authen/v1/oidc/refresh_access_token`）；刷新失败清空授权并提示重新授权。
4. **不泄漏**：token 只存在 `server/data/secrets.json`，接口不回传，日志不打印；文档接口只返回 `external_token` 给项目成员（用于跳转与后续正文拉取）。
5. **越权防护**：所有接口先过 `requireProject`，再校验文档是否属于该项目，不依赖飞书侧权限兜底。

## 10. 前端改造

### 10.1 文档子 tab（`DocLibraryView`）

- **顶部工具栏**：同步源下拉（多源切换 + 「全部源」）+ `[立即同步]` + `[添加同步源]`。已添加的源在添加弹窗的列表里直接显示为勾选并带「已添加」标记，点一下即移除；工具栏不再单独放管理入口。

- **添加源弹窗**：顶部两个 tab（云空间 / 知识库空间），按层懒加载浏览（面包屑 + 下钻），**目录与单篇文档都可勾选、可跨层级与跨 tab 多选**；勾目录 = 整棵子树，勾文档 = 只同步这一篇；当前所在目录也可直接勾选。确认后一次批量登记并自动发起同步。
- **同步中**：按钮 loading + 顶部细进度条（已扫描 N 篇 / 当前路径），完成后 toast 显示「新增 x / 更新 y / 移除 z / 失败 w」。
- **空态**：无同步源时整块引导「添加飞书同步源」。

### 10.2 项目知识库子 tab（`KbIndexPanel`）

- 数据源改为 `/docs?kb=on`；收录清单 = `kb_state != off`。
- 行状态徽标映射：`fetching` 拉取中、`ready` 待索引、`failed` 失败（带原因）、`kb_revision ≠ revision` → 待更新。
- 行操作：加入收录 / 移出 / 重试 / 在飞书中打开；索引详情弹窗展示快照字符数、拉取时间、失败原因。
- 片段数暂显示「—」，检索测试按钮置灰并提示「待 P3」。
- 统计条改为：已收录 / 待索引 / 失败 / 待更新。

### 10.3 数据层

- 新增 `src/lib/docSyncApi.ts`，统一封装 §6 接口与错误信息。
- `ProjectDetail` 把 `projectId` 传给 `KnowledgePanel` → 两个子 tab。
- `project.documents` 与 `project.knowledge.docs` 的 Mock 不再参与渲染（类型保留，后续统一清理）；`Knowledge.folders` 由服务端派生目录取代。
- 文档 tab 的 `onUpdateLibrary` / `onUpdateFeishu` 中，前者删除，后者保留（授权仍走设置页）。

## 11. 定时同步（本轮不做，预留设计）

数据模型已能承载，后续只需：

1. `feishu_doc_sources` 增加 `schedule_json`（`{enabled, freq: 'interval'|'daily'|'weekly', minutes, time, weekday}`）、`next_run_at`、`last_run_at`。
2. 服务端 30s tick：查 `next_run_at <= now` 的源，按 §7 流程以 `trigger = 'schedule'` 起 run，串行 + 单项目互斥。
3. 进程启动时把过期的 `next_run_at` 顺延到下一个周期，不补跑（避免重启风暴）。
4. 前端在文档子 tab 工具栏加「定时同步」设置：开关 + 频率 + 显示上次/下次同步时间；沿用自动化任务已有的 `ScheduleRule` 文案约定。

接入时不需要改动同步与摄入流程本身，只增加触发源与配置 UI。

## 12. 错误与降级

| 场景 | 表现 | 处理 |
|---|---|---|
| 未配置企业授权且无个人授权 | 同步按钮直接失败 | 提示去设置页授权 |
| 应用不在 wiki 空间 | 该源同步失败 | 提示「把应用加入空间或改用个人身份」 |
| 飞书限流 | 单节点重试后仍失败 | 记入 `failed`，整批继续；提示稍后重试 |
| 单文档无权限 | 该行失败 | 其余正常，行内显示「无权访问」 |
| 导出任务超时 | 收录失败 | 可重试；不阻塞其他文档 |
| 文档已删除 | 列表消失 | 软删 + 清快照；审计保留在 `feishu_sync_runs` |
| user token 过期 | 同步/收录失败 | 尝试刷新；失败提示重新授权 |
| 未收录的文档被打开正文 | 409 | 前端引导「先加入知识库」 |

## 14. 验收标准

| 项 | 目标 |
|---|---|
| 源登记 | 目录源与 wiki 空间源均可添加、移除；重复 token 不重复登记 |
| 同步正确性 | 新增/改名/移动/删除四类变化在清单中正确反映，层级路径与飞书一致 |
| 幂等 | 同一源连续同步两次，第二次 `added/updated/removed = 0` |
| 失败隔离 | 构造单文档无权限，其余文档仍同步成功，源状态为 `partial` |
| 正文覆盖 | docx / doc / sheet / bitable / file 五类均能收录为 `ready`，快照非空 |
| 状态一致性 | 飞书修改后重新同步，已收录文档显示「待更新」；展开后可手动重拉 |
| 越权 | 非项目成员访问任一文档接口返回 403/404 |
| 回归 | 会话、终端、成员管理、飞书授权不受影响；`npm run build` 通过 |

## 15. 风险

| 风险 | 对策 |
|---|---|
| 飞书导出任务排队久 | 单文档异步 + 超时重试；UI 显示「拉取中」而不是阻塞 |
| 大文档/大表格转换耗内存 | 强上限（2MB / 5000 块 / 500 行），超出截断并标注 |
| 权限模型不一致（项目成员 vs 飞书权限） | 统一按项目成员授权，快照不继承飞书 ACL；收录时提示「将向项目成员可见」 |
| 应用身份拿不到个人空间文档 | 明确两种身份与回退规则，错误文案指向具体操作 |
| 同步范围失控（整空间上千篇） | 源粒度由用户显式选择，单源节点上限 5000，超限提示拆分源 |
| 正文与知识库状态脱节 | `kb_revision` 与 `revision` 双写，列表以二者是否相等判定「待更新」 |

## 16. 与后续阶段的衔接

- **P3 切分/嵌入**：消费 `kb_state = ready` 的文档与 `feishu_doc_contents`，回写 `indexed/failed`，`chunks` 指向 `feishu_docs.id`。
- **定时同步**：按 §11 接上，复用同一 run 流程。
- **Agent 工具**：`list_docs` / `read_doc` 直接读 `feishu_docs` + `feishu_doc_contents`，写操作（发布回飞书）不在本期。
- **本地镜像**：本期不产出 markdown 镜像文件；若 Agent 需要 grep，按 `feishu_doc_contents` 生成即可，不影响本方案结构。

### 17.2 与方案的偏差

1. **PDF / 思维导图 / 幻灯片**暂不能提取正文：Office 只支持 docx / doc / xlsx / pptx，其余类型收录时返回「暂不支持」并置 `failed`。
2. **不产出本地 markdown 镜像**：正文只落 `feishu_doc_contents`，Agent grep 镜像按 §16 后续再接。
3. **片段数与检索测试**未实现，知识库统计改为「收录 / 待索引 / 拉取中 / 待更新 / 失败」，检索按钮置灰标注「待 P3」。
4. **Mock 退场**：`project.documents`、`knowledge.folders/docs` 不再参与这两个子 tab 的渲染；`ProjectDetail` → `KnowledgePanel` 的传参简化为 `projectId`，`feishu` / `onUpdateFeishu` 两个 prop 随之移除（授权仍在设置页完成）。
