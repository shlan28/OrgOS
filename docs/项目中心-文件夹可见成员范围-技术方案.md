# 「项目中心 · 文件夹可见成员范围」功能 - 技术方案

> 创建日期：2026-09-14
> 更新日期：2026-09-14（R3：先行落地「新建文件夹选成员 + 编辑文件夹（改名 + 成员范围）」；权限过滤/锁定等其余项待确认后实施）

## 1. 背景与目标

项目中心目前所有文件夹对所有人生效。本需求为**文件夹层**增加权限模型：

1. 文件夹增加「**可见成员范围**」（哪些人能看到这个文件夹）；
2. 文件夹角色分 **owner（文件夹所有者）** 和 **成员（文件夹成员）** 两种身份；
3. **范围外但参与项目的人**：看不到文件夹，但自己的项目**提升到顶层、与文件夹同级**平铺展示。

### 1.1 三类身份权限总表

| 身份 | 看到文件夹 | 看到文件夹内的项目 | 点击进入项目详情 | 创建项目到文件夹 | 删除文件夹 |
|---|---|---|---|---|---|
| owner | ✅ | ✅ 全部（含未参与的） | ❌ 未参与的**不能进**（仅自己参与的能进） | ✅ | ✅（**必须 0 项目**才能删） |
| 成员 | ✅ | ❌ 只能看到**自己参与的** | ✅（自己参与的能进） | ✅ | ❌ |
| 范围外 · 项目成员 | ❌ 文件夹不可见 | ❌ | — | ❌ | ❌ |
| 范围外 · 非项目成员 | ❌ | ❌ | ❌ | ❌ | ❌ |

**核心规则拆解：**

- **owner**：看得到文件夹与其中全部项目（浏览层面）；但进详情仍以**项目成员身份**为准 —— 未参与的项目只能看卡片，不能点进详情；
- **成员**：看得到文件夹（含创建项目入口），但文件夹内只显示**自己参与的项目**（是项目成员才能看到卡片并可进详情页）；
- **范围外 · 项目成员**：文件夹整个不可见；其参与但无文件夹权限的项目，**直接在项目中心顶层平铺**（与文件夹卡片同级），可直接进入详情；
- **范围外**：不能在无权限的文件夹里创建项目（新建项目弹窗的「所属文件夹」下拉不出现该文件夹）。

### 1.2 顶层视图效果示意（当前用户 shilu）

```
项目中心
├── 📁 研发线（shilu = owner）        ← 文件夹卡片
├── 📁 数据平台（shilu = 成员）        ← 文件夹卡片
├── 📁 增长实验（shilu 范围外，不可见）
│     └── （内部项目被提升）🎁 会员运营  ← shilu 是该项目成员 → 卡片提升到顶层
├── （未分组项目，保持全员可见）adhoc 脚本仓
```

## 3. 数据模型设计

### 3.1 `ProjectFolder` 扩展（`src/data/projects.ts`）

```ts
/** 文件夹成员条目（owner / 成员） */
export interface FolderMember {
  /** 用户名（与 Member.name / CURRENT_USER.name 对齐） */
  name: string
  role: 'owner' | 'member'
}

/** 项目文件夹（单层，不嵌套） */
export interface ProjectFolder {
  id: string
  name: string
  /** 可见成员范围（owner + 成员）；空 = 所有人可见（兜底，避免 Mock 刷新后文件夹消失） */
  members: FolderMember[]
}

/** 当前用户对某文件夹的身份（null = 范围外，不可见） */
export function getFolderRole(folder: ProjectFolder, userName: string): 'owner' | 'member' | null

/** 用户可见的项目（项目中心列表过滤核心） */
export function canSeeProject(project: Project, folder: ProjectFolder | undefined, userName: string): boolean
```

可见性规则（单一实现，列表与入口共用）：

```
canSeeProject(p, folder, user):
  folder 不存在（未分组）→ true（未分组保持全可见，不在本需求范围）
  folder.members 为空     → true（无范围 = 全员可见兜底）
  user 是 folder owner    → true（owner 能看到文件夹里所有项目）
  user 是 folder member   → user ∈ p.members（成员只能看到自己参与的项目）
  其他                    → user ∈ p.members
                            （范围外但项目成员 → 项目可见，但展示位置提升到顶层，见 3.1.2）
```

### 3.1.2 项目展示位置推导（新增）

```
projectDisplayMode(p, folder, user):
  canSeeProject 为 false         → 'hidden'（完全不渲染）
  folder 不存在 或 members 为空   → 'root'（未分组/全员文件夹：顶层平铺）
  user 是 owner 或 member        → 'in-folder'（归属文件夹内）
  user ∈ p.members（范围外）      → 'root-elevated'（提升到顶层，与文件夹卡片同级）
```

「提升到顶层」的项目卡片带**来源标识**（卡片角落小徽标「来自 研发线」或文件夹图标变体），
让用户知道该项目实际归属某文件夹、只是自己没有文件夹权限——避免误解为未分组项目。
点击可直接进入详情（是项目成员）。

`canOpenProject(p, user)`（进入详情的唯一判据，**与文件夹身份无关**）：

```
canOpenProject(p, user) = user ∈ p.members（项目成员才能进详情）
```

### 3.1.3 新建项目时文件夹下拉过滤

```
folderOptionsForCreate(user) = folders.filter(
  f => f.members 为空 || user 是 f 的 owner || user 是 f 的 member
)
```

范围外文件夹**不出现在**「所属文件夹」下拉中（顶层与下钻视图共用此过滤）。

### 4.1 文件夹卡片（`FolderCard.tsx`）

- 卡片副标题在 `N 个项目` 后追加身份徽标：**「所有者」**（紫色调）/ **「成员」**（灰蓝），让 shilu 一眼识别当前身份；

### 4.3 新建文件夹弹窗（改造现有）

- 新增字段「**可见成员范围**」：`MultiSelect`（成员池，可空）；
- 创建后 members = `[{创建者, owner}, ...所选成员（member）]`；
- 重命名弹窗不加成员字段（重命名只改名，成员管理走独立弹窗）。

### 4.4 项目可见性过滤（`ProjectCenter.tsx`）

- **顶层**：
  - `folders.filter(可见)` —— 当前用户是 owner/成员（或 members 为空）的文件夹才渲染卡片；
  - **提升项目**：`projects.filter(p => projectDisplayMode(p) === 'root-elevated')` 追加渲染在文件夹卡片之后、未分组项目之前（或直接混排，卡片带「来自 xx」来源徽标）；
  - 未分组项目（`root`）保持现状；
- **下钻**：`visibleProjects` 改用 `canSeeProject` 过滤（owner → 全部；member → 仅自己参与的）；
- **文件夹内视图空态**分两种文案：
  - 文件夹真的 0 项目 → 现有文案「该文件夹还没有项目」；
  - 有项目但当前用户是成员且未参与 → 「你不是这些项目的成员，仅文件夹所有者与项目成员可见」说明性空态；
- **统计文案**：下钻后副标题「N 个项目」为**过滤后**数量；顶层统计见 8 节待确认项。

### 4.5 owner 点未参与项目的处理（`ProjectCard.tsx`）

- 卡片右上角（状态徽标旁）出现 🔒 小徽标 + title：「文件夹所有者可浏览项目卡片，进入详情需为项目成员」；

### 4.6 提升项目的卡片样式（`ProjectCard.tsx`）

- `elevatedFrom` prop：卡片底部或名称旁显示小字「来自 增长实验」（12px 灰，带小文件夹图标）；
- 其余展示与普通项目卡片一致，点击可进详情（项目成员）。

### 4.7 删除文件夹规则收紧（`ProjectCenter.tsx` + `App.tsx`）

现状是"有项目时项目自动移至未分组"，**改为**：

- 文件夹内项目数 > 0：删除按钮禁用（menu item disabled + title「请先移出全部项目」）；确认弹窗不再出现；
- 项目数 = 0：二次确认后删除（文案：确定删除空文件夹「xxx」吗？）；
- `handleDeleteFolder` 增加防御：非 0 项目直接 return（保证数据不变式）。
- 「移动到」菜单同理收紧：范围外文件夹**不出现**在移动目标列表中（与新建下拉同一过滤口径）。

## 8. 待鹿鹿子大王确认的问题

1. **未分组项目**：是否保持"全员可见"现状？（本方案默认：是，本需求只管文件夹层）
2. **member 能否移动项目**：现状项目卡片「移动到文件夹」对所有人开放。member 把项目移出文件夹后，若项目因此对自己不可见（member 只能看到自己参与的项目），会产生"挪走后消失"的体验——本方案默认**保留移动能力**（仅过滤范围外目标），是否需要进一步收紧为 owner 才能移动？
3. **顶层统计文案**：「共 N 个项目 · M 个文件夹」中的 N/M 是否改为"当前用户可见数"（含提升项目）？（默认改为可见口径：`共 X 个项目 · Y 个文件夹`，X = 文件夹内可见 + 提升 + 未分组，Y = 可见文件夹数）
4. **owner 进未参与项目**：本方案按您原话保留"可见卡片 + 🔒 锁定详情"形态，未参与项目的详情页整页不可进入（不是只读模式）——确认？
