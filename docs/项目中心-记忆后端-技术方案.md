## 1. 范围

### 1.1 本轮做

- 「记忆」tab 的全部数据落库：记忆条目列表、手动添加、删除、清理过期、记忆规则读写。
- 生命周期派生（活跃 / 即将过期 / 已归档）与保留策略的过期流转。
- **会话默认注入**：每轮召回 top-k 拼进提示词，项目级与每轮双开关，SSE 回报本轮用了哪些。
- **按轮次自动收集**：每个会话每累计 N（默认 5）个已完成轮次，用项目 Agent 的运行时模型抽取这些轮次的会话内容，写入「会话沉淀」；不足 N 轮可「立即收集」。
- 项目级权限校验与 `memory_events` 审计。
- 前端 `MemoryPanel` 从 Mock 切到真实接口。

### 1.2 本轮不做

- 定时**自动反思**（需要 LLM 评估 + 调度）。
- 每轮实时收集（改为每 N 轮累计一次）。
- 记忆的**置顶 / 手动排除**（本轮只按相关度自动选）。
- 记忆编辑（UI 当前只有删除，无编辑）。
- 自动收集的**向量去重**（本轮只做文本 hash；向量去重与反思一起做）。

自动收集见 §8（本轮实现），自动反思见 §9（下一轮）；字段与表结构本轮一次建好。

## 3. 总体设计

```
前端 MemoryPanel / ChatPane（会话）
  │ CRUD、记忆规则              │ 每轮 useMemory
  ▼                            ▼
server/index.js  ──────────►  server/runner.js（startTurn）
  │                              │ recallMemories()
  ▼                              ▼
server/memory.js ◄───────────────┘（派生 / 过期流转 / 召回 / 收集 / 预留的反思）
  ▼
server/db.js（memories / memory_settings / memory_events / memory_job_runs）
  ▼
SQLite（server/data/app.db）
```

- 记忆**只存 SQLite**，不落文件；写入路径独立于文件 watcher。
- 页面读到的 `lifecycle`、`remainDays` 一律由后端派生，前端不再自己推断。
- 过期流转与自动任务都写 `memory_events`，便于排查「这条记忆为什么没了」。
- 累计收集由轮次完成事件触发：待处理轮次达到阈值才调用模型；不引入定时器。
- 会话侧在启动 CLI 前按「项目总开关 × 本轮开关」召回 top-k，拼进提示词；不调用模型，失败不影响本轮。

## 4. 数据模型（SQLite）

建表语句加在 `server/db.js` 的 `db.exec(...)` 中，全部 `CREATE TABLE IF NOT EXISTS`，启动即自动迁移，无需单独脚本。

### 4.1 `memories`

```sql
CREATE TABLE IF NOT EXISTS memories (
  id                TEXT PRIMARY KEY,
  project_id        TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  content           TEXT NOT NULL,
  source            TEXT NOT NULL DEFAULT '手动',        -- 手动 | 会话沉淀
  source_session_id TEXT,
  source_turn_id    TEXT,
  source_file_id    TEXT,
  status            TEXT NOT NULL DEFAULT 'active',      -- active | archived | deleted
  importance        REAL NOT NULL DEFAULT 0.5,
  reflect_note      TEXT,                                -- AI 反思备注（只读展示）
  dedupe_hash       TEXT,                                -- sha256(规范化文本)
  embedding         BLOB,                                -- Float32 归一化向量（可选）
  embedding_model   TEXT NOT NULL DEFAULT '',
  expires_at        TEXT,                                -- NULL = 永久保留
  last_used_at      TEXT,
  last_reflected_at TEXT,
  created_by        TEXT NOT NULL DEFAULT '',            -- 手动添加者；系统收集为空
  created_at        TEXT NOT NULL,
  updated_at        TEXT NOT NULL,
  deleted_at        TEXT
);

CREATE INDEX IF NOT EXISTS memories_project_status
  ON memories(project_id, status, created_at);

CREATE UNIQUE INDEX IF NOT EXISTS memories_dedupe
  ON memories(project_id, dedupe_hash)
  WHERE dedupe_hash IS NOT NULL AND status <> 'deleted';
```

要点：

- **不存 `expiring`**。总体方案把它列为 status，但它是时间派生值，落库会随时钟变脏；这里只存 `active | archived | deleted`，前端看到的「即将过期」由 `expires_at` 现算（§4.5）。
- 删除 = `status='deleted'` + `deleted_at`，行保留；部分唯一索引把 deleted 排除，同内容可再次添加。
- `embedding_model` 与知识库切片同样处理：模型变了旧向量不可比，需要重嵌。

### 4.2 `memory_settings`

每项目一行，首次访问时懒创建（`ensureMemorySettings`），历史项目无需回填。

```sql
CREATE TABLE IF NOT EXISTS memory_settings (
  project_id        TEXT PRIMARY KEY REFERENCES projects(id) ON DELETE CASCADE,
  auto_collect      INTEGER NOT NULL DEFAULT 1,
  inject_memory     INTEGER NOT NULL DEFAULT 1,           -- 会话使用记忆的总开关
  collect_rules     TEXT NOT NULL DEFAULT '',
  collect_every     INTEGER NOT NULL DEFAULT 5,           -- 每累计 N 个已完成轮次收集一次（1–50）
  retention_days    INTEGER NOT NULL DEFAULT 90,
  permanent         INTEGER NOT NULL DEFAULT 0,
  expire_policy     TEXT NOT NULL DEFAULT '自动归档',     -- 自动归档 | 自动删除 | 仅提醒
  auto_reflect      INTEGER NOT NULL DEFAULT 0,
  reflect_frequency TEXT NOT NULL DEFAULT '每周',         -- 每天 | 每周 | 每月
  reflect_rules     TEXT NOT NULL DEFAULT '',
  last_retention_at TEXT,
  last_reflect_at   TEXT,
  updated_at        TEXT NOT NULL
);
```

`auto_collect` 管**写**、`inject_memory` 管**读**，二者互不依赖：关闭自动收集不影响已有记忆被会话使用，关闭注入也不影响继续收集。

### 4.3 `memory_events`

```sql
CREATE TABLE IF NOT EXISTS memory_events (
  id           TEXT PRIMARY KEY,
  project_id   TEXT NOT NULL,
  memory_id    TEXT NOT NULL REFERENCES memories(id) ON DELETE CASCADE,
  type         TEXT NOT NULL,   -- created | collected | reflected | archived | expired | deleted | restored
  actor        TEXT NOT NULL DEFAULT '',   -- 用户名 / system
  payload_json TEXT NOT NULL DEFAULT '{}',
  created_at   TEXT NOT NULL
);

CREATE INDEX IF NOT EXISTS memory_events_memory
  ON memory_events(memory_id, created_at);
CREATE INDEX IF NOT EXISTS memory_events_project
  ON memory_events(project_id, created_at);
```

### 4.4 `memory_job_runs`

与 `kb_index_runs` 同构，用于过期扫描 / 收集 / 反思的运行记录；本轮写 `retention` 与 `collect`，`reflect` 下一轮。

```sql
CREATE TABLE IF NOT EXISTS memory_job_runs (
  id          TEXT PRIMARY KEY,
  project_id  TEXT NOT NULL,
  kind        TEXT NOT NULL,                  -- retention | collect | reflect
  trigger     TEXT NOT NULL DEFAULT 'threshold', -- threshold | manual
  status      TEXT NOT NULL DEFAULT 'running',-- running | done | skipped | error
  scanned     INTEGER NOT NULL DEFAULT 0,
  changed     INTEGER NOT NULL DEFAULT 0,
  detail_json TEXT NOT NULL DEFAULT '{}',
  error       TEXT,
  started_at  TEXT NOT NULL,
  finished_at TEXT
);

CREATE INDEX IF NOT EXISTS memory_job_runs_project
  ON memory_job_runs(project_id, kind, started_at);
```

### 4.5 生命周期派生

常量 `EXPIRING_WINDOW_DAYS = 7`。

| 条件（按顺序） | 返回 `lifecycle` | `remainDays` |
|---|---|---|
| `status = 'archived'` | `已归档` | 不返回 |
| `expires_at != null && expires_at <= now` | `即将过期`（已过期但按「仅提醒」保留） | `0` |
| `expires_at != null && expires_at <= now + 7d` | `即将过期` | `ceil((expires_at - now) / 1d)` |
| 其余（含 `expires_at = null`） | `活跃` | 不返回 |

- `expires_at` 的写入规则：`permanent = 1` → `NULL`；否则 `created_at + retention_days` 天。
- 修改规则时（确认项 5）：若 `retentionDays` 或 `permanent` 变化，重算所有 `status != 'archived' && status != 'deleted'` 的行的 `expires_at`；归档行保持不变。
- 时间统一存 `toISOString()`（UTC），字符串比较即可排序与判过期。

### 4.6 会话收集游标

```js
ensureColumn('sessions', 'memory_collect_cursor', 'memory_collect_cursor INTEGER NOT NULL DEFAULT 0')
```

- 记录该会话已处理到的最大 `turn.seq`；
- 待处理轮次数 = 该会话 `status='done'` 且 `seq > cursor` 的数量；达到 `collect_every` 时触发收集；
- 首次创建 `memory_settings`，或 `auto_collect` 由关变开时，把所有会话游标置为当前最大 `seq`——只收集今后的新内容，不回灌历史；
- 新会话默认 0，只收集自己的新轮次。

## 5. 接口设计

所有路由都在 `server/index.js`，沿用 `requireProject(req, res, id)`（不存在 404，非成员 403）。

### 5.1 列表

```
GET /api/projects/:id/memories?status=all&q=&limit=100&offset=0
```

- `status`：`all`（默认，不含 deleted）| `active` | `archived` | `deleted`（仅管理员）。
- `q`：内容包含匹配，trim 后为空则不过滤。
- `limit` 1–500，默认 100。
- 排序：未归档在前，同组按 `created_at DESC`。

```json
{
  "memories": [
    {
      "id": "mem_xxx",
      "content": "组件拆分应遵循展示/容器分离",
      "source": "手动",
      "createdAt": "2026-10-20T08:00:00.000Z",
      "lifecycle": "活跃",
      "remainDays": 89,
      "reflectNote": "与当前组件拆分规范一致，保持活跃",
      "status": "active",
      "expiresAt": "2027-01-18T08:00:00.000Z",
      "createdBy": "鹿鹿子大王"
    }
  ],
  "counts": { "total": 12, "expiring": 2, "archived": 1 }
}
```

`counts.total` 不含 deleted；`expiring` 是派生口径，与列表一致。

### 5.2 手动添加

```
POST /api/projects/:id/memories
{ "content": "支付回调需幂等处理" }
```

- `content` trim 后 1–4000 字，否则 400。
- `source` 固定 `手动`，`created_by` 取登录用户名，`importance = 0.5`。
- 计算 `dedupe_hash`；同项目存在未删除的同 hash → **409**，返回已有记忆，不重复插入。
- 若知识库嵌入配置可用，为内容生成向量（`embedding` + `embedding_model`，5s 超时）；失败或未配置则只存文本，召回走关键词降级。
- 成功 **201** `{ "memory": MemoryDTO }`，并写 `memory_events(type='created')`。

### 5.3 删除

```
DELETE /api/projects/:id/memories/:memoryId
```

- 记忆不存在或不属于该项目 → 404。
- 权限：成员仅能删 `created_by = 自己` 的；系统收集（`created_by=''`）与他人记忆仅项目负责人 / 组织管理员可删 → 403。
- 软删：`status='deleted', deleted_at=now`，写 `memory_events(type='deleted')`。
- 返回 `{ "ok": true }`。

### 5.4 清理过期

```
POST /api/projects/:id/memories/archive-expired
```

- 语义：把**当前展示为「即将过期」**的条目归档（`status='active'` 且 `expires_at <= now + 7d`），与按钮 title「将即将过期的条目归档」一致。
- 与 `expirePolicy` 无关：即使策略是自动删除，手动清理也只归档。
- 每条写 `memory_events(type='archived', payload={reason:'manual_clean'})`。
- 返回 `{ "archived": 3 }`。

### 5.5 读规则

```
GET /api/projects/:id/memory-settings
```

- 不存在则创建默认行后返回（`ensureMemorySettings`）。
- 返回 `{ "settings": MemorySettingsDTO }`，字段为 camelCase：`autoCollect / injectMemory / collectRules / collectEvery / retentionDays / permanent / expirePolicy / autoReflect / reflectFrequency / reflectRules / updatedAt`。

### 5.6 保存规则

```
PUT /api/projects/:id/memory-settings
```

- 权限：项目负责人 / 组织管理员（确认项 6 只放宽「清理过期」，不含规则）。
- 接受完整对象或部分字段；校验：
  - `retentionDays` 为 1–3650 整数（`permanent=true` 时忽略但仍存）；
  - `expirePolicy ∈ {自动归档, 自动删除, 仅提醒}`；
  - `reflectFrequency ∈ {每天, 每周, 每月}`；
  - `autoCollect / injectMemory / permanent / autoReflect` 为布尔；
  - `collectEvery` 为 1–50 的整数；
  - `collectRules` / `reflectRules` ≤ 2000 字。
- `injectMemory` 只影响后续轮次是否注入，不改任何记忆的状态或过期时间。
- `autoCollect` 由关变开时，保存后把该项目所有会话的收集游标置为当前最大 `seq`（不回灌历史）。
- 调整 `collectEvery` 不立即触发收集；下一次轮次完成或手动收集时按新阈值判断。
- 保存后若保留天数或永久标记变化，重算存量 `expires_at`（§4.5）。
- 保存后立即对该项目跑一次过期流转（只影响已过期项，不改「即将过期」）。
- 返回 `{ "settings": MemorySettingsDTO }`。

### 5.7 预留接口（本轮不实现）

```
GET /api/projects/:id/memories/:memoryId/events   审计时间线（可后续做详情）
```

召回不暴露公开 REST：由 `runner.startTurn` 直接调用 `server/memory.js` 的 `recallMemories`（见 §10），避免多一层鉴权与网络往返。

### 5.8 错误码

| 状态码 | 场景 |
|---|---|
| 400 | 内容为空 / 超长、天数越界、枚举非法 |
| 401 | 未登录（全局中间件） |
| 403 | 非项目成员、无权删除该条、无权改规则 |
| 404 | 项目不存在、记忆不存在或不属于该项目 |
| 409 | 同项目已存在相同内容（返回已有记忆） |

### 5.9 权限矩阵

| 操作 | 项目成员 | 项目负责人 / 组织管理员 |
|---|:--:|:--:|
| 查看列表与规则 | ✓ | ✓ |
| 手动添加 | ✓ | ✓ |
| 删除自己的手动记忆 | ✓ | ✓ |
| 删除他人 / 系统收集的记忆 | | ✓ |
| 清理过期（归档） | ✓ | ✓ |
| 保存记忆规则 | | ✓ |

实现上新增 `projectRoleOf(user, project)`：组织 `所有者` / `管理员` → `admin`；项目成员中 `permission === '项目负责人'` → `manager`；其余成员 → `member`；非成员 `requireProject` 已拦截。

### 5.10 立即收集

```
POST /api/projects/:id/memories/collect
```

- 权限：项目负责人 / 组织管理员（会消耗模型调用）。
- 异步执行，返回 **202** `{ "queued": true }`；同一项目已有收集任务时返回 `{ "queued": false, "reason": "running" }`。
- 与累计触发共用 `runCollect(projectId, { trigger: 'manual' })`：处理各会话游标之后的待处理轮次（按窗口分批），不是全量重建；不足 `collect_every` 也可手动触发。
- 手动触发**不受** `auto_collect` 开关限制（用户显式点击），但仍受项目权限与游标约束。
- 运行结果写 `memory_job_runs(trigger='manual')`。

## 6. 过期与保留

### 6.1 过期流转任务（本轮实现）

`runRetention(projectId, { trigger })`：

1. 取 `status='active' AND expires_at IS NOT NULL AND expires_at <= now`；
2. 按策略处理：
   - `自动归档` → `status='archived'`，事件 `expired`；
   - `自动删除` → `status='deleted', deleted_at=now`，事件 `expired`；
   - `仅提醒` → **不改状态**（列表派生为「即将过期」），不重复写事件；
3. 更新 `memory_settings.last_retention_at`；
4. 有变更或报错时写一条 `memory_job_runs(kind='retention')`；无变更不写，避免噪音。

触发点：

- 进程启动后延迟 30s（等种子项目就绪）扫一轮；
- `setInterval` 每小时扫一轮；
- `PUT memory-settings` 保存后立即扫当前项目。

并发保护：进程内 `Set<projectId>`，同一项目不并行跑。

### 6.2 与「清理过期」的差别

| | 到期流转 | 清理过期按钮 |
|---|---|---|
| 触发 | 时间到（`expires_at <= now`） | 用户点击 |
| 范围 | 已过期 | 已过期 + 未来 7 天内 |
| 动作 | 按策略归档 / 删除 / 不动 | 一律归档 |
| 权限 | 系统 | 任意项目成员 |

## 7. 去重

- 规范化：trim → 连续空白压成一个空格 → ASCII 转小写；`sha256` 十六进制即 `dedupe_hash`。
- 手动添加：同项目未删除的相同 hash → 409，返回已有条目。
- 自动收集（本轮）：hash 命中则跳过；同一批输出里的重复也跳过；查询**包含已删除行**——用户删掉的内容不再被自动收集。
- 向量去重（下一轮）：同项目 `cosine >= 0.92` 视为重复，只更新 `last_used_at`。
- 向量能力：把 `server/kb.js` 的 `embedTexts / normalize / toBuffer / fromBuffer / cosine` 抽到 `server/embeddings.js`，`kb.js` 与 `memory.js` 共用。本轮写入即生成向量（手动单条、收集批量），失败只影响召回路径，不影响写入；向量去重下一轮做。

## 8. 自动收集（每 N 轮，本轮实现）

### 8.1 为什么按轮次阈值

- 每轮收集：一段 10 条消息的对话 = 10 次模型调用，且后一次重复看前面的转录；
- 固定时间收集：要等时间点，还得处理时区、停机补跑、用户不知道何时生效；
- **每 N 轮收集**：默认 N=5，10 条消息只需 2 次调用；不需要定时器，记忆最多延迟 N 轮出现。

`collect_every` 默认 5，可配 1–50。设为 1 等价于每轮收集，不推荐。

### 8.2 触发条件

`server/runner.js` 的 `child.on('close')` 中 `status === 'done'` 之后异步执行，**不阻塞轮次结束**：

```js
if (status === 'done') {
  void maybeCollectIfDue({ agent, session, turn }).catch((err) => {
    console.error('[memory] collect failed', err?.message || err)
  })
}
```

同时满足才执行：

1. 会话有 `projectId`，项目 `auto_collect = 1`；
2. 会话有可用的 Agent 运行时（否则记 `skipped`）；
3. 该会话**待处理轮次数 ≥ `collect_every`**：
   `COUNT(turns WHERE session_id=? AND status='done' AND seq > memory_collect_cursor)`；
4. 进程内 `Set<sessionId>` 没有正在跑的收集任务（有则直接返回，下一轮完成时会再次判断）。

不要求队列为空：连续发 5 条消息时，第 5 条完成后就收集这 5 轮；第 6–10 条继续累计。

手动：`POST /api/projects/:id/memories/collect`（§5.10），不要求达到阈值，处理所有待处理轮次。

### 8.3 游标与窗口

- `sessions.memory_collect_cursor` = 该会话已处理到的最大 `turn.seq`（§4.6）。
- 一次触发只取 `status='done'` 且 `seq > cursor` 的轮次，按 `seq` 升序，最多 `collect_every` 轮，且累计不超过 **12k 字符**。
- 写入成功后游标推进到本批最后一轮；剩余待处理内容等下一次触发或手动收集，**不丢**。
- 若一次触发后仍 ≥ `collect_every`（例如积压），不在本次循环里继续打模型；等下一次轮次完成或手动触发，避免突发调用。
- 首次创建 `memory_settings` 或 `auto_collect` 由关变开时，把所有会话游标置为当前最大 `seq`：**不回灌历史**。

### 8.4 转录组装

```js
const turns = listTurns(session.id)
  .filter((t) => t.status === 'done' && t.seq > cursor)
  .slice(0, collectEvery) // 且累计 ≤ 12k 字符
const finals = listFinalsForTurns(turns.map((t) => t.id))
const transcript = turns
  .map((t) => `用户：${t.userContent}\n助手：${finals.get(t.id)?.text ?? ''}`)
  .join('\n\n')
```

- 只取 `done` 轮次，避免把失败 / 取消的中间态当成事实。
- 窗口不足 200 字符：游标推进，跳过，不调用模型。

### 8.5 模型调用

使用**项目 Agent 的运行时**，不新增配置：

```js
const runtime = agent.runtimeId ? getRuntime(agent.runtimeId) : null
const key = runtime ? runtimeKey(runtime.id) : ''
if (!runtime || !runtime.baseUrl || !agent.model || !key) {
  // 记一条 skipped 的 job run，直接返回
}
```

- OpenAI 兼容 `POST {base}/chat/completions`（base 不以 `/v1` 结尾时先试 `{base}`、404 再试 `{base}/v1`，与 `models.js` 一致）；
- `{ model: agent.model, messages, temperature: 0, max_tokens: 800 }`，非流式，30s 超时；
- 不依赖 `response_format`，兼容不支持该参数的网关。

### 8.6 抽取 Prompt

System：

```
你是项目记忆抽取器。从对话中提取值得长期保留、未来仍然有用的项目事实。
只输出 JSON：{"memories":[{"content":"...","importance":0.0}]}

规则：
1. 每条是一句独立、自包含的事实，不超过 200 字；
2. 只保留：代码规范、架构决策、接口/数据约定、第三方坑、业务规则、用户明确偏好；
3. 忽略：寒暄、临时调试、一次性命令、未确认的猜测；
4. 绝不记录密钥、密码、token、个人隐私信息；
5. 最多 5 条；没有值得保留的内容返回 {"memories":[]}。
```

User：

```
项目：<name>
项目描述：<description || "无">
项目记忆收集规则：<collectRules || "无，按通用规则">
对话：
<transcript>
```

### 8.7 校验与写入

- 去掉 ```json 围栏后 `JSON.parse`；必须是 `{ memories: [...] }`，否则按失败处理。
- 最多取 5 条；`content` trim 后 1–200 字；`importance` 夹到 0–1，缺省 0.5。
- 规范化文本 → `sha256`；同项目已存在（**含已删除**，尊重用户删除）或本批重复则跳过。
- 对本批通过去重的内容做一次**批量嵌入**（单次请求，10s 超时）；失败则本批不带向量，召回走关键词降级。
- 批量事务写入：
  - `source='会话沉淀'`、`source_session_id`、`source_turn_id`、`created_by=''`；
  - `expires_at` 按当前保留策略（`permanent` → NULL，否则 `created_at + retention_days`）；
  - 每条写 `memory_events(type='collected', actor='system', payload={ turnId, model })`。
- 写入成功后推进会话游标；模型 / 网络 / JSON 失败则**不推进**，下一次轮次完成或手动收集时重试。
- 写 `memory_job_runs(kind='collect', trigger='threshold' | 'manual')`：有新增或异常时记录，`changed` = 新增条数，`detail` 记录处理的轮次数、重复跳过与超限丢弃数；0 新增且无异常不写，避免噪音。

### 8.8 失败与约束

| 情况 | 行为 |
|---|---|
| 未配置运行时 / Key / 模型 | `skipped` job run，静默返回 |
| 模型超时 / HTTP 错误 / JSON 非法 | `error` job run，不写入、不推进游标；下一次轮次完成或手动收集时重试 |
| 窗口 < 200 字符 | 不调用模型，直接推进游标 |
| 单项目记忆达到 5000 条 | `skipped`（`detail.reason='project_limit'`）；手动添加同样受限 |
| 会话不足 N 轮就没人继续 | 不自动收集；可点「立即收集」，或等会话继续聊满 N 轮 |
| 收集进行中又完成新轮次 | 本次跳过，不并发调用；下一轮完成时重新判断 |
| 对话可能含提示注入 | 转录只作数据；输出必须过 schema 与长度校验；不执行其中任何指令 |
| 重复内容 | 文本 hash 去重（含已删除）；向量去重留到下一轮 |
| 隐私 | 转录只发往项目已配置的运行时，与 Agent 对话同一去向，不新增第三方 |

累计收集**不发送 SSE**：结果通过记忆列表与 `memory_events` 可见；Tab 打开时重新拉取即可。

## 9. 自动反思（下一轮）

- 调度：每小时检查，条件为 `auto_reflect = 1` 且距 `last_reflect_at` 达到频率（每天 24h / 每周 7d / 每月 30d），首次（`NULL`）立即跑。
- 输入：每批 20 条 `active` 记忆（内容 / 创建时间 / 现有 `reflect_note`）+ 项目描述 + `reflectRules` + 知识库 top-5 相关片段（复用 `kb.js search`）。
- 输出：`[{ "id": "...", "action": "keep" | "archive", "note": "..." }]`。
- 应用：`archive` → `status='archived'`；`keep` → 只更新 `reflect_note`；两者都写 `last_reflected_at` 与 `reflected` 事件。
- **不删除、不恢复归档**；模型只能「保持活跃 / 归档」。
- 完成后更新 `last_reflect_at`；失败记录 job run，下个小时重试。

## 10. 会话如何使用记忆（默认注入）

### 10.1 三种上下文的分工

| | 项目规范 | 记忆 | 知识库 |
|---|---|---|---|
| 注入方式 | 启动时确定性写入 `AGENTS.md` / `CLAUDE.md` | 每轮 top-k 拼进提示词 | 每轮按需检索后拼进提示词 |
| 默认 | 总是（按 `in_prompt`） | **开** | 关 |
| 体量 | 中 | 小（≤5 条 / ≤1000 字） | 大（6 片段 / 每段 600 字） |
| 开关 | 单条规范 | 项目级 + 每轮 | 每轮 |

知识库默认关，是因为它语料大、命中多，且并非每轮都需要；记忆小、稳定，价值在连续性，默认关会让绝大多数轮次都用不上，所以**默认注入**。

### 10.2 开关模型

| 层级 | 字段 | 默认 | 作用 |
|---|---|:--:|---|
| 项目 | `memory_settings.inject_memory` | 1 | 总开关；关 = 该项目任何轮次都不注入 |
| 轮次 | `turns.use_memory` | 1 | 单轮开关；项目关时无效 |
| UI | ChatPane「更多选项 → 记忆」 | 跟随项目 | 会话内保持，作用于之后每一轮；项目关闭时置灰并提示「项目已关闭记忆注入」 |

- `use_memory` 用现有 `ensureColumn('turns', 'use_memory', 'use_memory INTEGER NOT NULL DEFAULT 1')` 迁移。
- 服务端最终判定：`inject = settings.injectMemory && turn.useMemory && projectId`。
- 项目级开关放进「记忆规则」弹窗新增的第 5 项「会话使用」，文案：`每轮对话自动注入相关记忆（默认开启）`。
- `ProjectDetail` 在项目切换时拉一次 `memory-settings`，把 `injectMemory` 传给 `ChatPane` 初始化每轮开关；`MemoryPanel` 保存规则后通过 `onSettingsChange` 回传，避免开关状态与项目设置不一致。
- 两个开关独立于 `autoCollect`：写入与读取互不影响（§4.2）。

### 10.3 注入流程（`runner.startTurn`）

```js
const settings = getMemorySettings(session.projectId)
const inject = settings?.injectMemory && turn.useMemory && session.projectId
let memoryHits = []
if (inject) {
  try { memoryHits = await recallMemories(session.projectId, content, { topK: 5, sessionId: session.id }) }
  catch (err) { console.error('[memory] recall failed', err?.message || err) }
}
// 知识库逻辑保持不变
const prompt = buildTurnPrompt(content, { memoryHits, kbHits })
```

- 先查记忆条数：为 0 直接跳过，不产生嵌入调用。
- 记忆与知识库同时开启：提示词顺序为 **记忆段 → 知识库段 → 用户问题**。
- 把现有 `buildKnowledgePrompt` 拆成 `buildMemoryBlock / buildKnowledgeBlock`，新增 `buildTurnPrompt` 组合；原函数保留为薄封装，避免破坏已有单测。

### 10.4 提示词结构

```
以下是项目记忆，按与当前问题的相关度排序。
记忆可能过时或不完整；如与当前代码、项目知识库或用户本轮说明冲突，
以当前内容为准，不要仅凭记忆下结论。

[记忆 1] 组件拆分应遵循展示/容器分离（活跃）
[记忆 2] 支付回调需幂等处理（活跃）

（知识库片段段，若本轮开启）

用户问题：
...
```

- 每条截断 200 字，最多 5 条，总量 ≤ 1000 字；超出时丢弃低分项。
- 不注入 `archived / deleted` 或已过期记忆。
- 不往系统提示词里写记忆，避免失效；拼在用户消息前部，与知识库同一层。

### 10.5 Top-k 怎么选

`recallMemories(projectId, query, { topK = 5, sessionId })` 不是「取最近 5 条」，而是 **过滤 → 打分 → 相对截断 → 去重 → 预算截断**。k 是上限，不是目标。

**1. Query**

- 默认用本轮用户输入，trim 后 ≤500 字；
- 输入过短（< 8 字，如「继续」「然后呢」）时，通过 `sessionId` 取上一条用户消息拼在前面，保证指代与主题不丢；没有上一条则按短 query 处理。

**2. 候选池**

```sql
SELECT * FROM memories
WHERE project_id = ? AND status = 'active'
  AND (expires_at IS NULL OR expires_at > ?)
ORDER BY created_at DESC
LIMIT 2000
```

只取 `active` 且未过期；归档 / 删除 / 过期不参与。上限 2000 条，避免极端项目每轮全表扫描。

**3. 打分**

有嵌入（`embedding_model` 与当前配置一致，且向量维度相同）：

```
cos = cosine(queryEmbedding, memory.embedding)
门槛：cos ≥ 0.55
score = 0.65 * cos + 0.20 * recency + 0.15 * importance
```

无嵌入 / 嵌入不可用：

```
terms = query 的 CJK 2-gram + 英文词（去掉单字与常见停用词）
kw = 命中的不同词数 / query 词数
门槛：kw > 0（至少命中一个词）
score = 0.60 * kw + 0.25 * recency + 0.15 * importance
```

- `recency = exp(-daysSinceCreated / 90)`（90 天时间常数）；
- `0.55` 是起始值（知识库用 `0.6`，记忆更短所以略放宽），上线后用评估集调；
- 嵌入失败自动降级到关键词，不重试、不阻塞。

**4. 相对截断（k 不固定）**

- 按 `score` 降序；
- 只保留 `score ≥ 0.75 × 最高分` 的条目；
- 再取前 5 条。

效果：只有 1 条明显相关时就只注入 1 条，不为凑满 5 条塞入弱相关项；实际每轮通常 0–3 条。

**5. 去重与预算**

- 近重复合并：与已选条目 `cosine ≥ 0.92`（无嵌入时用 2-gram Jaccard ≥ 0.85）则跳过；
- 每条截断 200 字，最多 5 条，总量 ≤1000 字；
- 一条都不过门槛就注入 0 条——**不做「补足到 N 条」**，避免默认注入变成每轮塞背景噪音。

**6. 使用回写**

- 只对最终选中的条目更新 `last_used_at`（≥1h 节流一次）；
- 选中的条目通过 `memory_recall` 事件回报，前端可核对本轮到底用了什么。

**为什么上限是 5**：5 条 × 200 字 ≈ 1k 字符，约为知识库注入预算的 1/4；更多条目通常只是稀释指令、增加成本。实际注入条数由相关度决定，不由 k 决定。

### 10.6 SSE 事件与 UI

命中后发送：

```json
{
  "type": "memory_recall",
  "query": "支付回调怎么处理",
  "count": 2,
  "memories": [
    { "id": "mem_x", "content": "支付回调需幂等处理", "score": 0.82, "lifecycle": "活跃" }
  ]
}
```

- 仅在 `count > 0` 时发送；0 条不发，避免默认开启后每轮刷一条空记录。
- 召回失败只记日志，不额外发事件，本轮按无记忆继续。
- 前端：`runtimeApi.HarnessEvent` 增加 `memory_recall`；`harnessLines.ts` 增加 case，渲染为 CLI 轨迹里的一行：
  `⌕ 记忆注入：使用 2 条` + 每条截断 60 字。
- 与 `kb_search` 一样显示在格 3 的 Agent CLI 轨迹，不改聊天消息流。

### 10.7 成本与失败

- 每轮最多一次嵌入调用；记忆为 0 或项目关闭时零成本。
- 预算：最多 5 条 × 200 字 ≈ 1k 字符，实际通常 0–3 条，明显小于知识库的 6 × 600。
- 任何异常都降级为「无记忆」，绝不阻塞轮次。

### 10.8 隐私

记忆是项目级共享：成员 A 手动添加的记忆，成员 B 的轮次也会被注入。这是项目记忆的预期语义，UI 上已有「收集于」与来源展示；跨项目不共享。

## 13. 验收标准

1. 刷新页面后，手动添加的记忆与规则仍在（落库）；
2. 添加完全相同的内容返回 409，列表不出现重复行；
3. 成员可删自己的手动记忆；删系统收集或他人记忆返回 403；项目负责人可删全部；
4. 「清理过期」把全部「即将过期」变「已归档」，按钮随之禁用，`memory_events` 有 `archived` 记录；
5. 把保留天数 90 改成 30 后，未归档条目的 `remainDays / expiresAt` 立即变化；
6. 过期流转：三种策略分别为「归档 / 删除后不再出现在列表 / 状态不变但显示即将过期」；
7. 规则保存校验：天数越界、频率非法返回 400，弹窗内可见错误；
8. 默认注入：任意一轮发送后，CLI 轨迹出现「记忆注入：使用 N 条」；关闭本轮「记忆」开关后不再出现；
9. 项目级关闭「会话使用」后，所有轮次都不注入，ChatPane 开关置灰并提示「项目已关闭记忆注入」；
10. 记忆为空时零嵌入调用、无 SSE 事件；召回异常时本轮照常回答；
11. 记忆与知识库同时开启时，提示词同时包含两段且顺序为 记忆 → 知识库 → 用户问题；
12. 召回上限：任意一轮最多 5 条、每条 ≤200 字、总量 ≤1000 字；只有 1 条强相关时只注入 1 条，不为凑数塞入弱相关项；
13. 短输入（如「继续」）会拼接上一条用户消息作为 query；一条都不过门槛时注入 0 条，且不产生 `memory_recall` 事件；
14. 配置嵌入后，新增 / 收集的记忆带 `embedding`，召回走向量路径；未配置或嵌入失败时走关键词路径且不报错；
15. 每 N 轮收集：默认 5，完成第 5 个 `done` 轮次后自动触发一次，列表出现来源为「会话沉淀」的条目；第 6 轮完成不会重复处理前 5 轮；
16. 待处理不足 5 轮时不触发；点「立即收集」可补收，异步返回 202；
17. 开启自动收集不会回灌历史轮次；关闭后不再自动触发；
18. 收集进行中又完成新轮次不并发调用；失败后下一次轮次完成或手动收集会重试未推进的轮次；
19. 未配置运行时、模型超时或返回非法 JSON 时，不写入记忆且不推进游标；窗口 <200 字符只推进游标、不调模型；
20. 保留策略 UI：三张卡片可切换、选中态清晰；开启「永久保留」后整组禁用并显示永久保留结论；底部结论句随选择实时变化；
21. 非项目成员访问任意记忆接口返回 403；
22. `npm run build` 通过，知识库 / 文档 / 会话功能无回归。

## 14. 风险与偏差

### 14.1 与总体方案的偏差

| 项 | 方案 | 本设计 | 原因 |
|---|---|---|---|
| 数据库 | Postgres + pgvector | SQLite + BLOB 向量 | 与现有 `server/` 一致，不引入第二套存储 |
| `expiring` 状态 | 落库 | 派生 | 时间派生值落库会随时钟变脏 |
| `auto_reflect` 默认 | 开 | 关 | LLM 会自动归档数据，默认关更稳（待确认） |
| 记忆注入默认 | 未定义 | **项目级 + 每轮都默认开** | 2026-10-28 已确认：记忆小而稳定，默认关等于绝大多数轮次不用 |
| 自动收集触发 | 会话结束 | **每 N 轮 + 手动** | 每轮调用成本高且重复；按会话累计 N 个 `done` 轮次触发，不需要定时器或会话关闭事件 |
| 自动收集范围 | P5 | **纳入本轮** | 2026-10-28 已确认；它是记忆真正产生价值的入口 |
| `MemorySettings` 默认来源 | SQL default true | 与前端 `createEmptyProject` 对齐 | 新项目行为一致 |

### 14.2 风险

| 风险 | 应对 |
|---|---|
| SQLite 无向量索引，召回是 O(n) | 单项目记忆量按千级设计；超过阈值再考虑 FTS / 预过滤 |
| 默认注入让坏记忆污染每一轮回答 | 相关度阈值 + 上限 5 条 + 每条 200 字 + 相对截断 + 提示词免责声明 + SSE 可见 + 反思归档；后续可加置顶 / 手动排除 |
| 每轮嵌入调用增加延迟 | 记忆为 0 或项目关闭时短路；无嵌入时走关键词 + 时间降级；失败不阻塞轮次 |
| 记忆是项目共享的，可能注入他人添加的内容 | 项目级共享是预期语义；UI 展示来源与收集人，跨项目隔离 |
| 时间字符串比较依赖统一格式 | 新表所有时间统一 `toISOString()`，不复用其他表的本地格式 |
| 软删 + 部分唯一索引的边界 | deleted 行不参与唯一约束；恢复功能本轮不做 |
| LLM 失败阻塞会话 | 收集/反思全部 fire-and-forget，错误只记 job run |
| 自动收集编造事实或记录敏感信息 | Prompt 明确排除密钥 / 隐私；最多 5 条、每条 200 字；来源标「会话沉淀」；hash 去重 + 用户可删；后续可加「收集后待确认」 |
| 会话不足 N 轮，记忆迟迟不出现 | UI 明示阈值；提供「立即收集」；会话继续聊满 N 轮会自动触发 |
| 连续对话集中触发 | 待处理 ≥ N 才触发；每次最多一窗（N 轮 / 12k 字符）；同一会话不并发；剩余等下一次 |
| 收集成本 | 每 N 轮一次模型调用；窗口 12k 字符；hash 去重；未配置运行时直接跳过 |
| 写入时嵌入超时拖慢添加 | 手动添加 5s、收集批量 10s；失败仍写入文本，召回降级关键词，不影响写入成功 |
| 更换嵌入模型后旧记忆向量失效 | 只使用 `embedding_model` 与当前配置一致的向量，其余走关键词；旧向量回填放下一轮 |
| 提示注入 | 转录与文档只作数据；模型输出严格 schema 校验；不执行 |
| 记忆增长 | 保留策略 + 反思归档 + 每项目软上限（建议 5000 条，超出拒新增并提示） |
