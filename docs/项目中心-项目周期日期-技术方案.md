# 「项目周期日期（开始/截止）」功能 - 技术方案

> 创建日期：2026-08-28
> 更新日期：2026-08-28

## 1. 背景与目标

项目中心目前每个项目只有 `createdAt`（创建日期），缺少项目周期信息。需求：

1. 每个项目增加 **开始日期（startDate）** 与 **截止日期（endDate）**；
2. 在 **项目卡片**（项目中心列表页）与 **项目详情页头部** 展示周期；
3. 进行中项目可直观看到 **剩余天数 / 是否逾期**，辅助排期感知。

本工程为纯前端 Mock，日期仅存于本地数据，不做编辑入口（项目中心暂无新建/编辑项目功能，本期只做展示，字段预留后续编辑用）。

## 2. 现状分析

| 项 | 现状 |
|---|---|
| 数据 | `Project` 接口（`src/data/projects.ts`）：`id / name / description / status / createdAt / members / agents / autoJobs / knowledge / specs`，无周期字段 |
| 卡片 | `ProjectCard.tsx`：名称+状态徽标 / 描述一行 / 底部头像组+成员统计，无日期 |
| 详情页 | `ProjectDetail.tsx` 头部：`detail-desc` 一行「描述 · 创建于 2026-07-02」 |
| 日期格式 | `createdAt` 用 `YYYY-MM-DD`；记忆/文档等用 `MM-DD` 短格式 |
| 状态 | `'进行中' | '已完成' | '规划中'`，徽标色：success / info / neutral |

## 3. 数据层设计

### 3.1 类型（`src/data/projects.ts`）

```ts
export interface Project {
  id: string
  name: string
  description: string
  status: '进行中' | '已完成' | '规划中'
  createdAt: string
  /** 项目周期：开始日期（YYYY-MM-DD） */
  startDate: string
  /** 项目周期：截止日期（YYYY-MM-DD） */
  endDate: string
  // ...其余不变
}
```

### 3.2 Mock 数据（3 个项目）

| 项目 | 状态 | startDate | endDate | 设计意图 |
|---|---|---|---|---|
| loomweb | 进行中 | 2026-07-02 | 2026-09-30 | 正常进行中，剩 33 天 |
| yigou-app | 进行中 | 2026-05-18 | 2026-08-31 | 临期（剩 3 天），演示「剩 N 天」橙色提示 |
| data-pipeline | 规划中 | 2026-09-01 | 2026-12-31 | 未开始，演示「N 天后启动」 |

> 当前系统日期为 2026-08-28，上述数据可同时覆盖「正常 / 临期 / 未开始」三种展示态；逾期态（endDate 早于今天）无对应 Mock 项目，逻辑仍实现，便于后续数据调整时自然呈现。

## 4. 展示层设计

### 4.1 周期状态推导（新增工具函数，放 `src/data/projects.ts` 或组件内）

```ts
type PeriodState =
  | { kind: 'not-started'; days: number }   // 规划中且今天 < startDate
  | { kind: 'running'; days: number }       // 进行中且今天 ≤ endDate（days = 剩余天数）
  | { kind: 'expiring'; days: number }      // 进行中且剩余 ≤ 7 天
  | { kind: 'overdue'; days: number }       // 今天 > endDate（days = 逾期天数）
  | { kind: 'done' }                        // 已完成，不显示天数
```

- 用 `new Date()` 与 `startDate / endDate` 做当日零点比较，`Math.ceil` 按天取整；
- 状态徽标色：`expiring` → warning（橙）、`overdue` → danger（红）、其余不额外出徽标。

### 4.2 项目卡片（`ProjectCard.tsx` + `ProjectCard.css`）

在描述与底部之间新增一行周期行：

```
┌──────────────────────────────┐
│ 📁 yigou-app          ●进行中 │
│ 翼构移动应用                  │
│ 📅 05-18 ~ 08-31    ⚠ 剩 3 天 │  ← 新增
│ 👤L 👤Z 👤S   3 成员 · 1 ADE  │
└──────────────────────────────┘
```

- 左侧：日历图标 + `MM-DD ~ MM-DD`（同年省略年份；跨年则 `2026-12-01 ~ 2027-03-01` 全格式）；
- 右侧：周期状态小徽标（仅进行中显示）：
  - 剩余 > 7 天 → 不显示（避免噪音）；
  - 剩余 ≤ 7 天 → `剩 3 天`（warning 橙）；
  - 逾期 → `已逾期 5 天`（danger 红）；
  - 规划中未开始 → `34 天后启动`（neutral 灰）；
  - 已完成 → 不显示。
- 样式：12px 灰色文字，与底部 meta 一致，新增 `.project-card-period` 行样式。

### 4.3 项目详情页头部（`ProjectDetail.tsx`）

`detail-desc` 行扩展为：

```
翼构移动应用 · 创建于 2026-05-18 · 周期 2026-05-18 ~ 2026-08-31（剩 3 天）
```

- 详情页空间充足，日期用完整 `YYYY-MM-DD` 格式；
- 括号内天数提示与卡片同规则（逾期红色、临期橙色、未启动灰色、已完成不显示）；
- 不新增行，保持头部紧凑。

### 4.4 复用说明

- 周期状态推导函数导出（`getPeriodState(project)`），卡片与详情页共用，避免两处逻辑漂移；
- 徽标复用现有 `StatusBadge`（已支持 success / info / neutral / warning / danger 色调）；
- 日历图标在 `components/icons/index.tsx` 新增 `CalendarIcon`（1.5px 描边线框风，与现有图标一致）。

## 6. 验证方式

1. `npx tsc --noEmit` 类型检查通过；
2. `npm run build` 构建通过；
3. 页面自查：项目中心三张卡片分别呈现「无徽标（剩 33 天）/ 橙色剩 3 天 / 灰色 34 天后启动」；详情页头部显示完整周期文案；
4. 提交 commit：`feat: 项目增加开始/截止日期（卡片与详情页展示周期与剩余天数）`。

## 7. 边界与取舍

- **不做编辑**：项目中心无新建/编辑入口，本期纯展示；字段命名与格式与 `createdAt` 对齐，后续接表单零成本；
- **不做排序/筛选**：按截止日期排序、临期筛选等属于列表增强，待有诉求再加；
- **逾期不改状态**：endDate 过期不自动把「进行中」改成其他状态（状态是业务字段，由人维护），只做视觉提示。
