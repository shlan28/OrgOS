# 「项目中心-项目规范」每条规范增加「是否加入项目提示词」开关 - 技术方案

> 创建日期：2026-09-14
> 更新日期：2026-09-14（v3：规范列表顶部新增常驻 tips，说明规范会进入提示词）

## 1. 背景与目标

「项目中心 → 项目详情 → 项目规范」面板目前是：搜索 + 规范文档列表 ↔ 预览 ⇄ 编辑 + 新建/删除。

问题：项目规范里的文档不一定都适合作为提示词注入给 ADE（例如 `README.md` 只是项目说明，注入会浪费上下文；`编码规范.md` 才是希望 ADE 每次都遵守的约束）。目前所有文档要么全量生效、要么没有区分。

本次需求：**每一条项目规范增加一个「是否加入项目提示词」开关**（行右侧纯开关，无行内文案），点击开关时弹出**常驻提示**说明后果，用户手动点击【X】关闭。

## 2. 交互设计

遵循现有 Settings 极简风格，行内开关直接复用通用 `Toggle` 组件（与「自动从会话收集记忆」等开关观感一致）。

### 2.1 列表顶部 tips（v3 新增）

搜索框下方、规范文档分组卡片上方，新增一条**常驻说明 tips**（不可关闭）：

```
│ 🔍 搜索规范文档                                        │
│ ℹ️ 开启「加入提示词」的规范文档，将进入本项目的系统提示   │
│    词，Agent 执行任务时会遵守其中的约定。               │
│ 规范文档（5 份）                                + 新建  │
│ ┌──────────────────────────────────────────────────┐   │
│ │ 📄 README.md                          (●─)      > │   │
```

- **位置**：搜索框与「规范文档」分组之间；
- **样式**：轻量说明条（浅蓝信息底 `--status-info-bg` + 12px 说明字 + ℹ️ 图标），与 Settings 极简风格一致，不使用强警示色；
- **文案**：`开启「加入提示词」的规范文档，将进入本项目的系统提示词，Agent 执行任务时会遵守其中的约定。`
- **常驻**：始终展示（这是机制说明，不是操作反馈，不需要关闭按钮）。

### 2.2 列表行结构（v2 改动点，保持）

```
┌──────────────────────────────────────────────────────────────┐
│ 📄 README.md                                    (●─)        > │
│    项目说明 · 更新于 08-24                                      │
├──────────────────────────────────────────────────────────────┤
│ 📄 AGENTS.md                                     (─●)        │
│    智能体协作约定 · 更新于 08-22                                 │
└──────────────────────────────────────────────────────────────┘
                 ↑ 点击开关后弹出（toast 常驻，不自动消失）
        ┌─────────────────────────────────────────┐
        │ ✓ 「README.md」已加入系统提示词            │
        │   Agent 执行任务时将遵守该文档中的约定。    │
        │                                    [X]  │
        └─────────────────────────────────────────┘
```

- **开关位置**：行内**最右侧**（箭头之前），**纯开关，无标签、无小字**（v1 的「是否加入项目提示词」「打开则加入系统提示词」文案移除）；每条文档独立开关；
- **开关 title 悬停提示**：开启态「已加入系统提示词 · 点击移出」/ 关闭态「未加入系统提示词 · 点击加入」；
- **点击行为**：整行仍可点击进入预览（保持现状）；开关区域 `stopPropagation`，点击开关不触发行跳转；
- **行高**：右侧只剩开关单行，行高回到原始紧凑形态，与改造前一致。

### 2.2 点击开关弹出常驻提示（toast）

点击开关（无论开 → 关还是关 → 开）都弹出一个 **toast 提示**：

- **位置**：面板右上（主内容区顶部），与现有通知体系风格一致（白底圆角卡片 + 阴影）；
- **内容**：
  - 标题行：状态图标（✓ 绿 / ○ 灰）+ 文案（带文档名）：
    - 开启：`「{文档名}」已加入系统提示词`
    - 关闭：`「{文档名}」已移出系统提示词`
  - 说明行：
    - 开启：`Agent 执行任务时会遵守该文档中的约定。`
    - 关闭：`Agent 执行任务时不再受该文档约束。`
  - 右上角【X】关闭按钮；
- **常驻不自动消失**：无超时逻辑，必须用户手动点击【X】（或再次点击开关切换时更新文案，不叠加多个 toast——同面板同时只有一个提示）；
- **切换另一条文档开关**：toast 内容替换为最新文档的最新状态（单例更新，不堆叠）；
- **关闭方式**：仅【X】按钮；点遮罩/行/其他区域不关闭（保持常驻语义）。

### 2.3 预览页与编辑页

- 预览页头部工具栏保留状态徽标（`已加入项目提示词` / `未加入项目提示词`），让用户在二级页面也能看到状态；徽标仅展示，开关操作仍集中在列表行（避免双入口状态不同步的复杂度）。

### 2.4 新建文档

- 新建文档弹窗（FormModal）保留「是否加入项目提示词」开关字段（带标签与小字说明，弹窗内是表单语境，文案保留合理），默认**开启**；
- 创建后列表行开关与弹窗选择一致。

## 3. 数据模型改动（`src/data/projects.ts`）

```ts
export interface SpecDoc {
  id: string
  name: string
  note: string
  updatedAt: string
  markdown: string
  content: { heading: string; body: string }[]
  /** 是否加入项目提示词：开启后该规范注入本项目 ADE 的项目提示词 */
  inPrompt: boolean        // ← 新增
}
```

| loomweb | AGENTS.md | `true` |
| loomweb | 编码规范.md | `true` |
| loomweb | Git 提交规范.md | `true` |

## 4. 组件改动

### 4.1 `SpecsPanel.tsx`

- 新增 toast state：`promptToast: { docName: string; on: boolean } | null`（单例，null = 不显示）；
- `handleTogglePrompt(id, next)`：翻转 `inPrompt` 的同时 `setPromptToast({ docName, on: next })`——切换文档开关时提示内容**替换**（不堆叠）；
- 列表行开关区（v2）：仅 `Toggle`（带 title 悬停提示），**移除标签与小字**；`stopPropagation` 保持；
- toast 渲染（列表视图内，`position: fixed` 挂主内容区右上）：
  - 状态图标（✓ 绿圆 / ○ 灰圆）+ 标题（含文档名）+ 说明行 + 【X】按钮；
  - 【X】点击 `setPromptToast(null)`；**无自动消失定时器**；
- 新建弹窗、预览徽标、其余交互不变（v1 已有）。

## 5. 不改动的部分

- 搜索过滤逻辑、预览/编辑/保存/删除、文档列表行点击进入预览的交互不变；
- `Toggle`、`SettingsRow`、`FormModal` 通用组件不改动；
- 新建弹窗的开关字段（含标签与小字说明）保留——弹窗是表单语境，保留文案合理；
- 其他面板（知识记忆/自动化/安全审查等）不涉及。

## 6. 实施步骤

1. `SpecsPanel.tsx`：移除列表行内标签/小字，新增 `promptToast` state + 常驻 toast 渲染 + 【X】关闭；
2. `SpecsPanel.css`：行内开关区样式简化 + 新增 toast 样式（保留弹窗小字与预览徽标样式）；
3. `README.md`：项目规范段描述更新为 v2 交互；
4. `npm run build` 验证构建通过；
5. 浏览器自检：开关点击弹 toast、toast 常驻不消失、X 关闭、切换其他文档 toast 内容替换、开关点击不触发行跳转、行高恢复紧凑；
6. 提交 git commit。

## 7. 验收标准

1. 规范列表顶部（搜索框下方）出现常驻 tips：`开启「加入提示词」的规范文档，将进入本项目的系统提示词，Agent 执行任务时会遵守其中的约定。`（浅蓝信息底 + ℹ️ 图标，不可关闭）；
2. 每条规范文档行右侧只有开关（无「是否加入项目提示词」标签、无「打开则加入系统提示词」小字），行高恢复紧凑；
3. 点击开关（开→关、关→开）立即弹出 toast：开启文案 = `「{文档名}」已加入系统提示词` + `Agent 执行任务时会遵守该文档中的约定。`；关闭文案 = `「{文档名}」已移出系统提示词` + `Agent 执行任务时不再受该文档约束。`；
4. toast **不会自动消失**（等待数秒仍在），必须点击【X】才关闭；
5. 切换另一条文档的开关时，toast 内容更新为最新状态（同一时刻只有一个 toast）；
6. 点击开关本身不触发进入文档预览；
7. 新建弹窗开关、预览徽标、Mock 数据设定保持 v1 行为；
8. 视觉与现有风格一致，构建通过，代码提交 commit。

## 8. 风险与说明

- 纯 Mock：`inPrompt` 不真实注入任何提示词，仅前端状态演示，刷新即还原；
- toast 为面板内单例（fixed 定位），切换文档开关时替换内容，不做多 toast 堆叠与历史；
- toast 不监听 Escape/遮罩点击（仅【X】关闭），保持"必须手动关闭"的需求语义；面板卸载（切换 tab/项目）时随组件销毁消失，属合理行为。
