# 「项目中心」功能 - 技术方案

> 创建日期：2026-08-26
> 更新日期：2026-09-03（知识记忆：团队知识库更名为项目知识库）
## 1. 背景与目标

在现有 `loom-ui-mock`（Loom AI 编程助手界面模拟）基础上，新增「项目中心」功能：

1. 左侧边栏「定制」下方新增菜单项 **项目中心**；
2. 点击「项目中心」，右侧主区展示 **多个项目卡片**（卡片只展示项目基本信息与成员概况，**不展示任务**）；
3. 点击项目卡片进入 **项目详情页**，详情页采用 **左侧导航列表 + 右侧内容面板** 的 Settings 式布局，导航共 9 项（**项目规范置顶**）：
   - 本期实现详情的 5 项：项目规范（各种 .md）/ 项目成员 / 项目ADE / 知识记忆 / 自动化任务
   - **保留导航入口、本期不做详情的 4 项**：代码 / 安全审查 / 测试 / 能效看板 —— 点击后右侧展示统一的「敬请期待」占位面板（见 4.3 占位面板设计）
4. 各模块内容采用 **系统设置页（Settings）式极简风格**：分组卡片 + 行式布局 + 细分割线，大留白、无多余装饰；
5. 视觉与交互 **完全遵循当前整体风格**（浅色 macOS 风、现有色彩变量、细线框图标、无第三方 UI 库）。

本工程为纯前端 Mock（无后端），所有项目/任务数据使用静态 TypeScript Mock 数据。

## 3. 总体设计

### 3.1 视图状态机（不引入路由库，useState 驱动）

```
type View =
  | { type: 'home' }                                  // 现有对话首页
  | { type: 'project-center' }                        // 项目中心列表
  | { type: 'project-detail'; projectId: string }     // 项目详情
```

- `App.tsx` 持有 `view` 状态，主区按 `view` 渲染对应页面；标题栏、侧边栏保持不动。
- 侧边栏「项目中心」点击 → `project-center`；选中项高亮（新增 `.menu-item.active` 样式）。
- 项目卡片点击 → `project-detail`；详情页左上角「← 返回项目中心」回到列表。
- 进入 `project-center` / `project-detail` 时，主区右上角原有的预览/面板图标按钮保留（不影响）。

### 3.2 页面流转

```
侧边栏[项目中心] ──点击──▶ 项目中心列表（多项目卡片，仅基本信息）
                                │ 点击项目卡片
                                ▼
                项目详情（左侧导航列表 + 右侧 Settings 式内容面板）
                                │ 「← 返回」
                                ▼
                          项目中心列表
```

**整体框架**

- 头部：返回按钮（细线箭头图标 + 灰色文字，hover 变深）、项目图标 + 名称（22px 加粗）+ 状态徽标 + 简介/创建时间（12.5px 灰）。
- 左侧导航列表（替代原顶部 Tab 栏）：宽约 180px，**9 个导航项**纵向排列（**项目规范置顶并默认选中**），每行 = 线框图标 + 名称（13.5px）；
  - 选中态：浅灰圆角底 `rgba(0,0,0,0.06)` + 文字变黑（与 macOS 系统设置左侧列表一致，不用彩色）；
  - hover：更浅的灰底；
  - 导航区与内容面板之间用 `1px solid var(--border)` 竖线分隔；
  - 导航顺序：项目规范 / 代码 / 项目成员 / 项目ADE / 知识记忆 / 自动化任务 / 安全审查 / 测试 / 能效看板。其中 **代码 / 安全审查 / 测试 / 能效看板** 4 项保留入口、本期不做详情，名称后带浅灰小字「敬请期待」，点击后右侧展示占位面板。
- 右侧内容面板：最大宽度 720px，独立滚动；内部全部采用 **Settings 页极简风格**（见下）。

**占位面板设计（代码 / 安全审查 / 测试 / 能效看板 共用）**

- 点击未实现详情的导航项时，右侧面板展示统一的极简占位状态：面板垂直居中，一个灰色线框图标（对应该模块，48px）+ 一行主文案「{模块名} 功能建设中」（15px）+ 一行灰色说明「该模块将在后续版本提供，敬请期待」（12.5px）；
- 占位面板无按钮、无卡片，保持极简；左侧导航选中态正常切换，随时可切回已实现的模块。

**Settings 极简风格规范（所有面板统一）**

1. 内容按「分组（Section）」组织：灰色分组标题（11.5px，同侧边栏 `.section-title`）+ 白色圆角分组卡片（`1px solid var(--border)`、圆角 10px）；
2. 分组卡片内为「行（Row）」：每行高约 44px，行与行之间用 `1px solid #F0F0F0` 细分割线（首尾行不顶边，左右内缩 16px）；
3. 行结构：左侧 = 主文案（13.5px 黑）+ 可选次级说明（12px 灰，位于主文案下方）；右侧 = 值文本（13.5px 灰）/ 状态徽标 / 头像组等轻量控件；
4. 不使用阴影卡片堆叠、不使用彩色背景块，仅状态徽标和状态点带语义色；
5. 控件型元素共三类：启停开关（Settings 式 toggle，自动化任务/记忆自动收集用）、**弹窗表单**（所有新增/导入/添加/申请操作统一用居中弹窗，输入框与下拉均为细边框 32px 高）、行内编辑区（点击行展开，附保存/取消与红字删除）。其余均为展示型内容。

#### 模块设计：定位、内容与交互逻辑

**设计原则**：项目详情页回答「这个项目是什么、由谁做、怎么运转」。导航共 9 项，其中 **5 项本期实现详情**，按三条线划分，**每个 tab 只回答一个问题，彼此不重叠**：

- **项目资产（静态）**：项目规范（规则）→ 知识记忆（沉淀的经验）
- **项目参与者**：项目成员（人）→ 项目ADE（AI 队友）
- **项目运转**：自动化任务（机器自动做的事）

其余 4 项（代码 / 安全审查 / 测试 / 能效看板）**保留导航入口，本期展示占位面板**，后续迭代实现。

| # | 导航项 | 回答的问题 | 交互级别 |
|---|---|---|---|
| 1 | 项目规范（置顶、默认选中） | 这个项目要遵守什么规则？ | 二级视图（列表 → 预览 ⇄ 编辑）+ 新建 / 删除文档 |
| 2 | 代码 | 这个项目的代码现在什么样？ | **占位面板（本期不做详情）** |
| 3 | 项目成员 | 有哪些人在做这个项目？ | 添加成员 + 行内编辑（角色/权限）+ 移除 |
| 4 | 项目ADE | 有哪些 AI 队友接入、正在干什么？ | 申请专属ADE + 行内编辑 + 移除 |
| 5 | 知识记忆 | 这个项目沉淀了哪些知识与记忆？ | 外部导入 + 索引管理 + 自动收集开关 + 记忆生命周期管理 |
| 6 | 自动化任务 | 这个项目让机器自动做什么？ | 启停开关 + 新建 / 编辑 / 删除任务 |
| 7 | 安全审查 | 项目的安全风险状况？ | **占位面板（本期不做详情）** |
| 8 | 测试 | 项目的质量状况？ | **占位面板（本期不做详情）** |
| 9 | 能效看板 | 项目的研发效能如何？ | **占位面板（本期不做详情）** |

> **统一操作范式（所有已实现 tab 一致）**：
> - **新增**：分组标题右侧放「+ 新建 / + 导入 / + 添加 / + 申请专属ADE / + 手动添加」文字按钮（灰字，hover 变黑）；点击后弹出**居中弹窗**（见下「弹窗规范」），表单字段竖向排列，底部「取消」文字按钮 + 黑底「确认」按钮；
> - **编辑**：点击内容行在行下方**展开行内编辑区**（同组同时只展开一条），可修改字段并「保存 / 取消」，编辑区内附红色文字「删除/移除」按钮；
> - 所有写操作均为本地 state（Mock 不持久化）。
>
> **弹窗规范（新增类操作统一）**：
> - 遮罩层：`rgba(0,0,0,0.25)` 全覆盖，点击遮罩关闭弹窗；
> - 弹窗容器：白底、圆角 12px、宽 380px、`box-shadow: 0 12px 40px rgba(0,0,0,0.18)`、垂直水平居中；
> - 标题栏：15px 加粗标题（如「新建文档」「导入文档」「添加成员」「申请专属ADE」「添加记忆」「新建任务」）+ 右侧关闭 ×（灰色，hover 变黑）；
> - 表单区：字段竖向排列，每个字段 = 12px 灰色标签 + 输入框/下拉（高 32px、细边框、圆角 8px、间距 12px）；
> - 底部操作栏：右对齐，「取消」文字按钮 + 黑底「确认」按钮（必填项为空时禁用灰态）；
> - 动画：弹窗 `opacity + scale(0.96→1)` 150ms ease-out 入场。

**① 项目规范 —— 项目的"规则书"（可查看 + 可编辑 + 可新建）**

- **定位**：成员与 ADE 开展工作的依据（各种 .md）。置顶且默认选中，因为进入一个项目第一眼应看规则。规范需要随项目演进持续修订，因此**必须提供编辑能力**。
- **内容**：顶部为**搜索框**（见下），下方分组「规范文档（N 份）」（分组标题右侧 = 「+ 新建」文字按钮），每行 = 文件图标 + 文件名（主）+ 一句话说明 · 更新时间（次级）｜右侧 = 查看箭头。Mock 文件：README.md / AGENTS.md / 编码规范.md / Git 提交规范.md / 评审规范.md。
- **列表布局与大量文档的处理**：文档列表是面板的唯一内容，随右侧内容面板整体滚动，竖向排列不受数量限制；为应对文档很多的情况，列表顶部固定一个搜索框（高 32px、`1px solid var(--border)`、圆角 8px、左侧放大镜图标、占位「搜索规范文档」），按文件名/说明**实时过滤**列表行，分组标题的数量随之更新（如「规范文档（2 份）」）；无匹配时显示空状态提示「没有匹配的文档」（沿用 `.empty-hint` 灰字风格）。搜索框只在列表视图出现，进入预览/编辑后隐藏。
- **交互逻辑**（本 tab 是详情页唯一的「二级视图」，且文档视图为 **预览 ⇄ 编辑双模式**）：
  1. **列表 → 预览**：点击文档行，面板整体切换为该文档的极简渲染（标题 15px 加粗 + 段落/列表 13.5px）；顶部工具栏 = 左侧「← 返回文档列表」+ 右侧「编辑」文字按钮（灰字，hover 变黑）。返回列表时搜索词保留，便于继续筛选。
  2. **预览 → 编辑**：点击「编辑」，正文区切换为**编辑区**——带边框的文本域（`1px solid var(--border)`、圆角 10px、等宽字体 `SF Mono/Menlo` 13px、行高 1.6、内边距 14px，撑满面板剩余高度、内部滚动），预填该文档的 Markdown 源文本；顶部「编辑」按钮变为模式标识「编辑中」灰字徽标。
  3. **编辑区底部操作栏**：左侧 = 灰色提示「有未保存的修改」（仅当内容有改动时出现）+ 红色文字「删除文档」按钮；右侧 = 「取消」文字按钮 + 「保存」按钮（黑底白字、圆角 7px、高 30px；**内容无改动时禁用灰态**）。
  4. **保存**：写回本地 state（Mock 不持久化）→ 自动切回预览模式展示新内容 → 文档列表中该文件的「更新于」时间刷新为当前时间。
  5. **取消 / 返回**：编辑模式下点击「取消」或「← 返回文档列表」，若有未保存修改则直接丢弃（Mock 简化，不做确认弹窗）并回到对应视图。
  6. **新建文档**：点击分组标题右侧「+ 新建」，弹出「新建文档」弹窗（文件名 + 一句话说明）；创建后关闭弹窗并进入该文档的编辑模式（空内容），保存后出现在列表中。
  7. **删除文档**：编辑模式底部「删除文档」→ 直接删除并返回列表（Mock 不做确认）。
- **边界**：规范 = 仓库内、必须遵守的约束文档；经验性、非强制的内容归「知识记忆」。编辑器为纯文本域，不做 Markdown 工具栏/实时预览分栏（保持极简）。

**② 代码 —— 占位（本期不做详情）**

- 保留导航入口，点击后右侧展示统一占位面板（图标 + 「代码 功能建设中」+ 「该模块将在后续版本提供，敬请期待」）。不预留数据结构。

**③ 项目成员 —— 参与的"人"**

- **定位**：回答"谁在做"，人的名单与分工。
- **内容**：只有一个分组「成员（N 人）」（分组标题右侧 = 「+ 添加」文字按钮），角色/权限信息**整合进成员行**，不设单独的「角色」分组。每行 = 字母头像 + 姓名（主）+ 职位 · 权限（次级，如「前端 · 项目负责人」「后端 · 管理员」，无权限者只显示职位）｜右侧 = 在线状态点（绿●/灰○）+ 最近活跃时间。
- **交互逻辑**：
