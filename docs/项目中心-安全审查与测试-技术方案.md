# 「项目中心 - 安全审查 / 测试」技术方案

> 创建日期：2026-08-28
> 更新日期：2026-08-28

## 1. 背景与目标

项目详情页 9 个导航项中，「安全审查」「测试」目前仍为占位面板（`PlaceholderPanel`）。本方案将两者替换为完整面板：

- **安全审查**：回答「项目的安全风险状况？」——风险总览、漏洞趋势、漏洞明细与处理流转、审查策略；
- **测试**：回答「项目的质量状况？」——质量总览、测试趋势、覆盖率分布、套件健康度、失败用例。

与已实现模块的关系（互补不重叠，延续"每个 tab 只回答一个问题"原则）：

| 模块 | 回答的问题 | 视角 |
|---|---|---|
| 自动化任务 | 机器在做什么、跑到哪一步 | 过程 |
| 能效看板 | 自动化跑得怎么样 | 效率结果 |
| **安全审查** | 扫出了什么安全问题、处理得怎么样 | **安全结果** |
| **测试** | 质量防线覆盖与通过情况如何 | **质量结果** |

> 产品逻辑呼应：自动化任务里已有「依赖漏洞扫描」「接口回归」这类任务——能效看板展示它们的**运行统计**，安全审查/测试展示它们的**结果沉淀**，三者形成闭环。

约束与前提：

- 纯前端 Mock，不接真实数据源，数据本地静态生成（确定性生成，刷新不变）；
- 视觉与交互完全遵循现有体系：浅色 macOS 风、CSS 变量、组件级 CSS、无第三方 UI/图表库（图表内联 SVG / div 手绘）；
- 遵循项目详情页 Settings 式极简风格规范（分组卡片 + 行式布局 + 细分割线 + 大留白）；
- 最大化复用现有组件：`Section`/`Row`、`SegmentedControl`、`StatusBadge`、`Toggle`、`HBarChart`、KPI 卡片样式、双轴趋势图。

## 2. 现状分析

| 项 | 现状 |
|---|---|
| 导航入口 | `ProjectDetail.tsx` 的 `NAV_ITEMS` 中 `security` / `testing` 均 `ready: false`，点击渲染 `PlaceholderPanel` |
| 可复用组件 | `Section`/`Row`（Settings 分组）、`SegmentedControl`（时间范围切换）、`StatusBadge`（严重度/状态徽标）、`Toggle`（策略开关）、`HBarChart`（横向条形/迷你条） |
| 图表能力 | `TrendChart`（SVG 双轴：柱 + 折线 + hover 浮层，目前绑定能效的 `DailyStat` 结构）；`HBarChart`（div 百分比条形） |
| KPI 样式 | `EfficiencyPanel.css` 内 `.efficiency-kpis` / `.kpi-card` 系列（目前为能效看板私有） |
| 数据层模式 | `src/data/efficiency.ts`：类型 + 确定性 Mock + 聚合函数，`getXxx(projectId)` 按项目取数，无数据返回 `null` 走空状态 |

**结论**：仿照能效看板模式，新建 `security.ts` / `testing.ts` 两个独立数据层 + `SecurityPanel` / `TestingPanel` 两个面板；将 KPI 卡片样式抽为公共件、将 `TrendChart` 泛化为通用双轴图，`ProjectDetail` 仅改导航注册。

## 3. 总体设计

### 3.1 安全审查 · 信息架构（面板内自上而下）

```
安全审查                                    [近 7 天 | 近 14 天 | 近 30 天]
│
├── ① 核心指标（KPI 卡片网格 3×2）
│     安全评分 · 待处理漏洞(按严重度) · 依赖漏洞 · 密钥泄露 · 区间新增/修复 · 全量扫描
│
├── ② 漏洞趋势（SVG 双轴图：新增发现柱 + 待修复存量折线，hover 联动明细）
│
├── ③ 漏洞分布（横向条形 ×2：按严重程度 / 按来源）
│
├── ④ 漏洞明细（分段：待处理 / 已处理；行展开 + 状态流转）
│
└── ⑤ 审查策略（Settings 行 + 开关：MR 阻断 / 自动创建 Issue / 扫描范围）
```

```

        ▼                                            ▼

        │                                            │
```

- 时间范围切换（7/14/30 天）为全局筛选：KPI、趋势、分布全部联动重算（与能效看板一致）；
- 安全审查的**存量类指标**（待处理漏洞、依赖漏洞、密钥泄露、安全评分）不受 range 影响；**区间类指标**（新增/修复）随 range 变化；
- 面板宽度沿用详情页 720px 单列布局，图表随容器自适应（SVG viewBox 缩放）。

## 4. 页面设计

### 4.1 安全审查面板

#### 顶部：说明 + 时间范围

- 一行：左侧灰色小字「代码与依赖安全扫描结果统计」（11.5px，同 `.section-label` 风格），右侧 `SegmentedControl` 三段：近 7 天 / 近 14 天 / 近 30 天（默认近 14 天）。

#### ① 核心指标（KPI 卡片）

- 网格 `repeat(auto-fill, minmax(200px, 1fr))`，白底卡片 `1px solid var(--border)`、圆角 10px、内边距 14px（与能效看板 KPI 同族）；
- 每卡结构：灰色小标签（11.5px）+ 主数值（22px 加粗）+ 次级说明（12px 灰）：

| 标签 | 主数值 | 次级说明 |
|---|---|---|
| 安全评分 | 82 | 高危清零后可达 90+ |
| 待处理漏洞 | 19 | 高危 2 · 中危 5 · 低危 12 |
| 依赖漏洞 | 6 | 含 2 个 CVE |
| 密钥泄露 | 0 | 已检测 34 个文件 |
| 区间新增 | 7 | 同期修复 9 · 净收敛 2 |
| 全量扫描 | 每日 06:00 | 上次 08-28 06:00 · 耗时 4.2 分钟 |

- **安全评分着色**：≥ 90 用 `--status-success`，70–89 用 `--status-warning`，< 70 用 `--status-danger`（仅数值着色）；
- 「待处理漏洞」数值随漏洞状态流转实时联动（标记已修复/忽略后 -1）。

#### ② 漏洞趋势（SVG 双轴图）

- 尺寸 viewBox `680 × 220`，随容器等比缩放（同能效看板趋势图规格）；
- 左轴：**新增发现**（柱状，`--status-warning` 60% 透明度）；右轴：**待修复存量**（折线，`--status-danger`，范围 0–动态上限）；
- 网格 4 条 `#F0F0F0` 细线 + 左右轴刻度文字（10.5px 灰）；
- 交互：hover 竖向参考线 + 白底细边框浮层（日期 / 新增 / 修复 / 存量）；
- 图例：顶部右侧两枚小色点 + 文字（新增发现 / 待修复存量）。

#### ③ 漏洞分布

- Settings 分组卡片内两组横向条形（复用 `HBarChart`）：
  1. **按严重程度**（4 行）：高危（红 `--status-danger`）/ 中危（橙 `--status-warning`）/ 低危（蓝 `--status-info`）/ 提示（灰 `--status-neutral`）；每行 = 严重度名 + 条形（长度 = 占比）+ 数量与占比（13px 灰）；
  2. **按来源**（4 行）：SAST 静态扫描 / 依赖扫描 / 密钥检测 / 代码评审；同样式，中性灰绿填充。

#### ④ 漏洞明细（核心交互区）

- 顶部 `SegmentedControl` 两段：**待处理（N）** / **已处理（N）**（默认待处理；已处理 = 已修复 + 已忽略，行内状态徽标区分）；
- 每行 = 严重度徽标（色点或小徽标）+ 漏洞标题（主，13.5px）+ 位置 · 来源 · 发现时间（次级，12px 灰；依赖漏洞附 CVE 编号）｜右侧 = 状态徽标 + 展开箭头 ⌄；
- **点击行展开详情**（手风琴，同组同时只展开一条）：
  - 漏洞描述（13px）+ 修复建议（13px，前置「建议：」灰字标签）；
  - 待处理条目：底部「标记已修复」（黑底小按钮）+「忽略」（红字文字按钮）；
  - 已处理条目：显示处理方式与处理时间（12px 灰）；
- **状态流转**（本地 state）：待处理 → 已修复 / 已忽略；流转后行移入「已处理」分段，KPI「待处理漏洞」与分布条形联动重算；
- 排序：严重度降序（高危 → 中危 → 低危 → 提示），同级按发现时间倒序。

#### ⑤ 审查策略

- Settings 分组卡片，行式布局：
  1. 「MR 阻断」——次级说明「存在高危漏洞时阻断合并请求」｜右侧 Toggle（默认开）；
  2. 「自动创建 Issue」——次级说明「发现高危漏洞时自动在 GitLab 创建 Issue」｜右侧 Toggle（默认开）；
  3. 「扫描范围」——次级说明「每日全量 + MR 增量」｜右侧展示文本「全量 + 增量」（纯展示）。

#### 空状态

- 项目无安全数据（如 data-pipeline）：居中空状态——灰色线框盾牌图标 + 「暂无安全审查数据」+ 次级说明「接入代码仓库后，这里将展示安全扫描结果」（沿用能效看板空状态风格）。

### 5.1 `src/data/security.ts`

```ts
/** 漏洞日序列（固定 30 天，面板按范围截取） */
export interface VulnDailyStat {
  date: string        // 'MM-DD'
  found: number       // 当日新增发现
  fixed: number       // 当日修复
}

/** 漏洞条目 */
export interface VulnItem {
  id: string
  title: string
  severity: '高危' | '中危' | '低危' | '提示'
  source: 'SAST 静态扫描' | '依赖扫描' | '密钥检测' | '代码评审'
  /** 文件路径 / 依赖包名 */
  location: string
  /** 依赖漏洞的 CVE 编号 */
  cve?: string
  foundAt: string
  status: '待处理' | '已修复' | '已忽略'
  handledAt?: string
  description: string
  suggestion: string
}

/** 审查策略（本地 state 可切换） */
export interface SecurityPolicy {
  blockMrOnHigh: boolean
  autoIssue: boolean
  scanScope: string
}

export interface SecurityData {
  score: number
  daily: VulnDailyStat[]
  vulns: VulnItem[]
  policy: SecurityPolicy
  lastScanAt: string
  lastScanMinutes: number
  scannedFiles: number
}

getSecurity(projectId): SecurityData | null          // 按 project 取数
summarizeSecurity(data, rangeDays): SecurityKpis     // 6 项 KPI（存量 + 区间）
sliceVulnDaily(data, rangeDays): VulnDailyStat[]     // 趋势序列
severityBreakdown(vulns): { severity; count }[]      // 严重度分布
sourceBreakdown(vulns): { source; count }[]          // 来源分布
```

### 5.3 Mock 数据策略（与能效看板一致）

- **日序列**：确定性公式生成（工作日基线 + 周末衰减 + 固定相位波动），不用随机数，刷新不变；
- **条目级**：手写字面量。loomweb 数据丰富（漏洞约 30 条：待处理 19 / 已修复 23 / 已忽略 4；套件 6 个；失败用例 12 条；覆盖模块 5 个）；yigou-app 少量（漏洞 6 条 / 套件 2 个 / 失败 2 条）；data-pipeline 无数据（走空状态）；
- **派生指标全部现算**：KPI、分布、趋势由 `daily` / `vulns` / `suites` 按当前 range 聚合，切换范围联动一致；
- 口径：待修复存量 = 待处理漏洞总数（趋势折线取每日模拟存量）；净收敛 = 区间修复 − 区间新增。

## 7. 边界与约束

- 图表全部内联 SVG / div 实现，不引入第三方库；
- 颜色仅使用现有 CSS 变量（`--status-*` 系列语义色），不新增核心设计变量；
- 写操作仅两处：漏洞状态流转（待处理 → 已修复/已忽略）、审查策略开关——均为本地 state，刷新还原；
- 「重新扫描」「重跑套件」等触发类交互本期不做（运行能力统一在「自动化任务」tab，保持职责单一）；
- 测试套件运行详情不下钻（同能效看板明细表边界）；
- 窄容器（720px）下图表等比缩放，漏洞/用例列表随面板滚动。

## 9. 验收标准

1. 「安全审查」「测试」导航可正常选中，右侧展示完整面板，不再是占位面板；
2. 两面板顶部均有时间范围切换（近 7/14/30 天，默认 14 天），KPI 与趋势图联动重算；
3. 安全审查：6 项 KPI（安全评分按阈值着色）；趋势图 hover 浮层正常；严重度/来源分布条形正确；漏洞明细分段切换（待处理/已处理）、点击展开描述与修复建议、「标记已修复/忽略」流转后行移入已处理分段且 KPI「待处理漏洞」联动 -1；审查策略两个开关可切换；
4. 测试：6 项 KPI（通过率/覆盖率按阈值着色）；趋势图正常；覆盖率分布按阈值着色（低覆盖模块标橙/红）；套件列表含类型徽标 + 通过率迷你条 + 最近运行状态；失败用例可展开等宽字体错误详情，连败徽标与关联缺陷展示正确；
5. data-pipeline 两面板均展示空状态（各自图标与文案）；
6. 视觉遵循 Settings 极简风与现有色彩变量，无新色板、无第三方依赖；
7. 构建通过（含 tsc 类型检查），代码提交 commit。

## 10. 风险与说明

- 纯 Mock 数据，不与真实扫描器 / 测试框架对接，后续可替换为接口；漏洞状态流转与策略开关仅本地 state 生效，刷新即还原；
- 漏洞趋势的「待修复存量」为前端模拟序列（非真实逐日快照），仅保证图形语义正确；
- `DualTrendChart` 泛化涉及对 `TrendChart` 的改造，若能效看板同步迁移需回归验证其 hover 浮层与轴刻度（低风险，样式与逻辑同构）；
- 「代码」tab 仍保留占位，不在本方案范围。
