# 「项目中心 - 安全审查」规则引擎技术方案

> 创建日期：2026-09-01
> 更新日期：2026-09-01（v6：定时审查升级为弹窗设定——启用开关 + 频率（每天/每周/每月）+ 星期/日期 + 时:分 + 实时预览；工具行入口展示规则文案；去除重复说明文案）

## 1. 背景与目标

项目详情页「安全审查」tab 目前为占位面板（`PlaceholderPanel`）。本方案将其替换为**规则驱动的代码安全审查**能力，回答三个问题：

1. **审查依据是什么？** —— 用户可自行设定审查规则（关键词 / 正则匹配）；
2. **怎么审？** —— 按当前启用的规则对项目代码执行审查，产出审查记录与问题明细；
3. **开箱即用什么？** —— 预置一套安全类规则库（硬编码密钥、SQL 注入、XSS、弱加密等），默认启用、可停用。

本期范围界定：

- **只做安全审查 tab**，不涉及其他占位 tab；
- **不含任何数据图表**——KPI 卡片、趋势图、分布条形等统计向内容均不做，面板为纯「配置 + 列表」形态；
- **扫描/阻断策略为紧凑条**——策略是审查行为的全局配置，以一行三格的紧凑卡片放在面板最顶部（分段切换之前），切段时保持可见；扫描范围为可选配置（全量 / 增量 / 全量+增量）。

与既有文档的关系：`docs/项目中心-安全审查与测试-技术方案.md`（2026-08-28，未实施）设计了统计向面板。本方案按最新需求重新设计安全审查 tab，**原方案的安全部分由本方案替代**（其中「漏洞明细 + 状态流转」「审查策略」的交互形态被吸收保留）。

约束与前提：

- 纯前端 Mock，不接真实扫描器；「审查执行」为确定性模拟（与启用规则联动），写操作仅本地 state 生效；
- 视觉与交互完全遵循现有体系：Settings 式分组卡片 + 行式布局、`Section`/`Row`、`SegmentedControl`、`StatusBadge`、`Toggle`、`FormModal`，无第三方依赖；
- 数据挂在 `Project` 上（与 `repos` / `specs` / `knowledge` 同级），写操作统一走 `onUpdateProject`。

## 2. 现状分析

| 项 | 现状 |
|---|---|
| 导航入口 | `ProjectDetail.tsx` 的 `NAV_ITEMS` 中 `security` 为 `ready: false`，渲染 `PlaceholderPanel` |
| 可复用组件 | `Section`/`Row`（分组行）、`SegmentedControl`（段切换）、`StatusBadge`（严重度/状态徽标）、`Toggle`（规则启停）、`FormModal` + `ModalField`（新建/编辑规则弹窗）、`ChevronDownIcon`（行展开） |
| 数据层模式 | 面板数据挂 `Project` 字段（如 `repos: CodeRepo[]`），Mock 手写字面量 + 工厂函数（`createEmptyProject` 给默认值） |
| 同类参照 | `CodePanel`（分段 + Section + FormModal 添加 + 行操作）、`KnowledgePanel`（分段 + 行展开编辑）——本面板为两者交互模式的组合 |

**结论**：新建 `src/data/security.ts`（类型 + 预设规则库 + Mock 命中池 + 审查生成函数）与 `SecurityPanel.tsx/.css`，`Project` 增加 `security` 字段，`ProjectDetail` 仅改导航注册。

## 3. 总体设计

### 3.1 信息架构（面板内自上而下）

```
安全审查
│
├── ① 扫描/阻断策略（紧凑条：一行三格，面板最顶部，切段不隐藏）
│     格 1：MR 阻断（名称 + Toggle，默认开；title = 存在高危问题时阻断合并请求）
│     格 2：自动创建 Issue（名称 + Toggle，默认开；title = 发现高危问题时自动在 GitLab 创建 Issue）
│     格 3：扫描范围（名称 + 下拉可选：全量 / 增量 / 全量+增量，默认全量+增量）
│
├── ② 顶部分段切换：[ 审查规则（N）| 审查记录（M）]
│
├── ③ 段一：审查规则
│   ├── Section「预设安全规则（N 条 · 启用 X）」
│   │     行 = 规则名 + 安全子类徽标 + 严重度徽标
│   │           描述（次级一行省略）
│   │           右侧 = 启停 Toggle
│   │     行点击展开：匹配方式 + 规则内容（mono）+ 适用范围 + 示例说明
│   │     预设规则：不可删除、不可改内容，仅可启停
│   ├── Section「自定义规则」+ [+ 新建规则]
│   │     行 = 规则名 + 严重度徽标 + 匹配方式徽标（关键词/正则）
│   │           描述 · 适用范围（次级）
│   │           右侧 = 启停 Toggle + 编辑 + 删除
│   │     新建/编辑弹窗（FormModal）：规则名* / 严重级别 / 匹配方式（关键词|正则）
│   │           / 规则内容*（正则时校验合法性）/ 适用范围 / 规则说明
│   └── 底部提示行：停用的规则不参与审查
│
└── ④ 段二：审查记录
    ├── 顶部工具行：定时审查入口（点击打开设定弹窗，开启态展示规则文案）+ [立即审查] 主按钮
    ├── Section「审查记录（N）」
    │     行 = 时间 + 触发方式徽标（手动/定时/MR）+ 审查范围
    │           次级 = 应用规则 N 条 · 发现 M 个问题（高危 x · 中危 y · 低危 z）
    │           右侧 = 问题数徽标 + 展开箭头 ⌄
    │     行点击展开：问题明细（手风琴，同组同时只展开一条记录）
    │           问题行 = 严重度徽标 + 规则名 + 文件:行号（mono）
    │                     问题描述 + 「建议：」修复建议
    │                     待处理 → [标记已修复]（黑底小按钮）[忽略]（红字）
    │                     已处理 → 处理方式与时间（12px 灰）
    └── 空状态：暂无审查记录 →「点击右上角立即审查，或设定定时审查到点自动执行」
```

### 3.2 核心交互流

```
配置策略（①紧凑条）    设定规则（③段一）                     执行审查（④段二）
──────────────        ─────────────────                    ─────────────────
MR 阻断 Toggle ──┐    预设规则 Toggle 启停 ──┐
自动 Issue Toggle ─┤  自定义规则 增/改/删/启停 ─┴─→ 当前启用规则集 ─→ 点击「立即审查」
扫描范围 下拉 ────┘                                          │ 按钮「审查中…」禁用约 1.2s（模拟执行）
                                                             ▼
                                                      生成审查记录（置顶）
                                                      遍历启用规则 × Mock 命中池
                                                             ▼
                                                      展开记录 → 问题明细
                                                      待处理 → 已修复 / 已忽略（状态流转）
                                                      记录行次级的问题计数联动重算
```

- **审查生成与规则联动**：每条预设规则在 Mock 命中池中预置 1–2 条示例问题（文件 / 行号 / 代码片段 / 描述 / 建议）；执行审查时，仅**当前启用**的规则参与命中，保证「停用规则 → 再审查 → 该规则问题消失」的因果可感知；
- **自定义规则命中**：Mock 按规则名/关键词在预置文件清单中确定性命中 0–1 条（演示语义即可，不做真实正则引擎）；
- **状态流转**：问题「待处理 → 已修复 / 已忽略」为本地 state，记录行次级计数与徽标联动；
- **策略开关**：`MR 阻断` / `自动创建 Issue` 为本地 state 开关（Mock 不产生真实联动，仅保存配置态）。

### 3.3 数据流

```
src/data/security.ts
  ├─ PRESET_RULES（10 条预设安全规则）
  ├─ MOCK_FINDING_POOL（预设规则 → 示例问题池）
  ├─ createDefaultSecurity()（新项目默认：预设规则全启用 + 默认策略 + 空记录）
  └─ buildReviewRecord(rules, trigger)（按启用规则生成一条审查记录）
        │
        ▼
Project.security: SecurityData ──→ SecurityPanel（读）
        ▲                              │ 写：策略开关、规则增删改/启停、执行审查、问题流转
        └──── onUpdateProject ←─────────┘（与其他面板一致）
```

## 4. 页面设计

### 4.1 扫描/阻断策略紧凑条（面板最顶部）+ 分段切换

- **扫描/阻断策略紧凑条**（`section-card` 样式，一行三格，格间细分割线），位于面板最顶部：
  1. 格 1「MR 阻断」——右侧 `Toggle`（默认开）；格 title =「存在高危问题时阻断合并请求」；
  2. 格 2「自动创建 Issue」——右侧 `Toggle`（默认开）；格 title =「发现高危问题时自动在 GitLab 创建 Issue」；
  3. 格 3「扫描范围」——右侧**下拉可选**：全量 / 增量 / 全量+增量（默认「全量+增量」）；格 title =「全量 = 每日全仓扫描，增量 = 仅 MR 变更文件」。
- 紧凑条高度约一行（≈ 40px）；属面板级配置，**切段时保持可见**；开关与下拉说明收纳到 title 悬停提示，保证紧凑；
- 紧凑条下方为 `SegmentedControl` 两段：**审查规则（N）** / **审查记录（M）**（N = 预设 + 自定义规则总数，M = 记录数；默认落在审查规则段）；
- 段下方灰色小字说明（同 `CodePanel` 的 `SEG_HINT` 模式，仅此一处，记录段工具行不再重复）：
  - 规则段：「预设安全规则开箱即用，可停用；自定义规则支持关键词 / 正则匹配」
  - 记录段：「手动立即审查，或设定定时审查到点自动执行」

### 4.2 段一：审查规则

#### 预设安全规则（Section）

- 分组标题「预设安全规则（10 条 · 启用 X）」，无右侧操作（不可增删）；
- 每行（`Row` + `expandable`）：
  - 左：规则名（13.5px 主）+ 安全子类徽标（小号 `StatusBadge` neutral：密钥泄露 / 注入 / XSS / 加密 / 信息泄露 / 配置 / 依赖 / 规范）+ 严重度徽标（高危 danger / 中危 warning / 低危 info / 提示 neutral）；
  - 次级：规则描述（12px 灰，一行省略）；
  - 右：启停 `Toggle`（点击行展开与 Toggle 点击互不干扰——Toggle 上 `stopPropagation`）；
- **点击行展开**（手风琴，同组同时只展开一条）：
  - 匹配方式（关键词 / 正则）+ 规则内容（mono 等宽字体块，浅灰底圆角，同失败用例错误详情样式）；
  - 适用范围（如 `全部文件` / `*.ts, *.tsx`）；
  - 「预设规则不可修改，仅可启停」提示（11.5px 灰）。

#### 自定义规则（Section）

- 分组标题「自定义规则（N）」，右侧 `+ 新建规则` 文字按钮；
- 每行：
  - 左：规则名 + 严重度徽标 + 匹配方式徽标（关键词 = info / 正则 = neutral）；
  - 次级：描述 · 适用范围；
  - 右：启停 Toggle + `编辑`（文字按钮，打开弹窗预填）+ `移除`（红字文字按钮）；
- 空状态：分组卡片内居中灰字「暂无自定义规则」；
- **新建 / 编辑弹窗**（`FormModal`，字段竖排）：
  1. 规则名*（input，占位「如 禁止使用 eval」；同段重名拦截）；
  2. 严重级别（select：高危 / 中危 / 低危 / 提示，默认中危）；
  3. 匹配方式（select：关键词 / 正则，默认关键词）；
  4. 规则内容*（input；关键词 = 如 `eval(`；正则 = 如 `new Function\(.*\)`；**正则时校验合法性**（`new RegExp()` try/catch），非法时红字提示「正则表达式不合法」并禁用确认）；
  5. 适用范围（select：全部文件 / 前端 *.ts,*.tsx / 后端 *.java,*.py / 配置 *.yaml,*.json，默认全部文件）；
  6. 规则说明（input，选填，占位「命中时向审查人说明该规则的目的」）；
- 新建成功后规则默认**启用**，追加到自定义列表末尾。

#### 底部提示行

- 规则段底部一行 11.5px 灰字：「停用的规则不参与审查 · 审查在「审查记录」段执行」。

### 4.3 段二：审查记录

#### 顶部工具行

- 左：**定时审查入口**（描边胶囊按钮）——「定时审查」名称 + 状态（开启 = 绿字规则文案如「每天 06:00」/ 关闭 = 灰字「未开启」）+「设定」文字；点击打开**定时审查设定弹窗**；
- 右：`立即审查` 黑底主按钮（`btn-primary`）；点击后文案变「审查中…」并禁用，约 1.2s 后生成「手动」记录置顶并自动展开该记录；无启用规则时按钮禁用（title 提示「请先启用至少一条规则」）。

#### 定时审查设定弹窗（FormModal，字段竖排）

1. 「启用定时审查」——`Toggle`（默认关）+ 右侧说明文案（开启 =「到点后自动按启用规则执行审查」/ 关闭 =「关闭后仅可手动立即审查」）；
2. 「频率」——select：每天 / 每周 / 每月（默认每天）；
3. 「星期」——select：周一~周日（仅频率 = 每周时出现）；
4. 「日期」——select：1~31 日（仅频率 = 每月时出现）；
5. 「时间」——时:分双下拉（时 00–23 / 分 00·15·30·45，默认 06:00）；
6. 底部**实时预览**块（浅灰底圆角）：「将于 **每天 06:00** 自动执行安全审查」——文案随表单实时变化（对齐自动化任务新建弹窗的定时配置交互）；
- 保存：更新策略配置；**从关闭到开启**时模拟一次到点执行——生成一条「定时」触发记录置顶（时间 = 当天日期 + 所选时间点），直观演示定时效果；关闭保存不删记录；无启用规则时仅保存配置态不生成记录。

#### 审查记录列表（Section「审查记录（N）」）

- 每行（`Row` + `expandable`，点击展开）：
  - 左：`08-31 14:20`（主）+ 触发方式徽标（手动 = info / 定时 = neutral / MR = success）+ 审查范围（如 `loomweb · dev`，12px 灰）；
  - 次级：`应用规则 8 条 · 发现 5 个问题（高危 1 · 中危 3 · 低危 1）`——问题计数随状态流转实时重算（仅统计待处理）；
  - 右：问题数徽标（0 = success「无问题」，>0 = warning「N 个问题」）+ 展开箭头 ⌄（展开时旋转）；
- **展开区**（手风琴，同时只展开一条记录）：
  - 顶部一行执行摘要：`耗时 3.6 秒 · 扫描 34 个文件`（12px 灰）；
  - 问题明细列表：每条 = 严重度徽标 + 规则名（13px）+ `src/utils/html.ts:42`（mono 12px）；
    - 问题描述（13px）+ 修复建议（前置「建议：」灰字标签）；
    - 代码片段（mono 块，浅灰底，一行省略，title 悬停看全文）；
    - 待处理：底部 `[标记已修复]`（黑底小按钮）+ `[忽略]`（红字文字按钮）；
    - 已处理：`已修复 · 08-31 14:30`（12px 灰）；
  - 无问题的记录展开区：居中灰字「本次审查未发现问题」。

#### 空状态

- 无任何记录时：居中空状态——盾牌线框图标（复用 `ShieldIcon`）+「暂无审查记录」+ 次级说明「点击右上角立即审查，或设定定时审查到点自动执行」。

### 5.2 预设安全规则库（10 条）

| # | 规则名 | 子类 | 严重度 | 匹配 | 规则内容（示意） |

| 4 | 不安全的反序列化 | 注入 | 高危 | 关键词 | `pickle.loads` / `ObjectInputStream` |
| 5 | 弱加密算法 | 加密 | 中危 | 关键词 | `MD5` / `DES` / `ECB` |

## 7. 边界与约束

- 不做真实代码扫描：审查执行为 Mock 模拟（确定性生成，与启用规则联动），后续可替换为后端接口；
- **本期不含任何数据图表**：KPI 卡片、趋势图、分布条形等统计向内容均不做；如后续需要，可在审查记录段之上叠加，数据源为本期 `ReviewRecord`，无结构冲突；
- 预设规则不可删除、不可编辑内容（仅启停）；自定义规则可增删改启停，正则内容做合法性校验；
- 写操作均为本地 state（刷新还原）：策略开关、规则变更、审查记录生成、问题状态流转；
- 「重新扫描某条记录」「定时自动审查配置」本期不做（定时审查可后续与自动化任务打通）；
- 问题不做「跳转 GitLab」链接（Mock 无真实地址，保持与能效看板明细同边界）；
- 面板宽度沿用详情页单列布局，规则内容 / 代码片段 mono 块一行省略 + title 悬停全文。

## 10. 风险与说明

- Mock 审查结果为确定性生成（非真实扫描），仅保证「规则启停 ↔ 命中结果」的因果语义正确；接入真实引擎时 `buildReviewRecord` 替换为接口调用即可，面板结构不变；
- 自定义规则的「关键词 / 正则」在 Mock 中不做真实匹配，命中由确定性相位模拟；规则内容字段保留完整结构，便于后续接引擎；
- 策略开关（MR 阻断 / 自动创建 Issue）仅保存配置态，Mock 不产生真实联动；扫描范围选择同样仅保存配置态（Mock 审查不按范围区分命中）；
- 定时审查为 Mock 模拟：从关闭到开启保存时生成一条「定时」记录（时间 = 当天 + 所选时间点），不做真实定时器轮询；后续接后端时可由服务端调度触发；
- 问题状态流转仅本地 state，刷新还原（与全站 Mock 写操作口径一致）；
- 策略紧凑条在窄容器下三格可能换行拥挤，实现时保留 `min-width: 0` + 省略号兜底；若后续策略项增多，可降级为可展开的折叠区。
