## 1. 背景与目标

### 1.1 现状问题

| # | 问题 | 现状表现 |
|---|---|---|
| 1 | **通知无法跳转** | 确认型通知只有「拒绝/批准」快捷按钮，点击通知本身无反应；输入型「去填写 →」跳转后直接弹运行弹窗，落点不是「待人工处理」tab |
| 2 | **跳转落点错误** | `AutomationPanel` 收到 `focusJobId` 只执行 `setModalJobId`（打开 RunModal），不切换 segment；若用户当前停在「任务」tab，跳转后看不到待人工处理卡片 |
| 3 | **不知道找谁处理** | 待人工处理卡片（GateCard）只显示任务/状态/描述，没有标记需要哪个人确认或填写 |

### 1.2 改造目标

1. **通知项整体可点击**：点击任意通知 → 跳转到对应项目详情 → 自动化任务 tab → **「待人工处理」segment** → 滚动定位并高亮对应卡片；
2. **确认人标记**：待人工处理卡片上明确标记「需要谁确认/填写」（头像 + 姓名，当前用户时显示「需要你确认」）；
3. 通知列表同步展示处理人，信息一致；
4. 确认型通知的「拒绝/批准」快捷按钮保留（按钮点击不触发跳转）。

## 2. 数据模型变更（`src/data/projects.ts`）

### 2.1 `HumanGate` 增加处理人字段

```ts
export interface HumanGate {
  type: '确认' | '输入'
  title: string
  description: string
  /** 需要处理的人（确认型 = 确认人；输入型 = 填写人）；缺省 = 不指定 */
  approver?: MessageSender
  /** 输入型：表单字段定义 */
  fields?: { key: string; label: string; placeholder?: string; required?: boolean }[]
}
```

复用现有 `MessageSender`（name / initial / color），GateCard 可直接渲染头像，无需回查成员表。

### 2.2 `Notification` 增加处理人字段

```ts
export interface Notification {
  id: string
  type: '等待确认' | '等待输入'
  jobId: string
  runId: string
  projectId: string
  title: string
  description: string
  /** 相对时间文案 */
  time: string
  /** 需要处理的人（由 Gate 触发时带上，列表展示用） */
  approver?: MessageSender
}
```

|---|---|---|---|
| loomweb · j3 周报生成（等待确认） | gate.approver | **shilu**（当前用户） | 卡片显示「需要你确认」 |

## 3. 交互设计

### 3.1 通知项点击跳转（`Notifications.tsx`）

```
┌ 通知（2 条待处理）──────────────────────┐
│ [等待确认]  周报生成 · 运行 #r12          │ ← 整条可点击（cursor: pointer）
│ 即将把周报发布到外部渠道，请确认内容无误    │
│ (S) 需要 shilu 确认 · 5 分钟前  [拒绝][批准]│ ← 按钮点击不冒泡（不触发跳转）
├────────────────────────────────────────┤
│ [等待输入]  发布准备 · 运行 #r13           │
│ 发布前请补充版本号与发布说明               │
│ (L) 需要 luyu 填写 · 12 分钟前  [去处理 →] │
└────────────────────────────────────────┘
```

- 通知项 `onClick` → `onGoTo(n)` 并收起下拉；
- 确认型「拒绝/批准」、输入型「去处理 →」按钮均 `stopPropagation`（快捷操作不跳转；「去处理」与点击整条行为一致，保留显式入口）；
- foot 左侧新增处理人：小头像（16px 圆形底色）+「需要 xx 确认/填写」+ 时间。

### 3.2 跳转链路（`App.tsx` → `ProjectDetail` → `AutomationPanel`）

```
通知点击 → App.setView({ project-detail, initialNav: 'automation', focusJobId })
        → ProjectDetail 切到自动化任务 tab（已有逻辑，不变）
        → AutomationPanel focusJobId effect：
            ① setSegment('pending')            ← 新增：强制切到「待人工处理」tab
            ② setHighlightJobId(focusJobId)    ← 新增：高亮定位目标卡片
            ③ 不再自动打开 RunModal             ← 行为变更：落点是 tab 内卡片，不是弹窗
            ④ onClearFocus()
```

**行为变更说明**：原实现 `focusJobId` 直接打开运行弹窗；现改为切 tab + 高亮卡片。理由：用户明确要求落点是「待人工处理 tab」；确认型卡片上已有「批准/拒绝」按钮、输入型卡片上有「去填写 →」，落点即卡片即可处理，且两类通知行为统一。

### 3.3 待人工处理卡片确认人标记（`GateCard.tsx`）

```
▎周报生成 · 运行 #r12                        [等待确认]
▎发布前确认
▎即将把周报发布到外部渠道，请确认内容无误。
▎(S) 需要 shilu 确认                          ← 新增：头像 + 姓名（当前用户 → 「需要你确认」）
▎运行至步骤 3/4 · 已等待 5 分钟      [拒绝][批准]
```

- 位置：描述与 foot 之间单独一行，视觉上明显（头像底色 + 姓名 600 字重）；
- `approver.name === CURRENT_USER.name` 时文案为「需要你确认 / 需要你填写」，否则「需要 xx 确认 / 需要你填写」→「需要 xx 填写」；
- 无 approver 时不渲染该行（兼容旧数据）。

### 3.4 高亮定位（`GateCard.tsx` + `AutomationPanel.tsx`）

- `AutomationPanel` 维护 `highlightJobId` state，`focusJobId` 到达时设置，2.6s 后自动清除；
- `GateCard` 接收 `highlight` prop：为 true 时 `scrollIntoView({ block: 'center' })` + 播放一次背景闪烁动画（warning 底色渐隐），动画结束恢复常态；
- 多次点击同一通知可重复触发（focusJobId 清除后可再设置）。

## 5. 验证点

1. 通知中心点击任一条通知（含确认型）→ 进入对应项目自动化任务 tab 且停在「待人工处理」，目标卡片滚动至可视区并闪烁高亮；
2. 通知内「批准/拒绝」不跳转、直接生效；「去处理 →」与点击整条行为一致；
3. 周报生成卡片显示「需要你确认」（shilu = 当前用户）；发布准备卡片显示「需要 luyu 填写」；
4. 通知列表 foot 显示对应处理人；
5. 手动触发带「运行中需要人工确认」的任务 → 中点暂停产生的新卡片/新通知同样带处理人（loomweb 项目负责人 = shilu）；
6. 已在项目详情其他 tab / 已在「任务」segment 时点击通知，均能正确切到「待人工处理」并定位；
7. `npm run build` 通过。
