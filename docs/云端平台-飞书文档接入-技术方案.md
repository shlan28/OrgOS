# 云端平台 · 飞书文档接入 - 技术方案

> 创建日期：2026-10-23
> 归属：`docs/云端Agent协作平台-总体技术方案.md` 第 5 章（项目上下文）的替代方案
> 决策：**取消自建文档功能，飞书云文档作为文档唯一真相源**

## 1. 背景与结论

原方案的「文档」子 tab 是一个自建文档库（`DocLibrary`：本地目录树 + markdown 文档），与「项目知识库」结构重叠，且需要自建存储、版本、权限、协同编辑。现改为直接接入飞书文档：

- **所有文档存飞书**，系统内不再维护独立文档仓库；
- **本地可临时编辑**，但最终必须发布回飞书；
- **Office 文件（docx / xlsx / pptx / pdf）与普通文档同列**，不单独做页面，预览与编辑都交给飞书；
- 每项目对应**一个飞书云文档文件夹**；
- 项目规范（`specs` tab）**不在本次范围**，仍按原设计跟随代码仓库或本地。

### 1.1 范围

| 包含 | 不包含 |
|---|---|
| 文档 tab（原 `project.documents`） | 项目规范 tab（`specs`，含「加入提示词」开关） |
| Office 文件（docx/xlsx/pptx/pdf）的列表、同步、索引 | 代码仓库（仍走 GitLab/GitHub） |
| 飞书文档的本地草稿编辑与发布 | Agent 运行产物（日志、截图、构建包） |
| 飞书文档快照进入 RAG 索引 | 飞书多维表格 / 电子表格的在线编辑（只读 + 跳转） |
| **项目知识库**：同一批文档的 RAG 索引视图 | |

> 概念澄清：**项目知识库不是另一个文档库**，它是这批飞书文档的索引视图；「收录哪些」由 `index_policy` 控制，不另存一份。

### 1.2 三条原则

1. **飞书是唯一真相**：正文不在本系统存储，本地只有只读快照与草稿。
2. **本地只读快照 + 显式发布**：不做双向自动同步（Dropbox 式），避免无法解释的冲突。
3. **写操作显式**：Agent 与用户都必须通过「发布」动作写回飞书，不能直接改快照。

## 2. 组织与权限

### 2.1 容器

每个项目在飞书创建一个云文档文件夹，作为该项目的文档根：

```
飞书云空间
└── Org-OS / {项目名}          folder_token
    ├── 产品需求文档 PRD v3      docx
    ├── 发布流程说明             docx
    ├── 架构方案.xlsx            file
    └── 评审材料.pptx            file
```

- 文件夹由**服务账号（应用身份）创建并持有**，不挂在某个人的个人空间下——否则成员离职会带走全部文档。
- 项目成员按项目角色**同步为文件夹协作者**：项目负责人/管理员 = 可编辑，成员 = 可编辑或可阅读（项目设置决定），只读 = 可阅读。
- 组织层可配置「是否允许组织内通过链接查看」。

### 2.2 身份

| 用途 | 身份 | 原因 |
|---|---|---|
| 后台同步、索引、创建文件夹 | `tenant_access_token`（应用身份） | 不依赖个人在线，不会因某人离职中断 |
| 用户主动编辑/发布 | `user_access_token`（OAuth） | 保留真实操作人，继承用户自己的权限边界 |
| 定时对账 | 应用身份 | 只读 |

- 两种 token 都加密存储，`user_access_token` 按用户存取并处理刷新。
- 应用需要的权限范围（以开放平台当前 scope 命名为准）：云文档读写、云空间文件读写、权限成员管理、事件订阅。

### 2.3 越权防护

- 每次调用前校验「用户 → 项目 → 文档」关系，不依赖飞书侧权限兜底；
- 飞书侧权限作为第二道防线；
- 所有文档的创建、发布、分享记录 `audit_logs`。

## 3. 数据模型

```sql
-- 组织级飞书应用配置
feishu_integrations(
  id uuid pk, org_id fk,
  app_id text not null, app_secret_ref text not null,
  region text not null default 'feishu',   -- feishu | lark
  status text not null default 'active',
  created_at, unique(org_id))

-- 项目 ↔ 飞书文件夹（一项目一文件夹）
project_feishu_folders(
  project_id uuid pk fk,
  folder_token text not null,
  folder_url text,
  sync_mode text not null default 'manual',  -- manual | webhook
  created_at)

-- 统一文档登记表：飞书文档与 Office 文件都登记在这里
documents(
  id uuid pk, project_id fk,
  origin text not null default 'feishu',     -- feishu_doc | feishu_file
  external_token text not null,              -- doc_token 或 file_token
  external_type text,                        -- docx | xlsx | pptx | pdf | doc | ...
  title text not null,
  url text,
  parent_path text,                          -- 文件夹内路径（展示用）
  size_bytes bigint,
  revision text,                             -- 飞书侧版本/更新时间标识
  content_hash text,                         -- 快照内容 hash
  sync_status text not null default 'pending', -- pending | synced | failed | deleted
  sync_error text,
  last_synced_at timestamptz,
  indexed_revision text,                     -- 已索引的 revision
  index_policy text not null default 'auto', -- auto | manual | off
  index_status text not null default 'pending',
  deleted_at timestamptz,
  unique(project_id, origin, external_token))

-- 本地草稿：只对可解析为 markdown 的文本文档开放
doc_drafts(
  id uuid pk, document_id fk, user_id fk null,
  base_revision text, base_hash text,        -- 拉取时飞书状态，用于冲突检测
  content_md text not null,
  status text not null default 'draft',      -- draft | publishing | conflict | published
  created_at, updated_at,
  unique(document_id, user_id))

-- 同步事件：审计与增量依据
doc_sync_events(
  id bigserial pk, document_id fk,
  type text not null,                        -- created | updated | moved | deleted | published
  payload jsonb, created_at)

-- chunks 复用 P3 的表，document_id 指向本表
```

## 4. 同步

### 4.1 拉取

| 触发 | 说明 |
|---|---|
| 定时轮询（默认 5 分钟） | 遍历项目文件夹，比对 `revision` / 更新时间 |
| 事件订阅（可选） | 云文档编辑事件，收到后立即拉取；**以开放平台当前支持的事件为准**，事件缺失时由轮询兜底 |
| 手动刷新 | 文档列表与详情页的「重新同步」 |
| 首次绑定 | 全量拉取文件夹内文件 |

- 增量判定：`revision` 或 `content_hash` 变化才更新，避免无意义重索引；
- 删除：文件从文件夹消失 → `deleted_at` + 清理 chunks；
- 移动 / 重命名：更新 `parent_path` / `title`，不重建文档；
- 限流：按组织做队列与退避，单文档失败不影响整批。

### 4.2 快照

- 文本文档：拉 blocks → 转 markdown → 存对象存储 `snapshot/{document_id}/{revision}.md`；
- Office：通过导出任务拿到可解析格式（docx/xlsx/pdf）→ 解析文本 → 存快照；
- 快照是**只读**的，用于 RAG、diff、本地镜像；正文真相仍在飞书。

## 5. 编辑与发布

### 5.1 两种编辑方式

| 方式 | 适用 | 说明 |
|---|---|---|
| **在飞书中编辑**（默认） | 所有文档 | 点「在飞书中打开」，跳转飞书；保真度最高，无冲突问题 |
| **本地临时编辑** | 纯文本文档（标题/段落/列表/代码/引用/表格） | 拉取快照 → 本地草稿 → 显式发布 |

Office 文件**不提供本地编辑**：只能预览与跳转飞书。原因是要保持格式与公式，本地 markdown 往返一定会丢。

### 5.2 本地草稿的生命周期

```
打开文档
  → 拉取最新 revision + 快照（base_revision / base_hash）
  → 生成/恢复本地草稿
  → 用户编辑（自动保存草稿，不写飞书）
  → 点「发布」
      → 重新拉取当前 revision
      → 与 base_revision 比较
          ├─ 一致：转换为 blocks，批量更新，写入新 revision
          └─ 不一致：三方比较（base / 本地 / 远端）
                ├─ 无重叠：自动合并后发布
                └─ 有重叠：标记 conflict，展示差异，由用户选择保留哪边
```

草稿只存在本系统，飞书侧看不到；关闭页面不丢失。

### 5.3 markdown ↔ 飞书 blocks

v1 支持子集：

| markdown | 飞书 block |
|---|---|
| `#` ~ `######` | heading1–6 |
| 段落 | text |
| `-` / `1.` | bullet / ordered |
| ``` ``` ``` | code（带语言） |
| `>` | quote |
| `---` | divider |
| 表格 | table（简单表格） |

**不支持的块**（图片、提及、嵌入表格、callout、多维表格等）会导致整篇文档退化为「仅飞书编辑」：UI 显示「此文档包含复杂内容，请在飞书中编辑」，避免发布时被清空。

### 5.4 发布策略

- **按块更新而非整篇覆盖**：先做块级 diff，只更新变化块，保留未改动的复杂块与媒体 token；
- 大文档分批提交，失败可重试（幂等：以块 id 为键）；
- 发布成功后更新 `revision` / `content_hash` 并触发重索引；
- 发布失败保留草稿与错误原因，不丢内容。

## 6. Office 文件

| 类型 | 列表 | 预览 | 编辑 | RAG |
|---|---|---|---|---|
| docx | 同列 | 飞书预览 / 本地导出的 PDF | 飞书 | 导出 → 解析 |
| xlsx | 同列 | 飞书预览 | 飞书 | 导出 → 按 sheet 切分 |
| pptx | 同列 | 飞书预览 | 飞书 | 导出 PDF → 按页切分 |
| pdf | 同列 | 飞书预览 | 飞书（批注） | 文本层 / OCR |

- **没有独立的 Office 页面**：它们在文档列表里就是普通行，只是图标与操作不同；
- 上传新文件 = 上传到项目飞书文件夹 → 同步任务登记 → 生成快照 → 索引；
- 本地不保留原件，对象存储只放快照与预览产物。

## 7. Agent 接入

### 7.1 工具

```ts
list_docs({ folder?: string, query?: string })
read_doc({ documentId, range? })
create_doc({ title, contentMd, folder? })
update_doc({ documentId, contentMd, baseRevision? })
search_knowledge({ query, ... })   // 复用 P3
```

- Agent 创建/更新文档走工具，**不直接调用飞书 API**（凭证只在服务端）；
- `update_doc` 必须带 `baseRevision`，冲突返回冲突详情而不是覆盖；
- 所有写操作记录 `doc_sync_events` 与审计日志。

### 7.2 本地镜像

```
workspace/.feishu-mirror/{document_id}.md    # 只读，随同步刷新
workspace/.feishu-mirror/index.json          # token / 标题 / 路径 / revision
```

- 目的：让 Agent 能用 `grep` / `read` 快速查阅，避免每次都走工具；
- **只读**：写入落在草稿，不直接改镜像；
- 镜像可随时删除重建，不是真相源。

### 7.3 与「写入边界」的关系

原方案里「文档写 `project-docs/`」的规则作废。文档不再有本地写入目录：

| 产物 | 新规则 |
|---|---|
| 文档 / Office | 通过工具发布到飞书；本地只有 `.feishu-mirror/`（只读）与草稿 |
| 代码 | 仍写代码仓库（有仓库时）或 `scratch/` |
| 一次性脚本 | `scratch/` |
| Agent 产物（截图、构建包、日志） | 对象存储，不进飞书 |

## 8. RAG 索引

- **索引源**：飞书文档快照（不是本地文件）；
- **「项目知识库」子 tab 就是这条管道的前端视图**：展示收录范围、索引状态与检索测试，不另存一份文档；
- 文档模式与代码模式不再影响文档索引——所有文档都在飞书；
- 版本对齐：`indexed_revision` 与 `documents.revision` 比较，落后即标记「待更新」；
- 引用格式：`飞书 · {标题} · {文件夹路径} · revision {n}`，附文档 URL；
- 草稿**不索引**，避免半成品进入检索；
- 删除 / 移动同步到 chunks（级联删除 / 更新路径）。

- 列表 = `documents` 中 `index_policy != 'off'` 的文档，显示切分数、索引状态、最近同步；
- 操作：加入 / 移出知识库（切换 `index_policy`）、重建索引、检索测试；
- 不提供文档新建 / 编辑 / 删除——那些在「文档」子 tab 或飞书里完成。

## 10. 失败与降级

| 场景 | 表现 | 处理 |
|---|---|---|
| token 过期 | 同步失败 | 静默刷新；失败提示重新授权 |
| 权限不足 | 单文档失败 | 提示缺少文档权限；其余文档继续 |
| 限流 | 队列积压 | 指数退避；UI 显示「同步中」 |
| 文档被删除 | 列表消失 | 软删 + 清理 chunks，保留审计 |
| 复杂块无法转换 | 文档标记「仅飞书编辑」 | 禁用本地编辑入口 |
| 飞书不可用 | 无法同步/发布 | 本地快照仍可读与检索（标注可能过期） |

## 11. 安全

1. `app_secret` 与 `user_access_token` 用 KMS / Secret Manager 加密，不落日志；
2. 应用 scope 最小化，不申请通讯录等无关权限；
3. 文档访问必须经过「项目 → 用户」鉴权，不能只凭 token 直连；
4. 发布操作记录操作人、时间、diff 摘要；
5. 禁止把飞书 token 注入 Agent 容器。

## 13. 验收标准

| 项 | 目标 |
|---|---|
| 同步时效 | 飞书变更后 ≤ 5 分钟出现在列表（轮询模式） |
| 同步成功率 | ≥ 99%，失败可见可重试 |
| 发布冲突 | 100% 检测到并阻止静默覆盖 |
| 发布保真 | 支持的块类型往返无损；不支持的块阻止本地编辑 |
| 越权 | 非项目成员无法通过任何接口读取文档快照 |
| 索引一致性 | `indexed_revision = revision` 的文档 ≥ 99% |
| Office | 四类文件均可列出、预览跳转、进入索引 |

## 14. 风险

| 风险 | 对策 |
|---|---|
| 飞书 API 变更 / 限流 | 适配层隔离；版本化调用；退避与熔断 |
| 权限模型不匹配（组织架构 vs 项目成员） | 以项目成员为准显式同步协作者，定期对账 |
| markdown 往返丢格式 | 只对纯文本文档开放；块级更新；复杂块禁止 |
| 文档规模增长 | 分页、增量同步、索引按 revision |
| 单点依赖飞书 | 本地快照保证只读可用；关键内容可导出备份 |
| 应用身份创建的文档归属感弱 | 文件夹固定为项目；UI 明确「由 Org-OS 创建」 |

## 15. 与总体方案的衔接

- 取代 §5.7「知识库 = 本地文档」与 §5.8/§5.9 中「文档写 `project-docs/`」的规则；
- **项目规范**（`specs` tab）不受影响，仍按代码模式落在仓库 `docs/` 或本地；
- **文档模式 / 代码模式** 退化为只决定代码落点；文档落点恒为飞书；
- P3 的索引管道复用，仅替换「索引源」为飞书快照；
- `documents` 表替代原 `files(kind='kb')` 的文档部分，`chunks.document_id` 指向它。
