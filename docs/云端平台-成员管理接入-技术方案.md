# 设置页 · 成员管理接入真实后端 - 技术方案

> 创建日期：2026-10-24
> 状态：待实施
> 约束：**前端样式完全保留**，只替换数据来源与交互逻辑；不新增/修改现有 CSS 类

## 1. 目标与范围

把「设置 → 成员管理」从纯前端 Mock 改为真实后端：

| 内容 | 现状 | 改后 |
|---|---|---|
| 组织成员列表 | `settings.ts` 里的 `OrgMemberData.orgMembers` 常量 | `org_members` 表 |
| 移除成员 | 仅改本地 state | `DELETE /api/org/members/:id`，后端保护唯一所有者 |
| 从飞书导入成员 | `FEISHU_CONTACTS` 常量 + 1000ms 假延时 | 后端拉取飞书通讯录 + 批量写入 |
| 企业授权 | `UserSettings.feishu.appId/appSecret`（本地 state） | 后端加密存储 + 真实 `tenant_access_token` 校验 |
| 个人授权 | 800ms 假授权 | 后端持久化授权状态（OAuth 流程本身仍是占位，见 §7） |

不包含：真实的飞书 OAuth 回调、按部门树分页选择、邀请链接/邮箱邀请（已在上一版移除）。

## 3. 数据模型

```sql
org_members(
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,
  role        TEXT NOT NULL DEFAULT '',   -- 职位
  permission  TEXT NOT NULL DEFAULT '成员', -- 所有者 | 管理员 | 成员
  online      INTEGER NOT NULL DEFAULT 0,
  last_active TEXT NOT NULL DEFAULT '活跃于 刚刚',
  source      TEXT NOT NULL DEFAULT 'manual', -- manual | feishu
  created_at  TEXT NOT NULL,
  UNIQUE(name)
)

org_settings(
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
)
```

`org_settings` 存：

- `current_user_name` / `current_user_permission`（登录身份）
- `feishu_connected` / `feishu_connected_at`
- `feishu_authorized` / `feishu_account` / `feishu_authorized_at`

`admin_account`（单行）：

```sql
admin_account(id INTEGER PRIMARY KEY CHECK (id = 1),
              username TEXT, password_hash TEXT, created_at TEXT)
```

密码使用 Node `crypto.scryptSync` 加盐哈希，登录时 `timingSafeEqual` 比对。

飞书凭证不进 SQLite：`server/data/secrets.json` 增加

```json
{ "feishu": { "appId": "cli_xxx", "appSecret": "..." } }
```

接口只返回 `appId` 与 `hasSecret`，**永不下发明文 Secret**。

### 3.1 登录方式（账号 + 飞书扫码）

登录页两个入口：

| 入口 | 说明 |
|---|---|
| **账号登录** | 管理员账号 + 密码；首次启动时在登录页「创建管理员并登录」完成初始化 |
| **飞书登录** | 跳转飞书授权页扫码；需要应用凭证、网页应用登录权限与 `FEISHU_REDIRECT_URI` |

- 登录身份与成员名单分开：登录身份记录在 `org_settings`（`current_user_*`），不写入 `org_members`
- 管理员账号存 `admin_account` 表：`username` + `password_hash`（scrypt 加盐哈希），不存明文
- 退出登录在**左下角用户菜单**；退出后回到登录页
- 飞书登录未配置时，登录页显示配置提示且按钮禁用；配置后点击跳转飞书二维码授权页
- `org_members` 只放从飞书导入的人（+ 将来的手工添加），权限仅 管理员 / 成员

## 4. 后端接口

```
GET    /api/auth/session                     登录状态（authenticated / needsSetup / feishuConfigured）
POST   /api/auth/setup                       首次创建管理员账号并登录
POST   /api/auth/login                       管理员账号登录
POST   /api/auth/logout                      退出登录
GET    /api/auth/feishu/url                  飞书扫码登录地址（未配置返回 configured:false）
GET    /api/auth/feishu/callback             飞书 OAuth 回调（需 FEISHU_REDIRECT_URI）

GET    /api/org/session                       当前登录身份

GET    /api/org/members                       组织成员列表（仅飞书导入的名单）
POST   /api/org/members                       { name, role, permission }
PATCH  /api/org/members/:id                   { role?, permission? }
DELETE /api/org/members/:id                   唯一所有者返回 409
POST   /api/org/members/import                { permission, contacts: [{name, department, title}] }

GET    /api/org/feishu                        授权状态（appId/hasSecret/connected/authorized…）
PUT    /api/org/feishu                        { appId, appSecret? } 保存凭证（空 = 清除）
POST   /api/org/feishu/verify                 用已存凭证换 tenant_access_token，成功置 connected
POST   /api/org/feishu/authorize              记录个人授权（占位）
GET    /api/org/feishu/authorize-url          个人授权跳转地址（state=personal）
DELETE /api/org/feishu/authorize              取消个人授权（清令牌）
GET    /api/org/feishu/contacts               拉取通讯录联系人
```

### 4.1 批量导入

- 按 `name` 去重（库内已有 + 请求内重复）
- 权限取请求里的 `permission`（成员 / 管理员）
- 返回 `{ imported: n, skipped: n }`

### 4.2 权限校验

- 移除成员、导入成员、保存/清除企业凭证、校验授权、拉取通讯录：要求当前登录身份为所有者，否则 403
- 名单成员的权限只能是 管理员 / 成员；所有者是登录身份，不占名单
- 未登录由 App 登录页整体拦截，成员管理不渲染
- 非所有者登录后：导入按钮、凭证输入与保存、成员移除按钮均为禁用态

## 5. 飞书集成

### 5.1 企业授权校验

```
POST https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal
body: { app_id, app_secret }
```

- 成功 → `code === 0`，保存 token 到内存（不落盘），置 `feishu_connected=1`
- 失败 → 返回飞书原始错误信息，`connected` 保持 false

### 5.2 通讯录拉取

1. 用 tenant token 查根部门下成员：
   `GET /open-apis/contact/v3/users/find_by_department?department_id=0&page_size=50&department_id_type=open_department_id&user_id_type=open_id`
2. 分页最多取 5 页（250 人），避免大组织拖垮请求
3. 映射：`name`、`department`（取 `department_ids[0]` 或「飞书通讯录」）、`title`（职位，空则「成员」）
4. 12s 超时、响应上限 2MB；错误原文透传

没有凭证 → 400「请先完成企业授权」。

### 5.3 个人授权（真实 OAuth）

- 「去授权」跳转飞书授权页（`state=personal`，复用同一回调地址 `/api/auth/feishu/callback`）
- 回调换取 `user_access_token` 与用户信息，存入 `secrets.json` 的 `feishuUser`（0600，永不下发前端）
- 同步记录 `feishu_authorized` / `feishu_account` / `feishu_authorized_at`
- 「取消授权」清除令牌与授权状态
- 个人授权不依赖所有者身份，任意已登录用户都可完成
- **令牌刷新尚未实现**：access_token 约 2 小时过期，过期后需重新授权（后续接 refresh_token）

## 6. 前端改造（样式不变）

### 6.1 InviteMembersPanel

数据改为组件内部通过 `orgApi` 加载，移除 `settings` / `org` props：

- `members`、`feishu`、`user`、`loading`、`error` 状态
- 成员管理不再包含登录/退出：登录由 App 层登录页负责，退出在左下角用户菜单

- 成员、导入、授权状态全部走 API，页面无本地 Mock
- 移除成员：调用 API → 重新拉取 → 刷新列表
- 导入弹窗打开时拉取通讯录；列表区复用 `.fs-list`，在加载/失败时显示占位文案（不新增类）

- 「我」徽标与 `isOwner` 按**登录身份**判断，不再依赖写死的 `CURRENT_USER` 做权限

### 6.2 FeishuPanel

- `CorpAuthPane`：props 改为 `feishu` + `onSave` + `onVerify`；保存调用 `PUT /api/org/feishu` 后自动 `verify`；状态行文案与类名不变
- `UserAuthPane`：props 改为 `feishu` + `onAuthorize` + `onUnauthorize`；去掉 800ms 假延时，改为请求期间的禁用态

### 6.3 App / SettingsPage

- 删除 `orgData` state 与 `handleUpdateOrg`
- `SettingsPage` 不再接收 `org` / `onUpdateOrg`
- `InviteMembersPanel` 不再接收 `settings` / `onUpdateSettings`（飞书授权状态也从后端读）
- **保留** `UserSettings.feishu`：文档导入弹窗仍在用，本次不动（后续单独迁移）

## 7. 权限与边界

| 操作 | 规则 |
|---|---|
| 查看成员 | 登录用户 |
| 首次初始化 | 无管理员账号时在登录页创建（用户名 + 密码） |
| 账号登录 | 管理员用户名 / 密码；scrypt 哈希校验 |
| 飞书登录 | 扫码授权；需配置 `FEISHU_REDIRECT_URI` 与网页应用登录权限 |
| 移除成员 | 仅所有者；后端 403 兜底 |
| 导入成员 | 仅所有者；后端 403 兜底 |
| 保存/清除企业凭证 | 仅所有者；Secret 只写不读 |
| 唯一索引 | `name` 唯一，导入自动跳过重复 |
| 名单权限 | 仅 管理员 / 成员；所有者只存在于登录身份 |

## 10. 风险与后续

| 风险 | 说明 |
|---|---|
| 飞书应用权限不足 | 通讯录接口需要 `contact:user.base:readonly` 等权限，错误会原样提示 |
| 个人授权仍是占位 | 真实 OAuth 需回调与前端路由，后续接入时接口不变 |
| 文档导入仍用旧 `UserSettings.feishu` | 两处授权状态暂时并存，后续统一到 `org_settings` |
| 成员无分页 | 当前组织规模小，一次全量返回 |
