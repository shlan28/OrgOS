# 「项目中心-记忆」新增「自动反思规则」- 技术方案

> 创建日期：2026-08-31
> 更新日期：2026-08-31

## 1. 背景与目标

「项目中心 → 项目详情 → 知识记忆 → 记忆」段的记忆治理目前只有一种**时间规则**：

- **记忆保留策略**：按天设定保留期（`retentionDays`）+ 永久保留 + 过期策略（自动归档/自动删除/仅提醒）——纯**到期驱动**，不看内容。

问题：有些记忆虽然没到期，但内容已过时（如引用已废弃的方案、与最新规范冲突）；有些记忆虽然临近到期，但仍是当前有效的关键经验。时间规则无法区分。

本次需求：新增第二种治理规则——**自动反思规则**：AI 定期根据**项目里的内容**（项目规范、知识库文档、近期会话）自动整理记忆，判断哪些需要**归档**、哪些**保持活跃**，与时间规则互补（时间规则兜底，反思规则智能化）。

## 2. 交互设计

遵循现有 Settings 极简风格与「点击行展开行内编辑区」的统一编辑范式（与「收集记忆规则」「记忆保留策略」行一致）。

### 2.1 设置区新增一行（位于「记忆保留策略」行之后）

```
┌──────────────────────────────────────────────────┐
│ 自动从会话收集记忆                        (●─) 开 │
├──────────────────────────────────────────────────┤
│ 收集记忆规则                                ⌃     │
│     只收集代码规范与架构决策相关要点……             │
├──────────────────────────────────────────────────┤
│ 记忆保留策略（时间规则）                     ⌃     │
│     保留 90 天 · 过期自动归档                      │
├──────────────────────────────────────────────────┤
│ 自动反思规则                                ⌃     │  ← 新增行
│     已开启 · 每周反思 · AI 根据项目内容判断        │
│     归档与活跃                                    │
└──────────────────────────────────────────────────┘
```

- **行结构**：左侧 = 「自动反思规则」（主文案 13.5px）+ 当前摘要（次级 12px 灰，单行省略）；右侧 = 展开箭头（⌃，展开时旋转 180°）；
- **位置**：「记忆保留策略」之后——先时间规则、后智能规则，治理手段从基础到进阶排列；
- **摘要文案**：
  - 开启：`已开启 · 每周反思 · AI 根据项目内容判断归档与活跃`（频率联动）；
  - 关闭：`未开启 · 记忆仅按时间规则处理`。

### 2.2 点击行展开行内编辑区

```
│ 自动反思规则                                ⌄     │
│   (●─) 启用自动反思                               │
│   反思频率   [每天] [每周] [每月]                  │
│   ┌────────────────────────────────────────┐   │
│   │ （textarea，高约 64px，预填当前自定义规则，  │   │
│   │   占位：如 与当前规范冲突或引用已废弃方案的    │   │
│   │   记忆自动归档，关键链路经验保持活跃）        │   │
│   └────────────────────────────────────────┘   │
│   AI 将结合项目规范、知识库文档与近期会话，定期     │
│   评估记忆时效性：过时的自动归档，仍有效的保持活跃。 │
│                              [取消] [保存]       │
```

编辑区包含四部分：

1. **启停开关**：`Toggle` + 「启用自动反思」文案（与「自动从会话收集记忆」行的开关样式一致）；
2. **反思频率**：三选一按钮组（每天 / 每周 / 每月，选中黑底白字），互斥单选；
3. **自定义反思规则**：`textarea`（复用 `.field-input` 细边框风格，高约 64px），**可选**——空 = AI 自动判断，不强制填写（保存不禁用）；
4. **机制说明**：固定说明文案（12px 灰），让用户理解反思依据是"项目里的内容"。

操作：底部右对齐「取消」文字按钮 + 「保存」黑底按钮（与现有编辑区一致）。

### 2.3 记忆条目展示反思结果（让"归档/活跃"判断可见）

`MemoryItem` 增加可选字段 `reflectNote`（AI 反思备注）。记忆条目展开区在正文下方展示：

```
▸ 组件拆分应遵循展示/容器分离，样式跟随组件目录。
    AI 反思：与当前组件拆分规范一致，保持活跃      ← 活跃示例
    [删除记忆]

▸ 旧版埋点方案（已废弃，仅供追溯）。
    AI 反思：方案已被新埋点替代，AI 于 08-28 归档   ← 归档示例
    [删除记忆]
```

- 样式：12px 灰底圆角小条（`AI 反思：` 前缀加粗），归档/活跃结果通过文案本身区分，不加徽标（生命周期徽标已有）；
- 仅 Mock 演示：真实反思由后端异步执行后写入该字段，前端只读展示。

### 2.4 与现有规则的关系

| | 时间规则（保留策略） | 自动反思规则（新增） |
|---|---|---|
| 驱动方式 | 到期驱动（保留 N 天） | 内容驱动（AI 评估时效性） |
| 判断依据 | 创建时间 | 项目规范 / 知识库文档 / 近期会话 |
| 动作 | 归档 / 删除 / 提醒 | 归档 / 保持活跃 |
| 关系 | 兜底 | 智能化补充，两者并存互补 |

- **不做互斥切换**：两种规则并存——反思规则开启时，时间规则照常生效（反思是"提前/延后"的智能修正，不取代到期处理）；
- **不与自动收集联动禁用**：反思整理的是已有记忆（含手动添加的），与「自动从会话收集记忆」开关无依赖，始终可配置；
- **永久保留不冲突**：归档 ≠ 删除，`permanent` 只影响时间规则的删除动作。

## 3. 数据模型改动（`src/data/projects.ts`）

```ts
export interface MemorySettings {
  autoCollect: boolean
  collectRules: string
  retentionDays: number
  permanent: boolean
  expirePolicy: '自动归档' | '自动删除' | '仅提醒'
  /** 自动反思规则：AI 定期根据项目内容整理记忆 */
  autoReflect: boolean            // ← 新增：启停
  reflectFrequency: '每天' | '每周' | '每月'   // ← 新增：反思频率
  /** 自定义反思规则：空 = AI 自动判断 */
  reflectRules: string            // ← 新增
}

export interface MemoryItem {
  id: string
  content: string
  source: '会话沉淀' | '手动'
  createdAt: string
  lifecycle: '活跃' | '即将过期' | '已归档'
  remainDays?: number
  /** AI 反思备注：反思结果的归档/活跃原因说明（Mock 只读展示） */
  reflectNote?: string            // ← 新增
}
```

Mock 数据补充：

| 项目 | autoReflect | reflectFrequency | reflectRules | 记忆 reflectNote |
|---|---|---|---|---|
| loomweb | `true` | `每周` | `与当前架构规范冲突或引用已废弃方案的记忆自动归档，组件与接口约定类记忆保持活跃。` | mem1（活跃）：`与当前组件拆分规范一致，保持活跃`；mem3（已归档）：`旧版埋点方案已被新方案替代，AI 于 08-28 反思归档` |
| yigou-app | `true` | `每天` | `支付与账号安全相关记忆保持活跃，已下线渠道的处理经验自动归档。` | mem1（活跃）：`支付链路关键经验，保持活跃` |
| data-pipeline | `false` | `每周` | `''` | — |

`createEmptyProject` 默认值：`autoReflect: false, reflectFrequency: '每周', reflectRules: ''`。

## 4. 组件改动（`KnowledgePanel.tsx` / `KnowledgePanel.css`）

### 4.1 `MemorySegment` 组件

- 新增 state：`editingReflect: boolean`、`reflectDraft: MemorySettings`（展开时以当前 `memorySettings` 初始化）；
- 新增 handler：
  - `handleSaveReflect()`：写回 `autoReflect / reflectFrequency / reflectRules`（`reflectRules` trim），保存后收起；
- 渲染：在「记忆保留策略」行之后插入「自动反思规则」行（`Row` + `expandable`）：
  - 摘要：开启 `已开启 · ${reflectFrequency}反思 · AI 根据项目内容判断归档与活跃`，关闭 `未开启 · 记忆仅按时间规则处理`；
  - 展开区：开关行 + 频率按钮组 + textarea + 说明文案 + 取消/保存；
- 记忆条目展开区：`m.reflectNote` 存在时渲染 `AI 反思：{reflectNote}` 说明条。

## 5. 不改动的部分

- 「自动从会话收集记忆」开关行、「收集记忆规则」行、「记忆保留策略」行交互不变（仅行顺序上其后插入新行）；
- 记忆条目列表结构、手动添加、清理过期、删除等交互不变（展开区仅追加反思备注展示）；
- `FormModal`、`Toggle`、`SettingsRow`、`SegmentedControl` 等通用组件不改动；
- 团队知识库段与其余面板不涉及。

1. `src/data/projects.ts`：`MemorySettings` 增加 3 字段、`MemoryItem` 增加 `reflectNote`；3 个项目 Mock 数据 + `createEmptyProject` 默认值补充；

## 7. 验收标准

1. 「记忆」段设置区出现「自动反思规则」行，位于「记忆保留策略」行下方，摘要随开关/频率联动（开启显示频率与机制，关闭显示「未开启 · 记忆仅按时间规则处理」）；
2. 点击行展开编辑区：启停开关 + 频率三选一（选中态清晰、互斥）+ 自定义规则 textarea（预填、可清空）+ 机制说明 + 取消/保存；
3. 保存后摘要联动刷新；取消丢弃修改；自定义规则清空保存合法（空 = AI 自动判断）；
4. loomweb / yigou-app 记忆条目展开区显示「AI 反思：……」备注（活跃与归档两种示例）；data-pipeline 无备注；
5. 三个项目各自展示对应 Mock 配置（loomweb 每周开启、yigou-app 每天开启、data-pipeline 关闭）；
6. 视觉与现有 Settings 极简风格一致，构建通过，代码提交 commit。

## 8. 风险与说明

- 纯 Mock：反思不真实执行，`reflectNote` 为预置演示数据，刷新即还原；
- 反思频率仅前端配置展示，无定时器逻辑；
- 不做反思历史/日志列表（保持极简，后续可按需扩展）。
