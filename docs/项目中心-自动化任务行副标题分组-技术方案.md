# 「自动化任务」任务行副标题信息分组方案（含执行情况整合候选）

> 创建日期：2026-08-31
> 更新日期：2026-08-31（v2：新增执行情况整合的 3 个候选方案，待选型）
> 前置文档：`项目中心-自动化任务新建简化-技术方案.md`（副标题「模板名 · 触发方式 · 触发参数 · 运行信息」格式来源）

## 1. 需求

任务行副标题信息挤一行太混乱，已确认的调整：

1. **定时信息单独一行**（触发方式 + 触发参数）；
2. **去掉模板名**（与任务名重复）；
3. **执行情况**：可以再加一行，但**最好与右侧运行状态徽标整合**，避免两处重复表达同一件事。

现状问题：副标题第 4 段「执行中：安装依赖」与右侧徽标「● 运行中 2/4」说的是同一件事，两处都在说、两处都不完整。

## 2. 执行情况整合候选方案

### 方案 A：徽标增强（推荐）——执行情况并入右侧徽标区，副标题只留定时

```
┌──────────────────────────────────────────────────────────────┐
│ 每日构建                     [● 运行中 · 安装依赖 2/4]  (●─) 开 │
│ 定时 · 每天 08:00                                              │
└──────────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│ MR 静态检查                  [成功 · 08-26 13:42]  [运行]  (●─) 开│
│ 事件 · MR 创建时                                               │
└──────────────────────────────────────────────────────────────┘
```

- 右侧徽标从「状态 + 步骤数」增强为「状态 + 关键上下文」：
  - 运行中/等待中：`● 运行中 · 安装依赖 2/4`（当前步骤名 + 进度）；
  - 已结束：`成功 · 08-26 13:42`（状态 + 结束时间）；
  - 未运行：不显示徽标（副标题定时行已足够）；
- 副标题只剩定时一行，信息各归其位、零重复；
- 改动集中在右侧徽标区，视觉重心在行尾，扫读状态最快。

### 方案 B：副标题双行——定时行 + 执行情况行，右侧徽标简化为纯状态点

```
┌──────────────────────────────────────────────────────────────┐
│ 每日构建                                        [● 运行中] (●─) 开│
│ 定时 · 每天 08:00                                               │
│ 执行中：安装依赖（2/4）                                          │
└──────────────────────────────────────────────────────────────┘
```

- 副标题两行：第 1 行定时、第 2 行执行情况（`执行中：xxx（2/4）` / `上次成功 · 08-26 13:42` / `尚未运行`）；
- 右侧徽标退化为纯状态点（不带步骤数），只做远距离扫读锚点；
- 信息全在左侧文字区，适合「按任务纵向读」的习惯；但行高变三行，列表密度下降。

### 方案 C：状态行内联——执行情况紧跟定时行，用分隔符区分语义

```
┌──────────────────────────────────────────────────────────────┐
│ 每日构建                     [● 运行中 · 安装依赖 2/4]  (●─) 开 │
│ 定时 · 每天 08:00    │    执行中：安装依赖                       │
└──────────────────────────────────────────────────────────────┘
```

- 副标题一行内用竖线分隔两段语义：左「定时」右「执行情况」；
- 右侧徽标同方案 A（增强版）；
- 行高不变（两行），但一行内仍有两段信息，只是加了视觉分隔——整合程度最低，接近现状。

## 3. 对比

| 维度 | A 徽标增强 | B 副标题双行 | C 状态行内联 |
|---|---|---|---|
| 信息重复 | 零（状态只在右侧） | 低（右侧仅状态点） | 中（右侧徽标 + 左侧文字都带状态） |
| 列表密度 | 最好（两行） | 差（三行） | 好（两行） |
| 扫读状态 | 快（行尾聚合） | 慢（要读左侧文字） | 中 |
| 改动量 | 小（徽标区） | 中（副标题 + 徽标退化） | 小 |

**推荐 A**：状态类信息天然适合行尾徽标位（macOS 设置页惯例），副标题回归「任务是什么」（定时），徽标回答「任务怎么样」（执行情况），职责清晰零重复。

## 4. 方案 A 长文案问题与重新设计（v3）

上一版「徽标区封顶 45% + 截断」的兜底被否：截断丢信息、45% 封顶让两侧都残缺，不好。

重新思考问题本质：**一行放不下两段都可能很长的文字**。那就不要在一行里硬塞——把执行情况放回副标题区（左侧纵向堆叠，天然有换行空间），右侧徽标只保留**固定短内容**（状态 + 进度数字），两侧互不挤压。

### 4.1 新结构：副标题双行 + 徽标固定短内容

```
┌────────────────────────────────────────────────────────────┐
│ 每日构建                                  [● 运行中 2/4] (●─) 开 │
│ 定时 · 每天 08:00                                            │
│ 执行中：静态代码检查与规范扫描                                  │ ← 长文案自然放这里，可换行
└────────────────────────────────────────────────────────────┘
```

- **任务名行**：任务名（ellipsis，独占左侧空间）+ 右侧徽标区（**固定短内容**：状态徽标 + `2/4` 进度数字，总宽 ≤ 120px，永不截断、永不挤压任务名）；
- **副标题第 1 行**：定时信息（`定时 · 每天 08:00`）；
- **副标题第 2 行**：执行情况（仅活动运行显示）：
  - 运行中：`执行中：{当前步骤名}`（步骤名再长也只是这一行变宽，左侧空间大，且可 `word-break` 换行）；
  - 等待确认/等待输入：`等待人工处理 · 已等待 {waitingSince}`；
  - 已结束/未运行：**不显示第 2 行**（右侧徽标 + 结束时间已足够，历史信息价值低）。

### 4.2 为什么这样更好

| 上一版（截断兜底） | 新版（纵向堆叠） |
|---|---|
| 步骤名被截成 `静态代码…`，信息丢失 | 步骤名完整展示，长则换行 |
| 徽标区 45% 封顶，与任务名互相挤压 | 徽标固定短内容，与任务名互不干扰 |
| title 补全 = 承认视觉层失败 | 视觉层直接完整 |

- 徽标里的 `2/4` 与副标题的步骤名**不重复**：徽标答「进行到第几步」，副标题答「在做什么」；
- 行高：活动运行 3 行、其余 2 行——只有正在跑的任务多一行，可接受（运行中本来就需要更多关注）。

### 4.3 徽标区内容（固定短，永不截断）

- 运行中：`● 运行中` + `2/4`（mono 数字）
- 等待确认/等待输入：`等待确认` / `等待输入`（无附加数字）
- 已结束：`成功` / `失败` / `已取消` / `已拒绝` + `· {finishedAt}`（时间短，固定格式）
- 排队中：`排队中`
- 未运行：无徽标

## 5. 实施

- 副标题第 1 行：`{triggerType} · {triggerParam}`（去掉模板名）；
- 副标题第 2 行（仅活动运行）：`执行中：{步骤名}` / `等待人工处理 · 已等待 {waitingSince}`；
- 徽标区：状态徽标（不变）+ 运行中时的 `n/m` 进度（不变）+ 已结束时追加 `· {finishedAt}`；
- 删除 `workflowNameOf` 引用与旧 `stepInfo` 拼接。

## 6. 验证

1. `npm run build` 通过；
2. Playwright：任务行副标题两行（定时 / 执行中步骤名完整）；已结束任务两行（定时 + 徽标带结束时间）；未运行任务仅定时一行无徽标。
