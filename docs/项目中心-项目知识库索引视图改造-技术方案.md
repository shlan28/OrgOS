# 项目中心 · 「项目知识库」子 tab 改为索引视图 —— 技术方案

> 创建日期：2026-10-23
> 背景：文档统一由飞书托管后，**项目知识库不再是第二个文档库**，而是同一批文档的 RAG 索引视图
> 关联：`docs/云端平台-飞书文档接入-技术方案.md`、`docs/云端平台-P3-知识库RAG实施-技术方案.md`

## 1. 目标

把「文档和知识库」tab 下的「项目知识库」子 tab，从**文档管理界面**改为**索引管理界面**：

| 现在 | 改后 |
|---|---|
| 与「文档」子 tab 完全相同的文档库（目录树 + 文档列表 + 导入/编辑/删除） | 同一批文档的**收录范围 + 索引状态 + 检索测试** |
| 数据源 `project.knowledge.folders/docs`（另一套文档） | 数据源 `project.documents`（与「文档」子 tab 同一份） |
| 可以新建/编辑/删除文档 | **不能**增删改文档，只能加入/移出知识库、重建索引 |

一句话：**「文档」管来源，「项目知识库」管索引。**

## 2. 现状与问题

| # | 现状 | 问题 |
|---|---|---|
| 1 | `KnowledgePanel` 的两个子 tab 都渲染 `DocLibraryView` | 知识库只是换了一套数据，语义上仍是「另一个文档库」 |
| 2 | 知识库有独立的 folders/docs | 用户要在两处维护文档，内容容易分叉 |
| 3 | 没有索引状态 | 无法知道哪些文档进入了检索、切了多少片、是否过期 |
| 4 | 没有检索入口 | 无法验证「知识库到底好不好用」 |

## 4. 状态模型

```ts
type IndexStatus =
  | 'off'        // 未收录
  | 'pending'    // 已收录，等待索引
  | 'indexing'   // 索引中
  | 'indexed'    // 已索引
  | 'stale'      // 文档已更新，索引过期
  | 'failed'     // 索引失败
```

| 状态 | 徽标文案 | 颜色 | 可执行操作 |
|---|---|---|---|
| `off` | 未收录 | 中性灰 | 加入知识库 |
| `pending` | 待索引 | 信息蓝 | 立即索引 |
| `indexing` | 索引中 | 信息蓝 + 动效 | 禁用 |
| `indexed` | 已索引 | 成功绿 | 重建 / 移出 |
| `stale` | 待更新 | 警告橙 | 重建 |
| `failed` | 失败 | 危险红 | 重试 / 查看原因 |

状态流转：

```
off ──开启开关──▶ pending ──自动──▶ indexing ──成功──▶ indexed
                                      └──失败──▶ failed ──重试──▶ indexing
indexed ──文档更新──▶ stale ──重建──▶ indexing
indexed/failed/stale ──关闭开关──▶ off（清空 chunkCount）
```

## 5. 数据模型（Mock）

### 5.1 `KbDoc` 增加索引字段

```ts
export interface KbDoc {
  // …现有字段不变
  /** 是否收录进知识库 */
  indexPolicy?: 'auto' | 'manual' | 'off'
  /** 索引状态（缺省按 off 处理） */
  indexStatus?: IndexStatus
  /** 切分片段数 */
  chunkCount?: number
  /** 最近索引时间（MM-DD HH:mm） */
  indexedAt?: string
  /** 失败原因 */
  indexError?: string
}
```

## 7. 交互细则

### 7.1 加入 / 移出知识库

- 开关开启：`indexPolicy='auto'`，`indexStatus='pending'` → 800ms 后 `indexing` → 1.2s 后 `indexed`，按正文长度生成 `chunkCount`（`ceil(markdown.length / 120)`，最小 1），记录 `indexedAt`；
- 开关关闭：二次确认（「移出后该文档不再参与检索，文档本身不会被删除」）→ `indexPolicy='off'`、`indexStatus='off'`、`chunkCount=0`。

### 7.2 重建索引

- 详情页或行内 ⋯ 菜单触发；
- `indexing` 状态下禁用；
- 成功后刷新 `indexedAt` 与 `chunkCount`；
- 失败时写入 `indexError`，行内显示失败原因 tooltip。

### 7.3 筛选与搜索

- 筛选：全部 / 已收录 / 未收录 / 需处理（`stale` + `failed`）；
- 搜索：按标题与文件夹路径匹配，不区分大小写；
- 筛选与搜索叠加；目录树选择与筛选叠加；
- 列表头部显示当前结果数「共 N 篇」。

### 7.4 批量操作

「⋯」菜单：

- **全部加入知识库**：把所有 `off` 的文档置为 `pending` 并依次索引；
- **全部重建索引**：确认后对所有 `indexed/stale/failed` 执行重建。

批量时顶部统计条显示「索引中 N 篇」，全部完成后自动消失。

### 7.5 空态

| 场景 | 文案 |
|---|---|
| 项目没有任何文档 | 「还没有文档。先去「文档」子 tab 添加，或从飞书同步。」 |
| 有文档但全部未收录 | 「当前没有文档加入知识库。打开右侧开关即可开始索引。」 |
| 筛选结果为空 | 「没有符合条件的文档。」 |
| 检索测试无结果 | 「没有命中片段，试试更具体的关键词。」 |

## 8. 统计口径

| 指标 | 口径 |
|---|---|
| 收录 N / M | `indexPolicy !== 'off'` 的文档数 / 全部文档数（**全局**，不受筛选影响） |
| 已索引 | `indexStatus === 'indexed'` |
| 索引中 | `indexing` + `pending` |
| 失败 | `failed` |
| 待更新 | `stale` |
| 片段 | 所有 `chunkCount` 之和（仅已索引文档） |

统计条固定显示全局数字，筛选只影响右侧列表——避免用户误读。

## 9. 样式约束

- 与现有面板一致：浅色、圆角卡片、细分割线、字号层级沿用 `KnowledgePanel.css`；
- 状态徽标复用 `StatusBadge` 的语义色（成功/信息/警告/危险/中性）；
- 目录树复用现有 `.kb-tree` 系列类名，避免新增一套视觉；
- 索引中状态使用与 Agent CLI 呼吸点一致的轻微动效，不引入新的动画体系；
- 开关复用 `Toggle`，不新写控件。

## 10. 不做的事

- 不在知识库 tab 提供文档新建 / 导入 / 编辑 / 删除；
- 不提供目录新建 / 重命名 / 删除（目录来自文档侧）；
- 不接真实向量检索（检索测试为关键词 Mock）；
- 不做分页（文档量小，先全量渲染）；
- 不做批量勾选，批量操作只提供「全部」两种。

## 11. 验收标准

1. 「文档」与「项目知识库」两个子 tab 展示**同一批文档**；
2. 知识库 tab 无任何文档增删改入口；
3. 开关、重建、批量操作后，统计条与行状态即时更新；
4. 状态流转完整可见：未收录 → 待索引 → 索引中 → 已索引；
5. 目录树计数 = 已收录数 / 该目录文档数；
6. 筛选、搜索、目录三者叠加正确；
7. 检索测试能返回片段并跳转文档详情；
8. 空态覆盖四种场景；
9. `npm run build` 通过；Playwright 走查主路径 + 亲自读图。
