# 项目会话真实化方案

> 状态：已实现（2026-10-24）

## 1. 背景

项目详情页的「会话」目前只有聊天与 Agent CLI 接了后端（通过 `useProjectHarness` 把 mock 会话映射成后端会话），其余仍是前端假数据：

- 会话列表只存在前端 state，刷新即消失；后端已有 `sessions` 表，但前端从未调用 `runtimeApi.projectSessions`
- 新建会话不会落库（`Project.sessions` 没有对应后端字段）
- 自动化会话（每日构建 / 周报等）的消息、结果、CLI 轨迹来自 `src/data/projects.ts` + `runLogsOf`
- 聊天在拿不到真实后端时会回落到本地假回应

目标：**会话列表、创建、重命名、消息、CLI 轨迹全部以后端为准；会话里的成员与 agent 使用项目真实数据；不再保留 mock 回落。**

## 2. 数据模型（复用现有表，不新增表）

| 表 | 作用 | 关键字段 |
|---|---|---|
| `sessions` | 一次会话 | `id`、`project_id`、`agent_id`、`title`、`status`、`dsh_session_id`、`created_at`、`updated_at` |
| `turns` | 一轮用户输入 | `id`、`session_id`、`seq`、`user_content`、`status`、`error`、`created_at`、`ended_at` |
| `events` | dsh 流式事件 | `turn_id`、`session_id`、`seq`、`type`、`payload`、`created_at` |

关系：会话归属于项目（`project_id`）与一个真实 agent（`agent_id`）。agent 来自设置页 Agent 中绑定到该项目的记录，成员来自项目成员（设置页导入成员）。

## 3. 接口

已有：

- `GET /api/projects/:id/sessions` — 项目会话列表（按创建时间倒序）
- `POST /api/projects/:id/sessions` — 新建会话，body `{ agentId?, title? }`；未传 agentId 时取项目绑定的第一个 agent
- `GET /api/sessions/:id/messages` — 历史消息（由 turns + final 事件拼装）
- `POST /api/sessions/:id/turns` — 发送消息，创建 turn
- `GET /api/turns/:id/stream` — SSE 事件流（先回放已落库事件，再接实时）
- `DELETE /api/sessions/:id` — 删除会话

新增：

- `PATCH /api/sessions/:id` — 重命名会话，body `{ title }`
- `GET /api/sessions/:id/events` — 会话全部事件（按 turn.seq、event.seq 排序），用于刷新页面后回放 Agent CLI 轨迹

## 4. 前端改造

### 4.1 ProjectDetail：会话数据所有权

- 新增 `sessions: RuntimeSession[]` 状态，挂载时调用 `runtimeApi.projectSessions(project.id)`
- 当前会话 `activeSessionId` 默认取列表第一条；切换项目时重新加载
- 「＋ 新会话」调用 `runtimeApi.createProjectSession(project.id, { agentId, title })`，成功后插入列表并选中
- 会话改名调用 `runtimeApi.updateSession`
- 用 `useRealSession(activeSession.id)` 统一提供消息、事件行、busy、错误、发送
- 不再使用 `project.sessions`（mock），不再使用 `useProjectHarness`

### 4.2 SessionRail（格 1）

- 数据源改为 `RuntimeSession[]`：标题、状态（运行中/空闲）、所属 agent、最近更新时间
- 项目有多个 agent 时，头部提供「新会话 agent」下拉，选项为项目真实绑定的 agent
- 项目没有 agent 时禁用「＋」，提示先到编辑项目里添加 agent
- 去掉自动化会话标记、未读数、mock 排序权重

### 4.3 ChatPane（格 2）

- 只渲染真实消息：`useRealSession` 的 messages → `RunMessage` 视图模型
- 说话人使用真实身份：用户 = 当前登录用户；Agent = 该会话绑定的 agent 名称与颜色
- 发送直达后端；busy 时禁用；后端错误就地展示
- 删除本地假回应（定时器）、auto 任务联动、`ADE_SENDER` 回落
- @ 提及候选项继续使用项目真实成员 + 真实 agent
- 会话改名写后端

### 4.4 TerminalPane（格 3）

- 只渲染真实事件行（`useRealSession` 的 lines）
- 头部展示会话名 + 所属 agent + 运行指示
- 删除 `runLogsOf` 派生的 mock 轨迹、按 agent 分桶的多个 tab；一个会话只对应一个 agent

### 4.5 useRealSession：历史事件回放

- 切换会话时并行拉取 `messages` 与 `events`
- 历史事件经 `toLine` 转成终端行，key 使用 `turnId:seq` 保证稳定
- 新 turn 继续走 SSE 追加，结束后刷新消息并触发会话列表刷新（状态、updatedAt）

## 5. 兼容与边界

- 旧 `external_ref` 映射会话（`project_id` 为空）不会出现在项目会话列表里，不做迁移
- 工作流 / 自动化任务仍为前端 Mock，但不再生成会话，也不在会话列表展示；工作流检查器里的「在左栏打开本步骤会话」入口隐藏
- 会话的成员抽屉继续读取项目真实成员与真实 agent
- 后端不可用时展示错误，不回退到 mock 数据

## 7. 运行时状态与身份（实现补充）

### 7.1 Agent 状态由后端派生

- `GET /api/agents` 返回的 `status` / `currentTask` 来自 `sessions.status = 'running'`：
  - 有运行中会话 → `工作中`，`currentTask` = 最近运行中会话标题
  - 否则 → `空闲`
- `config_json.status / currentTask` 不再作为数据源，也不再写入
- 前端刷新时机：进入项目、发送消息（busy 开始）、turn 结束、打开设置页

### 7.2 会话内用户身份

- 消息发送者、输入框头像、成员抽屉「我」标识统一使用当前登录用户（`authUser.name`）
- 不再使用 `src/data/projects.ts` 中写死的 `CURRENT_USER`（shilu）
- Agent 消息的说话人取会话绑定的真实 agent（名称 / 首字母 / 配色）

## 8. 验收标准

1. 新建会话后刷新页面，会话仍在列表中，消息历史完整
2. 发送消息后聊天与 CLI 都是真实内容，刷新页面后 CLI 能回放历史事件
3. 会话列表显示真实 agent 名称与状态，新建会话可选择项目内 agent
4. 重命名会话后刷新仍生效
5. 项目内不再出现「每日构建 · 单元测试」等 mock 会话
6. 项目没有 agent 时无法新建会话并给出提示
7. 发送消息时对应 agent 显示「工作中」，结束后回到「空闲」
8. 会话内发送者显示当前登录用户，而不是写死的 shilu
9. `tsc -b` 通过，控制台无报错

## 9. 不在本期范围

- 会话删除入口（接口已具备，UI 后续再补）
- 消息分页、附件、多 agent 同会话协作
