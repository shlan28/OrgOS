# 「项目中心 - 自动化统计」技术方案

> 创建日期：2026-08-28
> 更新日期：2026-08-31（导航项由「能效看板」更名为「自动化统计」，顺序调整至「自动化任务」下方）

## 1. 背景与目标

在 `loom-ui-mock` 的「项目中心 → 项目详情 → 自动化统计」tab 中，将现有"敬请期待"占位面板替换为**基于自动化任务数据的自动化统计面板**，聚焦三大核心维度：

1. **任务规模**：任务总数 / 启用情况 / 触发类型分布
2. **执行运行**：执行次数趋势、成功率、平均耗时与 P90
3. **效率收益**：节省人工工时、自动化替代率、自动化 vs 人工耗时对比

约束与前提：

- 纯前端 Mock，**不接真实数据源**，所有数据本地静态生成（确定性生成，刷新不变）；
- 视觉与交互**完全遵循现有体系**：浅色 macOS 风、CSS 变量、组件级 CSS、无第三方 UI/图表库（图表用内联 SVG 手绘）；
- 遵循项目详情页 Settings 式极简风格规范（分组卡片 + 细分割线 + 大留白）。

## 2. 现状分析

| 项 | 现状 |
|---|---|
| 导航入口 | `ProjectDetail.tsx` 的 `NAV_ITEMS` 中 `efficiency` 项 `ready: false`，点击渲染 `PlaceholderPanel` |
| 自动化任务数据 | `AutoJob` 仅保留最近 3 条 `history` 运行，无长期统计序列，无法支撑趋势图 |
| 图表能力 | 工程无任何图表库；现有图标均为内联 SVG（1.5px 描边线框风） |
| 可复用组件 | `Section`/`Row`（Settings 分组）、`SegmentedControl`（分段切换）、`StatusBadge`（状态徽标）、`Toggle` |
| 设计变量 | `--border #E5E5E5`、`--text-secondary #888`、`--status-success/info/warning/danger` 系列语义色 |

**结论**：新建独立的能效 Mock 数据层（不改动 `AutoJob` 结构），新增 SVG 图表组件与 `EfficiencyPanel` 面板，`ProjectDetail` 仅改导航注册。

## 3. 总体设计

### 3.1 信息架构（面板内自上而下）

```
自动化统计                                    [近 7 天 | 近 14 天 | 近 30 天]
│
├── ① 核心指标（KPI 卡片网格 3×2）
│     任务总数(启用/停用) · 执行次数(日均) · 成功率
│     平均耗时(P90) · 节省工时(折算人天) · 自动化替代率
│
├── ② 执行趋势（SVG 双轴图：执行次数柱 + 成功率折线，hover 联动明细）
│
├── ③ 任务规模（触发类型分布横向条形：定时/事件/手动 × 执行次数占比）
│
├── ④ 效率收益（自动化 vs 人工耗时对比条形 + 替代率进度条）
│
└── ⑤ 任务明细（表格：按节省工时降序，含成功率迷你条与最近运行状态）
```

- 时间范围切换（7/14/30 天）为**全局筛选**：KPI、趋势图、分布、明细表全部联动重算；
- 面板宽度沿用详情页 720px 单列布局，图表随容器自适应（SVG viewBox 缩放）。

### 3.2 数据流

```
src/data/efficiency.ts（Mock 数据 + 聚合函数）
        │  EfficiencyPanel 传入 projectId + range
        ▼
EfficiencyPanel ── 聚合计算 KPI / 趋势 / 分布 / 明细
        │
        ├── TrendChart.tsx（SVG 双轴趋势图）
        ├── HBarChart.tsx（SVG 横向条形，触发类型分布 & 耗时对比复用）
        └── 明细表（原生 table，Settings 风格）
```

## 4. 页面设计

### 4.1 顶部：标题 + 时间范围

- 面板顶部一行：左侧灰色小字说明「自动化任务运行数据统计」（11.5px，同 `.section-label` 风格），右侧 `SegmentedControl` 三段：近 7 天 / 近 14 天 / 近 30 天（默认近 14 天）。

### 4.2 ① 核心指标（KPI 卡片）

- 网格 `repeat(auto-fill, minmax(200px, 1fr))`，白底卡片 `1px solid var(--border)`、圆角 10px、内边距 14px（与项目卡片同族，无阴影堆叠）；
- 每卡结构：灰色小标签（11.5px）+ 主数值（22px 加粗）+ 次级说明（12px 灰）：

| 标签 | 主数值 | 次级说明 |
|---|---|---|
| 自动化任务 | 8 | 启用 6 · 停用 2 |
| 执行次数 | 412 | 日均 29.4 次 |
| 成功率 | 96.4% | 失败 15 次 |
| 平均耗时 | 4.2 分钟 | P90 8.5 分钟 |
| 节省工时 | 86.5 小时 | ≈ 10.8 人天 |
| 自动化替代率 | 78% | 自动 412 / 人工 116 次 |

- 成功率 ≥ 95% 数值用 `--status-success`，90–95% 用 `--status-warning`，< 90% 用 `--status-danger`（仅数值着色，卡片底色不变）。

### 4.3 ② 执行趋势（SVG 双轴图）

- 尺寸：viewBox `680 × 220`，随容器宽度等比缩放；
- 左轴：**执行次数**（浅绿柱状 `--status-success` 60% 透明度）；右轴：**成功率**（蓝色折线 `--status-info`，范围 80–100%）；
- 网格：横向 4 条 `#F0F0F0` 细线 + 左右轴刻度文字（10.5px 灰）；
- 交互：hover 显示竖向参考线 + 浮层（日期 / 执行 / 成功 / 失败 / 成功率），浮层为白底细边框小卡片；
- 图例：图顶部右侧两枚小色点 + 文字（执行次数 / 成功率）。

### 4.4 ③ 任务规模（触发类型分布）

- Settings 分组卡片内 3 行（定时 / 事件 / 手动），每行：
  - 左：类型名（13.5px）+ 任务数徽标（`--badge-bg` 灰底）；
  - 中：横向条形（长度 = 该类型执行次数占比，绿色系填充）；
  - 右：执行次数 + 占比（13px 灰）。
- 条形复用 `HBarChart` 组件（纯 div + 百分比宽度实现，非 SVG）。

### 4.5 ④ 效率收益

分组卡片内三块：

1. **耗时对比**（双横条）：同类工作单次耗时 —— 人工预估 42 分钟（灰条）vs 自动化实际 4.2 分钟（绿条），右侧标注「效率提升约 10 倍」；
2. **自动化替代率**：横向进度条（绿）+ 文案「自动执行 412 次 / 人工操作 116 次」；
3. **节省工时**：一行式汇总「本期累计节省 86.5 小时 ≈ 10.8 人天」（数值加粗）。

### 4.6 ⑤ 任务明细表

- Settings 分组卡片内原生 table，表头灰色小字（11.5px），行高 44px，行间 `--row-divider` 细线；
- 列：任务名（主）+ 触发类型（次级/徽标）｜执行次数｜成功率（数字 + 40px 迷你条）｜平均耗时｜P90｜节省工时｜最近运行（状态徽标 + 时间）；
- 排序：按节省工时降序（体现能效主题，固定排序不做表头点击）；
- 行 hover 浅灰背景；无写操作（纯展示，不提供点击下钻——运行详情仍走「自动化任务」tab）。

### 4.7 空状态

- 项目无自动化任务（如 data-pipeline）：面板展示居中空状态——灰色线框图表图标 + 「暂无自动化任务数据」+ 次级说明「创建自动化任务后，这里将展示能效统计」（沿用 `.empty-hint` 风格）。

## 5. 数据设计（`src/data/efficiency.ts`）

### 5.1 类型定义

```ts
/** 日序列（近 30 天，前端按范围截取） */
export interface DailyStat {
  date: string        // 'MM-DD'
  runs: number        // 执行次数
  success: number     // 成功次数
  avgMinutes: number  // 当日平均耗时（分钟）
}

/** 任务级统计 */
export interface JobStat {
  jobId: string
  name: string
  triggerType: '定时' | '事件' | '手动'
  enabled: boolean
  runs: number          // 区间内执行次数（30 天口径）
  successRate: number   // %
  avgMinutes: number
  p90Minutes: number
  manualMinutes: number // 人工预估单次耗时
  lastStatus: '成功' | '失败' | '运行中' | '等待确认' | '等待输入' | '已取消' | '未运行'
  lastRunAt: string
}

export interface EfficiencyData {
  daily: DailyStat[]   // 固定 30 条
  jobs: JobStat[]
  /** 同期人工操作次数（30 天口径，替代率分母） */
  manualOps: number
}
```

### 5.2 Mock 数据策略

- **日序列**：确定性公式生成（工作日基线高 / 周末衰减 + 固定相位波动 `(i * 7) % 5`，失败率 3–5% 且个别日尖刺），**不用随机数**，保证每次渲染一致；
- **任务级**：手写字面量。loomweb 8 个任务（每日构建 / MR 静态检查 / 周报生成 / 发布准备 / 依赖漏洞扫描 / 接口回归 / 环境巡检 / 文档同步），字段与现有 `AutoJob` 命名对齐但独立维护；yigou-app 2 个任务；data-pipeline 无数据（走空状态）；
- **派生指标全部现算**（不硬编码）：KPI、分布、明细由 `daily`/`jobs` 按当前 range 聚合，保证切换范围联动一致；
- 节省工时口径：`Σ runs × (manualMinutes − avgMinutes) / 60`（小时）；替代率口径：`runs / (runs + manualOps)`。

### 5.3 聚合函数（同文件导出）

```ts
getEfficiency(projectId): EfficiencyData | null        // 按 project 取数
summarize(data, rangeDays): Kpis                        // 6 项 KPI
sliceDaily(data, rangeDays): DailyStat[]                // 趋势序列
triggerBreakdown(data, rangeDays): { type; jobs; runs }[] // 触发类型分布
jobRows(data, rangeDays): (JobStat & { savedHours })[]   // 明细行（按 savedHours 降序）
```

## 7. 边界与约束

- 图表全部内联 SVG / div 实现，**不引入 ECharts 等第三方库**（与工程"无 UI 库依赖"原则一致）；
- 颜色仅使用现有 CSS 变量（`--status-*` 系列语义色），不新增核心设计变量；
- 面板为纯展示，无写操作、无弹窗、无路由；
- 窄容器（详情面板 720px）下图表等比缩放，表格列在极窄时隐藏 P90 列（媒体查询兜底）。

## 8. 验证方式

1. `npm run build`（含 tsc 类型检查）通过；
2. Playwright 截图验证：loomweb（数据丰富）/ yigou-app（少量数据）/ data-pipeline（空状态）三个项目 × 默认 14 天 + 切换 7/30 天；
3. 检查项：KPI 与趋势图数值联动一致、hover 浮层、分段切换、表格排序、空状态、导航选中态。
