# 「团队知识库」移除「索引」类型、统一二级页面展示 - 技术方案

> 创建日期：2026-08-28
> 更新日期：2026-08-28

## 1. 背景与目标

「项目中心 → 知识记忆 → 团队知识库」当前将文档分为两种类型：

- **索引**（说明书）：完整文档，点击进入二级页面（预览 ⇄ 编辑），由「+ 新建索引」按钮创建；
- **知识**（外部导入）：点击展开手风琴摘要，由「+ 导入」按钮创建。

本次需求（两点合并）：

1. **取消「索引」这一单独类型，去掉「+ 新建索引」入口**——不再有类型区分；
2. **「知识」文档也改为二级页面展示**——点击文档行不再展开手风琴摘要，而是进入二级页面（与原索引的二级页面同构：预览 ⇄ 编辑）。

合并后的最终形态：团队知识库为**单一文档形态**——所有文档（导入的 + 原索引转化的）点击均进入**二级页面**，支持预览与编辑。

## 2. 改动设计

### 2.1 数据模型（`src/data/projects.ts`）

`KbDoc` 调整：

```ts
/** 团队知识库文档（统一形态：二级页面预览/编辑） */
export interface KbDoc {
  id: string
  title: string
  /** 所属目录 id（目录树过滤用） */
  folderId: string
  source: '团队 wiki' | 'GitLab 文档' | '本地文件' | '手动'
  sourceRef: string
  importedAt: string
  updatedAt: string
  /** 完整文档内容（编辑区源文本） */
  markdown: string
  /** 预览渲染数据 */
  content: { heading: string; body: string }[]
  /** 摘要（列表行次级文案展示用） */
  summary: string
}
```

- **移除** `type: '索引' | '知识'`（无类型区分）；
- **保留** `markdown` / `content`（二级页面预览/编辑需要）；
- **保留** `summary`，用途从「手风琴展开内容」改为「列表行的次级文案」（一行省略展示，帮助用户在列表快速识别文档内容）。

**现有 Mock 数据处理**：

- 原两条「索引」文档（模块分布说明、目录结构说明）：保留 `markdown` / `content`，`summary` 补一句摘要；
- 原三条「知识」文档（Loom 架构设计说明、接口约定 v2、支付链路设计）：原 `summary` 保留为列表摘要，同时**补全 `markdown` / `content`**（由摘要扩写为完整文档内容，Mock 数据），使其二级页面有内容可预览/编辑。

### 2.2 组件（`KnowledgePanel.tsx` 的 `KbSegment`）

**移除**：

| 移除项 | 说明 |
|---|---|
| `creatingIndex` / `indexForm` state | 新建索引弹窗状态 |
| `handleCreateIndex` | 新建索引 handler |
| 「+ 新建索引」按钮 | 分组标题右侧只保留「+ 导入」 |
| 「新建索引」FormModal | 弹窗整体移除 |
| `expandedId` state + 手风琴展开渲染 | 「知识」行不再展开摘要 |
| 行内类型徽标（`StatusBadge`） | 无类型区分后不再展示 |
| `isIndex` 分支逻辑 | 所有文档行统一交互 |

**保留/调整**：

- **二级视图（预览 ⇄ 编辑）保留**：`openId` / `editing` / `draft` state、`handleSaveIndex` / `handleDeleteIndex` handler、预览模式与编辑模式两段渲染——原为索引专属，现所有文档共用（函数名可顺带改为 `handleSaveDoc` / `handleDeleteDoc`，语义更准确）；
- **文档行交互统一**：点击行 → `setOpenId(doc.id)` 进入二级页面预览；行右侧统一为 `ChevronRightIcon`（进入指示箭头）；
- **行次级文案**：由「来源 · 更新于」改为「摘要（一行省略）· 来源 · 更新于」——摘要前置帮助识别文档；
- **二级页面预览模式**：底部补充来源信息行（来源：团队 wiki（wiki/loom/arch）· 导入于 08-23），原手风琴里的来源信息移到这里；
- **导入逻辑**：`handleImport` 创建的文档 `summary` 仍为「（摘要生成中……）」，`markdown` / `content` 为空——二级页面预览显示「（暂无内容，点击「编辑」开始编写）」，编辑后保存正常；
- 目录树（新建/重命名/删除）、「+ 导入」弹窗不变。

### 2.3 样式（`KnowledgePanel.css`）

- 无需新增样式；kb 段手风琴展开不再使用（`.knowledge-summary` 在 memory 段仍在用，保留）；
- `ChevronDownIcon` 在 kb 段不再使用（memory 段仍用），import 保留。

### 2.4 文档更新

- `loom-ui-mock/README.md`：知识库描述改为「统一文档列表（点击进入二级页面预览 ⇄ 编辑）+ 导入弹窗」，更新日期。

## 3. 实施步骤

1. `projects.ts`：`KbDoc` 移除 `type` 字段；Mock 数据调整（索引文档补 summary、知识文档补 markdown/content）；
2. `KnowledgePanel.tsx`：移除新建索引相关 state/handler/弹窗/按钮、手风琴展开逻辑、类型徽标；统一文档行交互为进入二级页面；行次级文案加摘要；二级页面预览补来源行；
3. `README.md` 更新功能描述；
4. `npm run build` 验证；
5. 浏览器自检：列表无徽标、点击行进二级页面、预览/编辑/保存/删除正常、导入正常、目录树正常；
6. 提交 git commit。

## 4. 验收标准

1. 团队知识库文档行**无类型徽标**，次级文案为「摘要 · 来源 · 更新于」；
2. 点击任意文档行进入**二级页面**（目录树保留）：预览模式（← 返回 + 编辑 + 正文 + 底部来源行）⇄ 编辑模式（文本域 + 未保存提示 + 删除/取消/保存）；
3. 分组标题右侧只有「+ 导入」，「+ 新建索引」不存在；
4. 「+ 导入」弹窗与导入流程正常，新导入文档可进入二级页面（空内容提示）并可编辑保存；
5. 编辑保存后「更新于」刷新；删除文档后返回列表；
6. 目录树（新建/重命名/删除）不受影响；
7. 原三条「知识」文档二级页面有完整内容可预览；
8. 构建通过，代码提交 commit。

## 5. 风险与说明

- 纯 Mock 改动，无后端影响；
- 知识文档的 `markdown` / `content` 为 Mock 补写数据，模拟「导入后解析出完整文档」的效果；
- 移除「新建索引」后，知识库文档只能通过「+ 导入」新增（与真实场景一致：知识库内容来自外部沉淀）。
