# 用户设置页 · 邀请成员改为「从飞书导入成员」（与飞书授权合并）—— 技术方案

> 创建日期：2026-10-23
> 更新日期：2026-10-23（v1.2 **实施完成**：① 顶部子 tab（企业授权/个人授权）**置于面板最顶端**（SegmentedControl + 右侧弱提示）；② **个人授权 tab 只展示授权状态行**（不渲染导入成员/组织成员/凭证表单）；③ 修复三处视觉缺陷——弹窗遮罩透叠（漏 import FormModal.css）、组织成员行缺权限徽标、**FeishuPanel 漏 import 自身 css 导致 App ID/Secret 表单行与个人授权说明文字无样式**（补 import 后 19 项计算样式断言 + 读图复验 PASS）；Playwright 74 项断言 + 读图全 PASS，见第 5 节）

## 1. 需求（鹿鹿子大王）

设置页「邀请成员」：

1. 邀请方式**改为「从飞书导入成员」**（替代现有邀请链接 / 邮箱邀请）；
2. **与「飞书授权」分区合并到一起**（左导航不再单独保留「飞书授权」项）；
3. 流程：**先授权，再导入**；
4. **飞书授权区分「企业授权」「个人授权」两个子 tab**：
   - **企业授权**：填写 App ID / App Secret（tenant_access_token，读取企业通讯录）→ 成员导入的门槛；
   - **个人授权**：**不需要填 App ID / App Secret**（user_access_token，OAuth 授权即可）→ 文档导入的门槛。

## 2. 现状与差距

| 项 | 现状 | 差距 |
|---|---|---|
| 左导航 | 3 项：Agent 设置 / 邀请成员 / 飞书授权（`SettingsSection` 含 `'feishu'`） | 合并为 2 项：**Agent 设置 / 成员管理**（飞书授权并入成员管理面板） |
| InviteMembersPanel | 邀请链接（复制/有效期/权限/重置）+ 邮箱邀请（多邮箱+校验）+ 待接受邀请 + 组织成员 | 删链接/邮箱/待接受三块；新增**飞书授权区（企业/个人两子 tab）+ 从飞书导入成员**；组织成员保留 |
| FeishuPanel | 独立面板：应用凭证 + 个人授权（`UserSettings.feishu` 全局共享） | **组件保留但内部重构**：SegmentedControl 两子 tab（企业授权 = 凭证表单 + 连接状态；个人授权 = 纯 OAuth 授权行，无凭证） |
| DocLibraryView 导入弹窗 | 步骤条（1 授权 → 2 选目录）+ 凭证警示条（credReady 判定）+ [去设置] 跳 feishu 分区 | **连带简化**：个人授权无凭证门槛 → 删凭证警示条与 [去设置] 链路（四层 props 链清理）；授权卡只显示个人授权状态 |
| settings.ts | `InviteData`（link/linkExpireDays/linkPermission/pending/orgMembers）、`PendingInvite`、`generateInviteLink`/`parseEmails`/`isValidEmail`/`nowStamp` | 精简为 `OrgMemberData { orgMembers }`；删死代码；新增飞书通讯录 Mock `FEISHU_CONTACTS` |

## 3. 方案

### 3.1 设置页导航合并

```
设置页左导航（3 → 2）
  Agent 设置
  成员管理   ← 飞书授权并入（企业授权 / 个人授权两子 tab + 导入成员 + 组织成员）
```

- `SettingsSection` 类型删 `'feishu'`，仅 `'agent' | 'invite'`；
- `SettingsPage` 删 feishu 分支与导航项；
- `App.handleGoToFeishuSettings` 及其四层传递链（DocLibraryView → KnowledgePanel → ProjectDetail → App）**整体删除**（文档导入弹窗不再有凭证警示/去设置入口）。

### 3.2 成员管理面板新结构（InviteMembersPanel 重构）

```
成员管理面板
 ├─ 顶部子 tab（**置于页面最顶端**，SegmentedControl）：
 │    [🏢 企业授权] [👤 个人授权]   企业授权管成员导入 · 个人授权管文档导入
 │
 ├─ [企业授权] tab（默认）
 │    ├─ Section「应用凭证」：App ID / App Secret 表单行（Secret 密码态+显隐）
 │    │    + 操作行「企业应用凭证用于读取通讯录（tenant_access_token），导入成员需要」+ 清除/保存
 │    ├─ Section「连接状态」：未配置 = 灰徽标「未连接」；已保存 = 绿徽标「已连接 · 可读取企业通讯录 · App ID 脱敏」
 │    │    （换凭证保存自动重连，不影响个人授权）
 │    ├─ Section「从飞书导入成员」：引导行（已连接 = 蓝icon+绿点标题；未连接 = 黄icon 置灰提示）
 │    │    + [从飞书导入成员]（飞书蓝描边；未连接 disabled）→ 导入弹窗（见 3.3）
 │    └─ Section「组织成员（n）」：头像 + 姓名 +「我」徽标 + 职位·权限·活跃 + 在线点
 │         + 权限徽标（所有者灰/管理员蓝/成员灰）+ 移除（唯一所有者保护）+ 权限说明
 │
 └─ [个人授权] tab（**只展示授权内容，不含导入成员/组织成员**）
      └─ Section「个人授权」：授权状态行（飞书蓝 icon + 标题 + 徽标）：
           未授权 = [去授权]（800ms OAuth Mock）→ 已授权 = 账号 + 时间 + [取消授权]
           副文案：「个人身份授权（user_access_token）用于项目「文档」导入，无需配置应用凭证」
      + 底部说明「OAuth 登录飞书账号授权，无需配置应用凭证；与「企业授权」互不影响」
```

- 面板 props：新增 `settings: UserSettings` / `onUpdateSettings`；`invite/onUpdateInvite` 更名 `org/onUpdateOrg`。

### 3.3 导入弹窗：单步选成员（企业凭证就绪即可，无 OAuth 步骤）

```
┌─ 从飞书导入成员 ───────────────────────────── × ─┐
│ 状态条：企业应用 cli_a3f8…2c61 已连接 · 权限：读取通讯录       │
│ 成员多选列表（max-height 320 滚动，头部「飞书通讯录 · 共 12 人」+ 全选新人）：  │
│    [✓] 头像 张伟    产品部 · 产品经理                          │
│    [ ] 头像 李娜    研发部 · 前端工程师                        │
│    [—] 头像 wang   研发部 · 后端工程师      「已是成员」置灰不可选 │
│ 底部操作行：导入后权限 [成员 ▾/管理员 ▾] · 已选 n 人（已是成员不可选）      │
│    [取消] [导入所选（n 人）]（未选禁用）                        │
└──────────────────────────────────────────────┘
```

- 弹窗骨架复用 `modal-overlay/modal-box` + `fs-*` 样式（import `DocLibraryView.css`）；
- **打开门槛**：企业授权凭证已保存（未保存时入口按钮 disabled，弹窗不可达）；
- 顶部状态条（非步骤条）：绿已连接徽标 + App ID 脱敏 + 权限说明——替代原「步骤 1 授权卡」（企业授权已在面板完成）；
- 成员行 = `fs-check` checkbox + 头像（`memberColorOf`）+ 姓名（粗）+ 部门 · 职位（副文案）+ 右侧「已是成员」灰徽标（**已在 orgMembers 的置灰不可勾**）；
- 导入（1s Mock）→ 选中成员**顶插入** `orgMembers`：`permission` = 弹窗底部下拉所选（默认「成员」）、`online: false`、`lastActive: '活跃于 刚刚'`、`role` = 飞书职位；弹窗关闭、勾选清空；
- 导入即加入（Mock 立即生效，无飞书侧确认环节）。

### 3.4 数据层（settings.ts）

- `InviteData` → **`OrgMemberData`**（`{ orgMembers: OrgMember[] }`，`createDefaultOrgMemberData()` 初值不变：5 人、shilu 所有者）；
- 删除：`PendingInvite`、`InviteData`、`createDefaultInviteData`、`generateInviteLink`、`parseEmails`、`isValidEmail`、`nowStamp`（均无外部引用）、死代码 `feishuAuthorized`（无引用）；
- 新增飞书通讯录 Mock（约 12 人）：

```ts
export interface FeishuContact {
  id: string
  name: string
  /** 部门（导入后作为成员职位显示来源） */
  department: string
  /** 职位 */
  title: string
}
export const FEISHU_CONTACTS: FeishuContact[] = [
  // 与现有组织成员重叠 2 人（wang / chen）→ 弹窗内展示「已是成员」置灰
  // 新人 10 人：张伟(产品部·产品经理)、李娜(研发部·前端)、刘强(研发部·后端)、
  //            孙敏(测试部·测试)、周杰(设计部·UI)、吴霞(运营部·运营)、
  //            郑凯(研发部·算法)、冯雪(产品部·产品)、韩磊(研发部·架构)、唐悦(测试部·测试)
]
```

- `OrgMember.initial`：中文取首字、英文取首字母大写；
- **`FeishuSettings` 语义调整（字段不变，职责标注）**：appId/appSecret 归「企业授权」（tenant_access_token，成员导入门槛）；authorized/authorizedAccount/authorizedAt 归「个人授权」（user_access_token，文档导入门槛）；
- 企业授权状态 = **凭证已保存且非空**（`feishuCredReady` 派生，无独立连接状态字段；保存动作即连接验证，Mock 不失败）；
- **换企业凭证不再清空个人授权**（两者身份解耦，原「保存清授权态」语义删除）。

### 3.5 文档导入弹窗连带简化（DocLibraryView）

个人授权与凭证解耦后，文档导入只剩一个门槛（个人 OAuth）：

- 删「凭证未配置警示条」（`fs-cred-warn` + [去设置]）与 `credReady` 判定；
- 步骤条简化为单步语义：授权卡文案改「**个人授权 · 权限：读取云文档**」（不再显示 App ID 脱敏——个人授权与凭证无关）；
- 未授权 → [授权]（800ms OAuth Mock）→ 已授权徽标 + 账号 → 选目录导入（其余逻辑不变）；
- props 清理：删 `onGoToFeishuSettings`（KnowledgePanel / ProjectDetail / App 三层转发同步删除）。

## 4. 交互要点汇总

1. **企业授权（成员导入门槛）**：填 App ID/Secret → 保存 = 已连接（Mock 即成功）→ 导入按钮解锁；换凭证保存自动重连，**不影响个人授权**；
2. **个人授权（文档导入门槛）**：纯 OAuth（800ms Mock），无需任何凭证；取消授权后可重新授权；**个人授权 tab 下不展示导入成员/组织成员**；
3. 已是成员的飞书联系人置灰不可选；导入后组织成员计数 + 徽标即时更新；
4. 组织成员的移除/唯一所有者保护、权限说明**行为不变**；
5. 文档导入弹窗：未授权直接弹窗内 [授权]（无凭证警示、无跳设置）。
