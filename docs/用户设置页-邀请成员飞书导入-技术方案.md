# 用户设置页 · 邀请成员改为「从飞书导入成员」（与飞书授权合并）—— 技术方案

> 创建日期：2026-10-23
> 更新日期：2026-10-23（v1.0 初稿，待鹿鹿子大王确认后实施）

## 1. 需求（鹿鹿子大王）

设置页「邀请成员」：

1. 邀请方式**改为「从飞书导入成员」**（替代现有邀请链接 / 邮箱邀请）；
2. **与「飞书授权」分区合并到一起**（左导航不再单独保留「飞书授权」项）；
3. 流程：**先授权，再导入**。

## 2. 现状与差距

| 项 | 现状 | 差距 |
|---|---|---|
| 左导航 | 3 项：Agent 设置 / 邀请成员 / 飞书授权（`SettingsSection` 含 `'feishu'`） | 合并为 2 项：**Agent 设置 / 邀请成员**（飞书授权并入邀请成员面板） |
| InviteMembersPanel | 邀请链接（复制/有效期/权限/重置）+ 邮箱邀请（多邮箱+校验）+ 待接受邀请 + 组织成员 | 删链接/邮箱/待接受三块；新增**飞书授权区（组合 FeishuPanel）+ 从飞书导入成员**；组织成员保留 |
| FeishuPanel | 独立面板：应用凭证 + 个人授权（`UserSettings.feishu` 全局共享） | **组件保留**，作为 InviteMembersPanel 的首个区块直接渲染（组合复用，非迁移重写）；文案微调提及成员导入 |
| DocLibraryView 导入弹窗 | 步骤条（1 授权 → 2 选目录）+ 授权卡 + 多选树 + fs-* 样式 | 平移范式到成员导入弹窗（1 授权 → 2 选成员，多选列表）；「去设置」目标分区 `'feishu'` → `'invite'` |
| settings.ts | `InviteData`（link/linkExpireDays/linkPermission/pending/orgMembers）、`PendingInvite`、`generateInviteLink`/`parseEmails`/`isValidEmail`/`nowStamp` | 精简为 `OrgMemberData { orgMembers }`；删死代码；新增飞书通讯录 Mock `FEISHU_CONTACTS` |

## 3. 方案

### 3.1 设置页导航合并

```
设置页左导航（3 → 2）
  Agent 设置
  邀请成员   ← 飞书授权并入（凭证 + 授权状态成为面板第一个分组）
```

- `SettingsSection` 类型删 `'feishu'`，仅 `'agent' | 'invite'`；
- `SettingsPage` 删 feishu 分支与导航项（`FeishuIcon` import 移除）；
- `App.handleGoToFeishuSettings`：`setSettingsSection('invite')`（文档导入弹窗「去设置」直达邀请成员面板顶部的凭证区，链路 `DocLibraryView → KnowledgePanel → ProjectDetail → App` 签名零改动）。

### 3.2 邀请成员面板新结构（InviteMembersPanel 重构）

```
邀请成员面板
 ├─ Section「飞书授权」          ← 直接渲染 <FeishuPanel/>（组合复用）
 │    ├─ 应用凭证卡（App ID / Secret + 保存/清除，保存换凭证清授权态）
 │    └─ 个人授权行（未授权 [去授权] 800ms Mock / 已授权账号+时间+[取消授权]）
 ├─ Section「从飞书导入成员」（新）
 │    ├─ 状态引导行：未授权 = 灰提示「请先完成上方飞书授权」；已授权 = 绿点 + 授权账号可导入
 │    │    （不可导入时 [从飞书导入成员] btn disabled + title 提示）
 │    └─ [从飞书导入成员]（飞书蓝描边，同文档导入 fs-import-btn）→ 导入弹窗（见 3.3）
 └─ Section「组织成员（n）」（保留现状）
      头像 + 姓名 +「我」徽标 + 职位 · 权限 · 活跃 + 在线点 + 移除（唯一所有者保护）
      权限说明（所有者/管理员/成员三档）
```

- 面板 props 扩展：新增 `settings: UserSettings` / `onUpdateSettings`（SettingsPage 已有，直传）；`invite/onUpdateInvite` 更名 `org/onUpdateOrg`（语义化，见 3.4）。

### 3.3 导入弹窗：先授权，再选成员（范式对齐文档导入）

```
┌─ 从飞书导入成员 ──────────────────────────── × ─┐
│ ① 凭证未配置 → 黄色警示条「尚未配置飞书应用凭证」+ [去设置]  │
│ ② 步骤条：1 飞书授权（未授权 active / 已授权 ✓ done）→ 2 选择成员 │
│ ③ 未授权 → 授权卡（App ID 脱敏 + 权限：读取通讯录 + [授权] 800ms）│
│    已授权 → 已授权徽标 + 账号 · 时间                          │
│ ④ 成员多选列表（max-height 320 滚动）：                        │
│    [✓] 头像 张伟    产品部 · 产品经理                          │
│    [ ] 头像 李娜    研发部 · 前端工程师                        │
│    [—] 头像 wang   研发部 · 后端工程师      「已是成员」置灰不可选 │
│ ⑤ 底部操作行：导入后权限 [成员 ▾/管理员 ▾] · 已选 n 人          │
│    [取消] [导入所选（n 人）]（未授权/未选禁用）                │
└──────────────────────────────────────────────┘
```

- 弹窗骨架复用 `modal-overlay/modal-box` + `fs-*` 样式（import `DocLibraryView.css`，项目已有跨组件 import CSS 先例：DocLibraryView import KbIndexPanel.css）；
- 成员行 = `fs-check` checkbox + 头像（`memberColorOf`）+ 姓名（粗）+ 部门 · 职位（副文案）+ 右侧「已是成员」灰徽标（**已在 orgMembers 的置灰不可勾**）；
- 授权写回 `UserSettings.feishu`（与上方 FeishuPanel 授权区、文档导入弹窗三处天然同步）；
- 导入（1s Mock）→ 选中成员**顶插入** `orgMembers`：`permission` = 弹窗底部下拉所选（默认「成员」）、`online: false`、`lastActive: '活跃于 刚刚'`、`role` = 飞书职位 → 弹窗关闭、勾选清空；
- 导入即加入（Mock 立即生效，无飞书侧确认环节）。

### 3.4 数据层（settings.ts）

- `InviteData` → **`OrgMemberData`**（`{ orgMembers: OrgMember[] }`，`createDefaultOrgMemberData()` 初值不变：5 人、shilu 所有者）；
- 删除：`PendingInvite`、`InviteData`、`createDefaultInviteData`、`generateInviteLink`、`parseEmails`、`isValidEmail`、`nowStamp`（均无外部引用）、死代码 `feishuAuthorized`（无引用）；
- 新增飞书通讯录 Mock（约 12 人）：

export const FEISHU_CONTACTS: FeishuContact[] = [
  // 与现有组织成员重叠 2 人（wang / chen）→ 弹窗内展示「已是成员」置灰

- `OrgMember.initial`：中文取首字、英文取首字母大写。

### 3.5 FeishuPanel 文案微调（组合复用，不动结构）

- 「凭证用于「文档」导入的个人身份授权，仅本人可见」→「凭证用于飞书个人身份授权（文档 / 成员导入），仅本人可见」；
- 「授权后可在项目「文档」子 tab 从飞书目录导入文档」→「授权后可从飞书导入文档与组织成员」。

### 3.6 App / SettingsPage 接线

| 文件 | 改动 |
|---|---|
| `App.tsx` | `inviteData` state → `orgData: OrgMemberData`；`handleUpdateInvite` → `handleUpdateOrg`；`handleGoToFeishuSettings` 跳 `'invite'` |
| `SettingsPage.tsx` | 左导航删第三项；`SettingsSection` 删 `'feishu'`；props `invite/onUpdateInvite` → `org/onUpdateOrg`，并向 InviteMembersPanel 新传 `settings/onUpdateSettings` |
| `InviteMembersPanel.tsx` | 重构（删链接/邮箱/待接受 → 飞书授权组合 + 导入弹窗 + 组织成员） |
| `InviteMembersPanel.css`（新建） | 导入 Section 引导行 + 弹窗成员行/权限下拉补充样式（fs-* 公共类复用 DocLibraryView.css） |
| `FeishuPanel.tsx` | 仅文案微调 |
| `DocLibraryView.tsx` / `KnowledgePanel.tsx` / `ProjectDetail.tsx` | **零改动**（回调签名不变，目标分区在 App 层切换） |

## 4. 交互要点汇总

1. **先授权，再导入**：面板内两条路——① 先在顶部「飞书授权」分组完成授权，再点导入；② 直接点导入 → 弹窗内授权卡完成授权（800ms Mock）→ 列表解锁勾选；两路写同一 `feishu` state；
2. 凭证未配置：导入 btn disabled + title「请先配置飞书应用凭证」；弹窗若打开则顶部黄色警示条 + [去设置]（滚到面板顶部凭证区——同分区无需切页，仅聚焦滚动）；
3. 已是成员的飞书联系人置灰不可选；全选新成员导入后组织成员计数 + 徽标即时更新；
4. 组织成员的移除/唯一所有者保护、权限说明**行为不变**。
