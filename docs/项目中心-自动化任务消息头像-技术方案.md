# 「自动化任务」消息流说话人头像方案

> 创建日期：2026-08-28
> 更新日期：2026-08-28
> 前置文档：`项目中心-自动化任务实时交互升级方案.md`（v2.1，已实现任务运行弹窗 + 消息流 + 输入框）

## 1. 需求

任务运行弹窗（RunModal）的消息流中，**人插话的消息需要带发送者头像**。

原因：项目成员都可以向运行中的任务发消息，仅靠"右侧绿气泡"无法区分**是谁**在说话；同理 ADE 消息也应带身份标识，让整个消息流的说话人一目了然。

## 2. 现状与差距

| 角色 | 现状 | 差距 |
|---|---|---|
| 人 | 右侧绿气泡，无头像无名字 | 看不出是哪个成员发的 |
| ADE | 左侧灰气泡，无头像无名字 | 看不出是哪个 ADE 在执行 |
| 系统 | 居中灰小字 | 不变（事件性质，无说话人） |
| 输入框 | 纯输入框 + 发送按钮 | 不显示"我以什么身份在说话" |

## 3. 设计

### 3.1 数据模型（`data/projects.ts`）

```ts
/** 消息发送者（区分说话人） */
export interface MessageSender {
  /** 显示名 */
  name: string
  /** 头像字符 */
  initial: string
  /** 头像底色（缺省用默认灰蓝） */
  color?: string
}

/** 当前登录用户（Mock：与侧边栏底部一致） */
export const CURRENT_USER: MessageSender = { name: 'shilu', initial: 'S', color: '#5b7ba6' }

/** 任务执行方 ADE 的默认身份 */
export const ADE_SENDER: MessageSender = { name: '研发工程师ADE', initial: 'A', color: '#7c66d8' }

export interface RunMessage {
  // …现有字段不变…
  /** 说话人（人 = 发消息的成员；ADE = 执行方）；缺省时渲染按 role 兜底 */
  sender?: MessageSender
}
```

- `sender` 为**可选**字段：旧 Mock 数据不用逐条补，渲染时按 role 兜底（人 → CURRENT_USER，ADE → ADE_SENDER）；
- 头像底色进数据（`color`），不同成员天然不同色，无需 hash。

### 3.2 消息渲染（`RunModal.tsx` MessageItem）

```
研发工程师ADE                                    ← 名字（11px 灰，仅连续首条显示）
[A] ┌────────────────────────┐                  ← ADE：头像在左 + 灰气泡
    │ 拉取 origin/dev 完成…   │
    └────────────────────────┘
                    ┌────────────────────────┐ [W]
                    │ 顺便把 login 分支的用例… │     ← 人：绿气泡 + 头像在右
                    └────────────────────────┘
                                             wang ← 名字右对齐
```

- **头像**：26px 圆形（与成员面板 `member-avatar` 同规格），白字 + sender 底色；
- **名字**：气泡上方 11px 灰字；**连续同一说话人只显示第一条的名字**（系统消息天然打断连续性）；
- **对齐**：人消息整行右对齐（头像贴气泡右侧），ADE 消息头像贴气泡左侧，头像与气泡顶部对齐；
- Gate 问题消息（带按钮/表单）同样带头像，样式不变。

### 3.3 输入框（RunModal 底部）

输入框左侧常驻**当前用户头像**，title 提示「以 shilu 身份发送」——发消息前即可确认自己的身份：

```
[S] [ 给运行中的任务发消息…              ] [发送]
```

### 3.4 引擎（`useAutomationEngine.ts`）

`msg` 工厂函数自动附带 sender：

```ts
const msg = (role: RunMessage['role'], text: string): RunMessage => ({
  id: msgId(), role, text, time: nowTime(),
  sender: role === 'ADE' ? ADE_SENDER : role === '人' ? CURRENT_USER : undefined,
})
```

`sendMessage`（人插话）产出的消息自动带 `CURRENT_USER`，无需单独处理。

### 3.5 Mock 数据（演示多人说话）

「每日构建」当前运行的消息流中预置一条**其他成员（wang）**的插话 + ADE 回应，打开弹窗即可看到不同成员头像/名字的区分效果：

```
[A] 依赖安装完成，共 312 个包。
[W] 顺便把 login 分支的用例也跑一下        ← wang（橙色头像）
[A] 收到，已将 login 分支用例加入本次测试范围。
[A] 单元测试进行中… 42/58 通过
```

自己发消息则显示 shilu（灰蓝头像），与 wang 区分开。

## 4. 改动清单

| 文件 | 改动 |
|---|---|
| `data/projects.ts` | 新增 `MessageSender` 接口 + `CURRENT_USER` / `ADE_SENDER` 常量；`RunMessage` 增加可选 `sender`；每日构建 Mock 预置 wang 插话 |
| `hooks/useAutomationEngine.ts` | `msg` 工厂自动附带 sender |
| `components/project-detail/RunModal.tsx` | MessageItem 渲染头像 + 名字（连续同一说话人去重，按 role 兜底 sender）；输入框左侧当前用户头像 |
| `components/project-detail/RunModal.css` | 头像 / 名字 / 内容行（头像+气泡）样式 |
| `README.md` | 自动化任务说明补充"消息流区分说话人" |

## 5. 验收标准

1. 弹窗消息流：人消息右侧带头像 + 名字，ADE 消息左侧带头像 + 名字，系统消息样式不变；
2. 输入框发消息：绿气泡 + 当前用户（shilu）头像立即上屏，约 1.5s 后 ADE 回应（带头像）；
3. 不同成员的消息头像底色与名字不同（Mock 预置 wang 插话可见区分效果）；
4. 连续同一说话人的消息只在首条显示名字；
5. 输入框左侧显示当前用户头像；
6. v2.1 已有能力（消息流推进 / Gate / 编辑模式等）不回退；
7. 构建通过，提交 commit（按用户要求不做 Playwright 验证）。

## 6. 风险与说明

- 纯 Mock：真实系统中 sender 应来自登录态/会话接口，此处用 `CURRENT_USER` 常量模拟；
- ADE 身份暂用全局默认（研发工程师ADE）；若后续任务需关联具体 ADE（多 ADE 协作），在 `AutoJob` 上加执行方字段即可，渲染层已按 `sender` 驱动。
